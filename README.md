# ShitPM

> 一套跑在 AI 编程助手里的硬核产品设计工作台。
> 它不搞虚头巴脑的「一键生成流水账」，而是用唯一事实体系，帮你把零散业务需求，推演成研发挑不出刺的严密 PRD，以及现场就能直接操作的真实前端工程原型。

做产品和写代码的朋友，其实都清楚日常协作里最折磨人的几个死结，

一是文档与原型脱节。改了需求，改了 PRD 往往漏了原型，或者改了原型忘了同步文档。几份交付物口径不一，各执一词。
二是通用 AI 生成的 PRD 假大空。直接让大模型写需求，吐出来的全是套话废话。遇到边界异常、逆向流程、权限状态机这些脏逻辑，AI 经常回避，甚至在核心未决问题上不声不响替你瞎拍板。
三是所谓原型全是纸片。要么是几张无法交互的静态图，要么是几行简单 HTML 拼出的半成品，根本无法在正式评审里验证真实组件行为与多角色权限。

ShitPM 就是为了解决这些工程与协作断层做出来的。

它不做独立封闭的付费 SaaS，而是做成了一套紧凑锋利的 Skill 工具集，直接运行在你每天都在用的 AI 编程助手里，比如 Codex、Trae、Claude Code 还有 WorkBuddy。

它的核心理念极其明确，

**Design 是唯一产品事实体系。**

在 ShitPM 里，文档、原型不再各自为政，规矩非常清晰，

一个设计地图，理清系统边界与主业务链。
一个设计集清单，用机器可读的 SHA-256 文件指纹锁死依赖与事实归属。
系统级基线与跨模块契约，承载全局角色、数据范围、状态衔接与失败补偿。
模块详细设计，管好各自的页面、字段、操作、规则与异常分支。

每一个产品事实，有且仅有一个归属地。

基于这套坚实的事实底座，PRD 和原型根本不需要互相抄，它们是 Design 派生出来的两个并列下游。

先看 PRD 这块，

彻底摒弃「点击按钮、打开弹窗、提交保存」这类无意义的流水账。
PRD 按业务闭环组织并分段完成，核心是 4.x.6 功能详细说明。这一节要求做到自包含，前端能看清页面形态与交互边界，后端能看懂数据流向与状态机变化。研发和测试只看这一节就能独立开发和写用例，不用反复回问产品。涉及复杂流转时，系统还会自动生成 draw.io 流程图并导出高清图直接嵌入正文。

再看原型这块，

ShitPM 产出的不是静态纸片，而是一套标准的 Vite + React 18 + Ant Design 6 源码工程。
表格遵从 Ant Design 官方规范，支持真实钉列、横向滚动与折叠筛选。弹窗、抽屉、分步表单与状态机禁用全是真实可跑的代码。原型内置了角色切换器，切换管理员或经办人，能立刻看到对应的真实界面与操作权限。
工程根目录下提供了「原型工具.bat」，双击即可完成本地开发预览、打包构建，甚至通过 Wrangler 一键部署到 Cloudflare Pages 进行在线演示。

还有改动时的杀手锏，同步修复，

需求变更从来无法避免。在 ShitPM 里，底层维护着严格的文件级指纹溯源。
当你需要修改业务规则时，只需对 AI 说一句，
「同步修复，把商户名称长度限制改成 100 字，增加待复核状态。」
它会自动定位到 Design 里的唯一事实归属，修改定义，接着顺着依赖链，把所有实际受影响的 PRD 章节与前端代码一次性联动更新，并自动运行一致性检查，绝不让两端出现口径冲突。

诚实与防幻觉机制，

对于核心流程、权限边界或状态流转中的含糊未知，ShitPM 严禁 AI 静默拍板。
遇到无法确定的业务规则，AI 会在对应文件中打上未决标记并局部阻断，直接抛出具体的业务问题等待你决策，绝不擅自脑补。

两种工作模式，

开始设计时，AI 会根据业务复杂度向你确认，
简单模式，面向单一主流程、小范围业务闭环，快速产出结构化设计。
完整模式，面向多角色、多阶段流转的复杂系统，完整承担 A 需求理解、B 业务建模、C 产品承接的三层责任，把深水区的规则与边界理清。

安装与配置，

环境只需 Python 3.10 以上版本。克隆本仓库后，在终端运行一行命令，通过 Windows junction 软链技术直接挂载到你的 AI 客户端，

安装到 Codex，

```powershell
python scripts/python/shitpm-host.py install --host codex
```

安装到 Trae，

```powershell
python scripts/python/shitpm-host.py install --host trae-cn
```

安装到 Claude Code 或 WorkBuddy，

```powershell
python scripts/python/shitpm-host.py install --host claude-code
python scripts/python/shitpm-host.py install --host workbuddy
```

多个工具共享，可直接装入全局目录，

```powershell
python scripts/python/shitpm-host.py install --host agents
```

通过软链挂载后，后续更新仓库只需 git pull，所有技能、规则和模板自动同步生效，无需重复安装。

常用自然语言交互，

1. 「启动辅助器」，扫描当前项目进度、产物状态与所有可用动作。
2. 「开始设计」，输入原始业务需求，确认使用简单模式或完整模式，生成多文件设计集。
3. 「开始写 PRD」，基于设计基线直接生成严密的需求规格文档。
4. 「开始原型」，基于设计基线生成可交互的 React 前端工程。
5. 「同步修复，...」，指定修改内容，自动联动更新受影响的设计、文档与原型。
6. 「设计 Review」/「PRD Review」/「原型 Review」，对指定产物进行独立审查，获取修改建议。

10 个内置 Skill 分工说明，

| 技能名称 | 核心职责 |
| --- | --- |
| spm-start | 项目启动与导航，只读盘点项目进度、产物状态与可用动作 |
| spm-align | 需求对齐，将零散材料沉淀为事实基线，识别高影响未知 |
| spm-design | 产品设计建模，生成多文件唯一事实体系（支持简单模式与完整模式） |
| spm-prd | PRD 生成，基于设计事实闭包直接产出研发可评审的规格文档 |
| spm-prototype | 原型生成，构建 Vite + React 18 + Ant Design 6 标准前端工程 |
| spm-fix | 同步修复，将变更沿事实链精准传播，联动更新 PRD 与原型 |
| spm-design-review | 设计独立审查，提供第二意见挑出逻辑盲区 |
| spm-prd-review | PRD 独立审查，检查场景覆盖、业务闭环与规则落地 |
| spm-prototype-review | 原型独立审查，检查工程规范、路由与设计一致性 |
| spm-prototype-mark | 原型标注，为原型副本叠加可交互的审阅说明弹窗 |

软件工程的本质是严密与自洽。ShitPM 不做虚无飘渺的魔法承诺，而是把事实源、状态机和工程闭环扎扎实实落地，把机械繁琐的对账与格式劳动交给工具，把真正的业务思考与方案决断留给产品经理。
