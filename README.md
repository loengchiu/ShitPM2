# ShitPM

ShitPM 是一个运行在 AI 编程助手中的产品设计工作台。它能够帮助产品经理将零散的业务需求，转化为标准化、高质量的产品设计方案、PRD 文档和可点击交互原型，并保证三者之间内容完全一致。

---

## 核心价值

在传统的产品设计流程中，产品经理常面临以下痛点：

- **文档与原型脱节**：设计改动后，PRD 或原型未能同步修改，导致评审会上多方内容对不上。
- **AI 生成内容假大空**：直接让通用 AI 写 PRD，容易得到缺乏细节逻辑和规则的流水账，修改成本高。
- **重复劳动耗时**：整理需求、撰写文档、绘制原型分散在不同工具中，繁琐且效率低下。

**ShitPM 的解决方案**：

ShitPM 以**产品设计基线**为唯一事实源。你只需要用自然语言表达业务需求，ShitPM 就会引导 AI 自动完成需求梳理、结构化设计，并在此基础上同步生成 PRD 文档与可交互原型。只要设计基线发生变更，下游的文档和原型都能联动更新，彻底消除内容不一致的问题。

## 交付产物

运行工作流后，你的项目中将自动生成以下标准交付材料：

| 产物名称 | 说明 | 适用场景 |
| --- | --- | --- |
| **设计基线文件** | 定义系统结构、页面路由、区块划分、字段表、操作规则及角色权限 | 产品经理内部归档、架构参考 |
| **PRD 文档** | 按照业务闭环组织的标准需求文档，规则严密、逻辑完整 | 研发评审、测试用例编写 |
| **可点击交互原型** | 基于 Web 的标准原型页面，支持主流程操作、状态切换与交互体验 | 需求评审、产品演示、UI 设计参考 |
| **原型标注版** | 在原型页面上叠加标记与规则弹窗（可选） | 研发快速对照实现细节 |
| **评审报告** | 对设计、PRD 或原型进行独立质量检查后给出的建议清单（可选） | 质量自查与优化 |

## 两种设计模式

根据需求复杂程度，ShitPM 提供了两种设计模式：

- **简单模式**：适用于单一功能点、小需求或快速迭代。AI 专注分析目标的最小业务闭环，快速产出结构化设计。
- **完整模式**：适用于多角色、多状态、多模块联动的大型系统。AI 会进行深度的需求理解与业务建模，确保复杂的权限与状态流转无死角。

你无需手动配置模式，在开始设计时，AI 会根据需求情况向你询问确认。

## 核心优势：三维深度产品分析

传统的 AI 产品工具往往直接将用户的模糊描述填充进模板，容易产生逻辑死角、状态遗漏和权限混乱。ShitPM 的核心优势在于内置了**三维深度产品分析机制**，在生成文档和原型前，先完成严密的业务建模与产品推演：

1. **需求解构（理清本质与边界）**
   - **分析内容**：深入剖析需求背后的本质目标与真实痛点，厘清参与的角色与干系人诉求，明确系统边界，并主动识别歧义与潜在风险。
   - **核心作用**：避免“提什么做什么”导致的业务偏离，把模糊的需求转化为清晰无歧义的事实基线。

2. **业务建模（构建逻辑与状态闭环）**
   - **分析内容**：构建核心业务实体关系、主干与分支异常流程、状态机模型（如“待派单 → 处理中 → 已完成”）及角色权限矩阵。
   - **核心作用**：堵住传统 AI 容易遗漏的异常分支、状态卡死和权限越权问题，确保业务逻辑严密闭环。

3. **产品落地（定义界面与交互规格）**
   - **分析内容**：将业务模型转化为可落地的产品界面与交互规格，包括模块划分、页面结构、区块布局、字段规则（展示条件、输入校验）及操作响应。
   - **核心作用**：建立 100% 确定性的设计事实源，为同步一键生成 PRD 和原型提供无遗漏的依据。

通过“需求解构 → 业务建模 → 产品落地”层层推演，ShitPM 能在正式写文档前就把复杂逻辑理清，这是生成高质量、无死角产物的关键所在。

## 快速开始

无需编写代码或安装复杂的开发环境，只需完成以下准备即可使用。

### 1. 环境准备

- 安装 Python（3.10 或更高版本）。
- 使用支持的 AI 编程助手客户端，目前支持：**Trae**、**Codex**、**Claude Code**、**WorkBuddy**；也支持将完整资源安装到共享的 `C:\Users\<用户名>\.agents`。

### 2. 安装 ShitPM

下载或克隆本仓库到本地，打开终端（Terminal）并进入仓库根目录，根据你使用的 AI 客户端运行对应的安装命令。若多个工具共享 `C:\Users\<用户名>\.agents`，先执行：

```powershell
# 安装共享 bundle、Skill、契约、参考文档、Schema、脚本和模板
python scripts/python/shitpm-host.py install --host agents
```

然后按需安装具体客户端：

```powershell
# 如果你使用的是 Trae
python scripts/python/shitpm-host.py install --host trae-cn

# 如果你使用的是 Codex
python scripts/python/shitpm-host.py install --host codex

# 如果你使用的是 Claude Code
python scripts/python/shitpm-host.py install --host claude-code

# 如果你使用的是 WorkBuddy
python scripts/python/shitpm-host.py install --host workbuddy
```

> **说明**：安装后，ShitPM 会自动与你的 AI 助手关联。后续通过 `git pull` 更新仓库代码时无需重新安装，变更会自动生效。

## 使用指南

安装完成后，在你的项目目录中启动 AI 助手对话框，使用自然语言即可驱动整个产品设计流程。

### 基本流程

1. **查看项目状态**
   在对话框中发送：**“启动辅助器”**
   AI 会自动扫描当前项目进度，列出当前可执行的动作和下一步建议。

2. **开始产品设计**
   在对话框中发送：**“开始设计”**
   将你的业务需求描述发给 AI（支持文字输入或直接粘贴原始需求材料）。AI 会引导你对齐需求细节，并生成结构化的产品设计基线文件。

3. **生成 PRD 文档或原型**
   设计完成后，你可以按需选择生成 PRD 或原型（两者相互独立，先后顺序不限）：
   - 发送 **“开始写 PRD”**：AI 会严格基于设计基线生成标准的 PRD 文档。
   - 发送 **“开始原型”**：AI 会生成可在浏览器中直接打开体验的可点击原型。

4. **同步需求变更**
   当评审提出修改意见或需求发生变更时：
   - 在对话框中发送：**“同步修复”** 并说明修改内容（例如：“资产名称长度改为 100 字”）。
   - AI 会自动更新设计基线中的字段规则，并联动修复所有受影响的 PRD 章节和原型页面。

## 常见问题

**Q: 使用 ShitPM 需要懂前端或 Python 代码吗？**
A: 不需要。所有的文档撰写和原型生成均由 AI 自动完成，你只需要使用自然语言与 AI 助手对话即可。

**Q: 如果我只需要 PRD，不需要原型，可以吗？**
A: 可以。设计完成之后，你可以只执行“开始写 PRD”，无需生成原型；反之亦然。

**Q: AI 写的 PRD 会不会出现字段对不上或流水账的情况？**
A: 不会。ShitPM 在生成 PRD 前内置了严格的格式和规则校验机制，确保 PRD 中的所有字段、权限、状态与设计基线完全一致，同时过滤掉无意义的重复描述。

**Q: 想要获取更详细的技术配置或操作细节？**
A: 请参阅 [USAGE.md](USAGE.md)。
