# ShitPM

**一句话需求进去，完整 PRD + 设计文档 + 可交互原型出来。**

你只负责讲清楚业务，AI 帮你把想法变成可以直接拿去评审的全套文档。

---

## 你是不是也遇到过这些问题？

| 痛点 | 后果 |
|------|------|
| 业务方给了一句话需求，不知道从哪开始写 PRD | 拖了三天还在"理解需求" |
| 好不容易写完 PRD，研发说"没写清楚" | 来回返工，评审变辩论 |
| 改了设计文档，忘了同步更新 PRD | 文档之间互相矛盾 |
| 想用 AI 帮忙写，但输出总是"模板腔"、流水账 | 花更多时间改 AI 的稿子 |
| 原型要另外找人画，跟 PRD 对不上 | 评审会上才发现页面少了一半 |

**ShitPM 就是为了解决这些问题而生的。**

它不是又一个文档模板，而是一套**让 AI 按正确顺序帮你写文档的工作流**。你跟 AI 聊需求，它帮你一步步产出对齐稿、设计文档、PRD、HTML 原型——每一步之间自动保持一致。

---

## 你能得到什么

完成一轮流程后，你的项目文件夹里会多出这些东西：

| 产物 | 是什么 | 给谁看 |
|------|--------|--------|
| 对齐稿 | 确认目标、范围、角色、边界的对话记录 | 你自己、业务方 |
| 设计基线 | 模块、页面、字段、规则、权限的完整定义 | 你自己、UI 设计师 |
| PRD 文档 | 研发可直接评审的详细需求说明 | 研发、测试 |
| HTML 原型 | 可点击的页面原型，展示主流程和状态变化 | 评审会上所有人 |
| 标注原型 | 带关键点标记和备注弹窗的原型，展示规则和交互逻辑 | 研发、测试 |
| 审查报告 | 每一步的自动检查结果，告诉你哪里有问题 | 你自己 |

**最关键是：** 这些文档之间是一致的。改了设计里的字段，PRD 会跟着变，原型也会跟着变。不会出现"设计里有 8 个字段，PRD 里写了 6 个"这种事。

---

## 完整流程长什么样

整个流程分 8 步，每步都有明确的输入和输出。你不需要记住顺序，AI 会告诉你"下一步该做什么"。

```
第 0 步  启动检查        →  状态报告
第 1 步  需求对齐        →  对齐稿
第 2 步  详细设计        →  设计基线
第 3 步  设计审查        →  审查报告（不通过就改，通过继续）
第 4 步  生成 PRD        →  PRD 文档
第 5 步  PRD 审查        →  审查报告（不通过就改，通过继续）
第 6 步  生成原型        →  HTML 原型
第 7 步  原型审查        →  审查报告（全通过，大功告成）
（可选）原型标注        →  带标注的原型（给研发看交互规则和备注）
```

每一步做完，AI 会自动帮你检查质量。发现问题会告诉你哪里需要改，不会让你带着错误往下走。

## 实际使用示例

### 示例 1：从零开始做一个新功能

> 老板说："我们小区要做一个报修系统，业主能在小程序上报修，物业能派单给维修工。"

你的操作：

1. **启动：** 对 AI 说"启动辅助器"，它会帮你初始化项目
2. **对齐：** 对 AI 说"开始对齐"，然后跟它聊业务目标、用户角色、功能范围。它会一个一个问你关键问题，你回答就行
3. **设计：** 对齐完成后，对 AI 说"开始设计"。它会基于你的回答，生成一份完整的设计文档——有哪些页面、每个页面有哪些字段、按钮、状态变化，全都列清楚
4. **审设计：** 说"设计 review"，AI 自动检查设计文档是否完整、有没有遗漏。有问题告诉你改，没问题继续
5. **写 PRD：** 说"开始写 PRD"。AI 把设计文档展开成研发能直接看的需求文档——每个页面、每个按钮、每种状态都写清楚
6. **审 PRD：** 说"PRD review"。AI 检查 PRD 是不是写成了流水账、有没有漏字段漏权限
7. **出原型：** 说"开始原型"。AI 生成一个可以在浏览器打开的 HTML 原型，点来点去看效果
8. **审原型：** 说"原型 review"。全部通过就大功告成

整个过程大概 30-60 分钟，你就能拿到一份**可以直接拿去评审会的全套文档**。

### 示例 2：改了一个字段，全链路同步

> 评审会上研发说："资产名称这个字段，长度限制是 50 还是 100？"

你发现设计文档里写的是 50，但业务方说需要 100。改完设计文档后：

1. 对 AI 说"同步修复"，告诉它"资产名称字段长度改为 100"
2. AI 自动帮你更新 PRD 里的字段定义表、原型里的输入框限制
3. 不用你一个一个文件去找、去改，AI 沿着文档之间的依赖关系帮你全改完

### 示例 3：AI 写的 PRD 不像流水账？

AI 生成 PRD 之后，会自动用风格检查工具扫一遍。如果它把"点击按钮→填写表单→提交"这种流水账写法检测出来，会提示 AI 补充展示规则、状态变化、异常处理。**你不需要手动去改 AI 的稿子**，它会自己改好再给你看。

## 怎么开始用

### 第一步：准备环境

你需要两样东西：

1. **Codex / Trae-CN / Claude Code / WorkBuddy 桌面应用**（你的 AI 助手运行环境，四选一即可）
2. **你的项目文件夹**（用来存放所有文档的地方）

不需要装任何开发工具，不需要写任何代码。

### 第二步：启动

打开你的 AI 助手（Codex / Trae-CN / Claude Code / WorkBuddy），对 AI 说：

> "启动辅助器"

AI 会帮你初始化项目，然后告诉你当前该从哪一步开始。

### 第三步：跟着 AI 走

每完成一步，AI 会告诉你下一步做什么。你只需要：

- **跟 AI 聊你的需求**（对齐阶段）
- **看 AI 生成的文档，确认没问题**（设计、PRD 阶段）
- **让 AI 帮你检查质量**（审查阶段）
- **有问题就让 AI 改，没问题就继续下一步**

不需要记住任何命令。AI 会全程引导你。

## 这套东西适合谁

**非常适合：**
- 手上有一堆零散需求，需要快速整理成可评审文档的产品经理
- 想用 AI 帮忙写 PRD，但试过几次发现 AI 写的东西"看着像那么回事，实际没法用"的团队
- 一份需求要出设计文档 + PRD + 原型，希望这三样东西保持一致的项目组

**不太适合：**
- 需求已经非常清晰、只需要做微调的项目（直接改文档可能更快）
- 不使用 Codex / Trae-CN / Claude Code / WorkBuddy 作为 AI 协作工具的场景

## 背后原理（可选阅读）

> 以下是给想了解技术细节的人准备的，不影响使用。

ShitPM 的核心思路是**让设计文档成为"唯一事实源"**。所有字段、权限、状态的定义都以设计文档为准，PRD 负责展开细节，原型负责可视化表达。当上游事实发生变化时，AI 会沿着文档间的依赖关系自动同步，不会遗漏。

每一步完成后，除了生成人读的文档，还会生成一份机器可读的校验数据。审查阶段会用这些数据自动检查：章节是否完整、文档之间是否一致、PRD 有没有写成流水账等。
