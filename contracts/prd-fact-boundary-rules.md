# PRD 事实边界规则

> 本文件定义 `design` 与 `PRD` 在字段、权限、状态三类事实上的边界。
> `prd` writer、reviewer 以及相关校验脚本都应遵循本文件。

## 一、唯一事实源

`design` 是以下三类内容的唯一事实源：

1. 字段完整定义
2. 权限完整定义
3. 状态完整定义

## 二、PRD 的职责

`PRD` 的职责是把 `design` 中已确认的事实展开成研发可评审的人读规格说明。

1. `PRD` 可以为交付目的完整镜像字段、权限、状态
2. `PRD` 可以补足研发理解所需的页面动作、展示规则、异常边界
3. `PRD` 不得独立改写 `design` 已确认事实的语义

## 三、禁止行为

1. 不得独立新增 `design` 中不存在的字段定义
2. 不得独立新增 `design` 中不存在的权限定义
3. 不得独立新增 `design` 中不存在的状态定义
4. 不得把 `PRD` 变成字段、权限、状态的第二事实源

## 四、PRD 中三类章节的边界

### 数据字典

1. 数据字典是字段主定义的交付镜像区，不是新的字段事实源
2. 数据字典只保留交付所需字段，不带内部稳定 ID、relations、anchors、source refs
3. 业务来源只写：`用户填写 / 系统生成 / 外部同步 / 关联带出`

### 权限汇总

1. 权限汇总是研发评审所需权限口径的集中展示区
2. 只保留页面级、按钮级、字段级权限口径
3. 不带机读映射字段

### 状态机

1. 状态机按核心业务对象组织
2. 只保留研发评审所需的状态集合、迁移、触发动作和限制条件
3. 不带机读映射字段
