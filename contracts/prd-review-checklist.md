# PRD Review 检查项

> 本文件只保存 PRD 专项审查口径。通用审查结论、预检查、输出、独立性和停止规则见 [Review 公共执行契约](review-checklist.md)。Review 只审查、不修改、不自动推进；不把旧模板结构当作正确性标准。Review 按模块检查，不只检查模块标题是否存在。
>
> 审查顺序：先审最后一个业务模块，再向前审查，避免审查疲劳导致后半段被宽松放行；对统计页和复杂动作按“统计页与复杂动作逐页验收专项检查”逐页、逐动作回答。

## 结构与业务闭环

| 检查项 | 触发证据 | 默认严重度 | 输出位置 |
|---|---|---:|---|
| 1.  顶层结构可定位 | 缺少文档信息、范围、总体说明、功能模块或待确认事项中的必要部分 | P1 | `structure` |
| 2.  按业务闭环组织 | 直接按菜单、页面目录、管理端/移动端或 Design 章节拆分，导致同一闭环被拆散 | P1 | `structure` |
| 3.  模块边界清楚 | 模块目标、起点、结果、终点或范围外内容无法理解 | P1 | `content` |
| 4.  模块可独立阅读 | 关键事实依赖“同上”“见前文”或模糊跨节引用 | P1 | `content` |
| 5.  页面落点准确 | 页面只在映射表出现，没有放入所属模块 `4.x.6` 的真实业务阶段，或一个页面被重复定义且口径不一 | P1 | `structure` / `consistency` |
| 6.  管理端和移动端共同闭环 | 移动端被单独堆成统一模块，或与所属业务阶段脱节 | P1 | `structure` |
| 7.  共用事实单一定义 | 共用页面、字段、状态或“我的处理记录”等事实存在多个权威版本 | P1 | `consistency` |
| 8.  全局与模块边界合理 | 模块专属规则被放在全局，或跨模块规则被重复定义并冲突 | P1 | `content` |
| 9.  Design 全读痕迹（上下文爆栈症状） | 字段定义章节整体缺失；页面以“页面职责/使用对象/入口与返回/区块清单”元数据块开头且无业务判断和动作展开；大面积机械重复文案（同一失败/恢复话术重复 N 次）；待确认事项异常稀少（高影响未知被静默拍板）。命中多项时提示：疑似生成时一次性全读 design.md 导致上下文爆栈，应按分片流程重新生成受影响模块 | P1 | `content` / `consistency` |

## 动作、字段与状态

| 检查项 | 触发证据 | 默认严重度 | 输出位置 |
|---|---|---:|---|
| 10.  核心动作形成因果链 | 缺执行角色、前置条件、输入、处理规则、结果、状态副作用或失败边界 | P1 | `content` |
| 11.  动作交互可操作性 | 动作正文违反 `prd-writing-rules.md` 详细需求说明写作规范的复杂度分级：简单动作虚构不存在的表单、确认或异常分支；高复杂动作缺角色/状态/入口、字段和确认、分支结果、状态变化、失败恢复或后续去向；或高影响交互未定义时自行拍板、低影响交互措辞未承接 Design 推断值而自行补造按钮/表单/反馈 | P1 | `content` |
| 11a.  资深规格回读 | 主链路没有按操作顺序写、关键分支没有单列、状态变化没有落到结果、下一步衔接角色没有写在结果处；已确认文案没有用双引号嵌入正文、动态内容没有说明来源、超长文本没有写清处理方式；默认角色反复出现或特殊角色限制没有就近写；存在原因腔、重复话术、标签式小节、流水账或模板填空腔（对照 `prd-writing-rules.md` 详细需求说明写作规范的信息密度与自然语言要求） | P2 | `content` |
| 12.  动作不是流水账 | 只描述点击顺序，没有业务判断和结果 | P1 | `content` |
| 13.  强动作条件明确 | 新建、删除、提交、确认、停用等动作未写角色、允许状态或权限 | P1 | `content` / `consistency` |
| 14.  字段有准确落点 | Design 字段未在对象、业务阶段、页面使用或系统内部用途处出现 | P1 | `consistency` |
| 15.  字段属性不被猜测 | 类型、枚举、格式、默认值、范围、来源或权限与 Design 冲突，或凭经验补造 | P1 | `consistency` |
| 16.  局部字段表达合理 | 把局部表格误当总字典，或用固定七列要求替代业务判断 | P2 | `content` |
| 17.  业务状态清楚 | 业务状态、页面展示状态和操作过程状态混淆，或状态迁移缺条件和结果 | P1 | `content` / `consistency` |
| 18.  页面表达与状态一致 | 页面筛选、按钮、展示或动作条件与业务状态冲突 | P1 | `consistency` |
| 19.  生命周期完整（按需） | 删除、作废、归档、恢复、撤回等场景存在但未说明可见性、可编辑性或关联结果 | P1 | `content` |
| 20.  查询统计口径完整（按需） | 筛选范围、统计口径、下钻关系或无数据结果不清楚；无依据补排序/分页/上限 | P1 | `content` |
| 21.  页面展示行为完整（按需） | 无权限、加载中/骨架屏、空态、异常态、超长文本、默认值、标签颜色、分页/排序或筛选保留规则缺失 | P1 | `content` |
| 22.  状态驱动展示完整（按需） | 状态页面缺可见/置灰/隐藏操作、字段显隐、点击跳转、标签颜色或刷新时机 | P1 | `content` / `consistency` |

## 权限、异常与验收

| 检查项 | 触发证据 | 默认严重度 | 输出位置 |
|---|---|---:|---|
| 23.  角色与数据范围一致 | 角色、组织范围、可见数据或职责分离与 Design 不一致 | P1 | `consistency` |
| 24.  权限与按钮一致 | 权限规则和按钮可见/可点/置灰条件不匹配 | P1 | `consistency` |
| 25.  外部责任边界清楚 | 未说明事实源、同步方向、责任人或失败后的业务归属 | P1 | `content` |
| 26.  异常与恢复可理解 | 失败、无数据、状态过期、外部不可用或部分成功缺少产品结果；擅自补造重试/补偿 | P1 | `content` |
| 27.  表单与配置边界清楚 | 保存/提交、空值/零值、生效范围/时点/历史影响或失败结果混淆 | P1 | `content` |
| 28.  模块验收就近 | 验收只在文末堆放，或未覆盖模块业务结果、状态、权限和异常 | P1 | `content` |
| 29.  待确认事项真实 | 高影响未知被静默拍板，或低影响表达被伪装成结论 | P1 | `consistency` |
| 30.  自动动作失败闭环 | 自动生成/挂号/归档/迁移只有成功路径，缺失败状态、反馈、重试/补偿/人工处理或待确认 | P1 | `content` |
| 31.  删除传播完整（按需） | 删除、软删除、停用、撤回、作废或归档未说明子对象、关联、审批、日志、附件、历史、引用和恢复/审计 | P1 | `content` |
| 32.  枚举和独立上限有来源（按需） | 枚举只有“字典/枚举”占位，或分页、导出、批量、首页和文件限制没有分别表达 | P1 | `content` |
| 33.  不以建议代替结论 | Review 只给泛化建议，没有具体问题、严重度和位置 | P2 | `structure` |

## Design 一致性与高影响事实

| 检查项 | 触发证据 | 默认严重度 | 输出位置 |
|---|---|---:|---|
| 34.  目标与范围一致 | PRD 改变 Design 的目标、范围、系统边界或排除项 | P1 | `consistency` / `affected_objects` |
| 35.  无未授权页面和模块事实 | 出现 Design 未定义的新页面、页面行为或高影响模块边界 | P1 | `consistency` / `affected_objects` |
| 36.  无未授权字段、状态和权限 | 出现 Design 未定义或与其冲突的字段、状态、权限、枚举或流程 | P1 | `consistency` / `affected_objects` |
| 37.  待确认项未被结论化 | PRD 把 Design 待确认事项写成确定事实 | P1 | `consistency` / `affected_objects` |
| 38.  变更传播完整 | 同一事实在对象、动作、状态、权限、验收或待确认位置发生不一致 | P1 | `consistency` / `affected_objects` |
| 39.  内部字段可交付 | 非页面字段缺失，或未说明系统内部用途 | P1 | `consistency` |
| 40.  语义问题不伪装成脚本通过 | 仅凭脚本退出码宣布完整，未人工回读业务闭环 | P2 | `content` |
| 41.  上游问题正确回退 | Design 缺失或错误时 PRD 自行补事实，而不是提出上游同步 | P1 | `consistency` / `needs_upstream_sync` |

## 文风与交付文件

| 检查项 | 触发证据 | 默认严重度 | 输出位置 |
|---|---|---:|---|
| 42.  不使用标签式正文 | 出现“关键动作：”“状态变化：”“触发：”“处理：”“成功结果：”“失败与恢复：”等加粗或行首标签堆叠 | P2 | `content` |
| 43.  表格只用于结构化事实 | 字段表、页面区块表、操作表、状态表或数据流表承载详细需求正文，或页面正文完全由表格组成 | P2 | `content` |
| 44.  不使用 Mermaid | PRD 以 Mermaid 代码块替代流程图交付 | P1 | `structure` |
| 45.  draw.io 交付完整 | 需要流程图但缺源文件、PNG，或图文名称/流程不一致 | P1 | `structure` / `content` |
| 46.  无明确占位与 AI 痕迹 | 出现待补充、TBD、TODO、明显生成痕迹或空泛理由 | P1 | `content` |
| 47.  名词与编号统一 | 核心术语、稳定标识、页面名称或引用在不同模块不一致 | P1 | `consistency` |
| 48.  用户说明与实际规则一致 | Skill、模板、规则和脚本对旧结构的宣称未同步 | P2 | `structure` |

## 高影响事实与上游回退

涉及核心流程、角色权限、数据范围、关键状态、系统边界、产品范围或核心字段含义的未知，必须作为高影响问题审查，并在需要时输出 `needs_upstream_sync: true` 和 `affected_objects`。Review 不代写 PRD，不自动修改、不自动推进，不新增 Review 阶段、覆盖率报告或证明性回执。

## 分片结构与功能详细说明专项检查

| 检查项 | 触发证据 | 默认严重度 | 输出位置 |
|---|---|---:|---|
| S1. `4.x.6` 必需章节存在 | 有页面或业务动作的模块缺少 `4.x.6 功能详细说明` | P1 | `structure` |
| S2. `4.x.6` 非空且有落点 | `4.x.6` 为空、只有标题，或下面没有业务阶段、页面或动作 | P1 | `structure` / `content` |
| S3. 页面落在 `4.x.6` | Design 页面只在总体页面清单出现，未在对应模块的 `4.x.6` 落点 | P1 | `structure` / `consistency` |
| S4. 页面正文未摘要化 | 页面以“页面职责/使用对象/入口与返回/区块清单”元数据块作为主体，缺少业务判断链；或核心动作被压缩成模块摘要 | P1 | `content` |
| S5. 页面语义未被重新解释 | 角色页、组织页、审批页等被合并成无差别的“系统配置”摘要 | P1 | `consistency` |

## 页面动作、引用与验收顺序专项检查

| 检查项 | 触发证据 | 默认严重度 | 输出位置 |
|---|---|---:|---|
| T1. 页面/动作/终端格式统一 | 页面使用加粗行、动作使用六级标题或数字编号、PC 页面带“（管理端）”/“（PC端）”后缀、出现“页面：”前缀 | P2 | `structure` |
| T2. 页面操作承接与合并 | Design 有独立业务结果的操作未在对应页面展开或未说明唯一复用位置；无独立业务结果的简单浏览动作未按业务结果合并，或为复刻数量强行一对一生成；合并后丢失角色、前置条件、状态、数据范围、失败结果或后续去向；返回筛选保留、重置范围缺失；用“同上”掩盖差异 | P1 | `content` |
| T3. 无效引用与内部引用可定位 | “见 6.1”“按第十二章”等引用无法在当前 PRD 定位，或 Design 原编号伪装成 PRD 内部章节；上游引用未标明 Design 来源 | P1 | `consistency` |
| T4. 生效描述未推导时间范围 | 从“立即生效”等推导“历史记录不受影响”“仅后续对象生效”等 Design 未确认内容 | P1 | `consistency` |
| T5. 检查后修改已重新验收 | 最终 `prd.md` 修改晚于检查或状态更新，或仍使用旧检查结论宣称“零冲突”；“无法提取/无法判断”被写成“零冲突” | P1 | `structure` / `consistency` |

## 详细需求说明语义专项检查

对应执行计划的语义硬验收。以下任一项命中，详细需求说明不通过；Review 只标记问题，不代写、不自动推进。

| 检查项 | 触发证据 | 默认严重度 | 输出位置 |
|---|---|---:|---|
| U1. 页面主体非元数据清单 | 页面以“页面职责：/使用对象：/所属业务侧：/所处业务阶段：/入口与返回：/页面区块：/字段来源：”固定块作为主体 | P1 | `content` |
| U2. 页面有业务判断或任务 | 页面没有自然说明用户要完成的判断或业务任务，只有控件盘点 | P1 | `content` |
| U3. 动作标题表达业务结果 | 业务动作标题主要是“点击、打开、切换、返回、播放”等 UI 行为 | P1 | `content` |
| U4. 操作按业务结果合并 | Design 操作被机械一对一复刻，简单浏览动作没有按业务结果合并 | P1 | `content` |
| U5. 动作有处理规则和业务结果 | 动作只写按钮和跳转，没有处理规则、业务结果或状态影响 | P1 | `content` |
| U6. 复杂动作完整 | 多角色、多状态、多分支或外部协作动作缺少角色、状态、关键分支、失败恢复或下一步衔接 | P1 | `content` |
| U7. 主链路连续可读 | 页面正文需要读者跨多个表格才能拼出主链路 | P1 | `content` |
| U8. 非模板填空 | 多数页面使用同一套模板句式，替换字段名后仍完全相同 | P2 | `content` |
| U9. 无未授权高影响事实 | 为追求完整新增 Design 未确认的页面、字段、角色、权限、状态或流程 | P1 | `consistency` / `affected_objects` |
| U10. 待确认未被静默拍板 | 确认版 Design 的待确认事项被写成确定事实 | P1 | `consistency` / `affected_objects` |

## 自然语言硬约束专项检查

`4.x.6` 正文必须全部使用自然语言，按内容场景正确分工：自然段承接业务，数字编号列表表达有先后顺序的步骤和状态推进，`·` 并列列表表达同层并列的展示、校验、限制、异常和动作。每一项必须是完整业务语句，能读出条件、含义或结果。

| 检查项 | 触发证据 | 默认严重度 | 输出位置 |
|---|---|---:|---|
| U19. 无键值对句式 | “字段名：说明”“来源：某系统”“结果：已完成”等键值对式模板承载正文，或连续多行键值对代替自然语义 | P1 | `content` |
| U20. 三种表达分工正确 | 数字编号列表用于无顺序的字段盘点；`·` 并列列表拆散有先后关系的状态推进；自然段承担本应分步的复杂处理链路 | P1 | `content` |
| U21. 整章不使用模板填空 | 多个页面使用同一套模板句，仅替换页面名和字段名即可互换 | P2 | `content` |
| U22. 简单页面保持简短 | 纯查看页面没有表单和状态变化，却为满足篇幅补写不存在的保存、提交、确认或异常分支 | P2 | `content` |

## 前端可独立开发专项检查

前端只读 `4.x.6` 即可确定页面产品行为，不查看 Prototype、Design 或旧 PRD。以下检查项按页面实际能力判断适用性；纯查看页不要求提交去向，无筛选页不要求分页。

| 检查项 | 触发证据 | 默认严重度 | 输出位置 |
|---|---|---:|---|
| V1. 页面形态与边界可判断 | 无法从正文判断是看板、列表、详情、表单还是多页面组合；列表和详情、查看和编辑、管理端和移动端混成一个无法拆分的描述 | P1 | `content` |
| V2. 页面构成清楚 | 业务区域及其共享的当前对象、查看范围或筛选条件不明确；关键业务信息应出现在指标区、列表、详情、表单还是历史记录由前端自行决定 | P1 | `content` |
| V3. 页面内容可读 | 关键字段、指标、状态、图片、视频、趋势、历史记录和操作入口在正文不可读；复杂页面只描述目的和最终动作，省略用户赖以判断的内容 | P1 | `content` |
| V4. 展示和输入方式明确 | 展示方式影响业务理解或操作时未说明文本、标签、图片、播放器、卡片、列表、趋势图、单选、多选、下拉或多行输入；前端需自行判断只读文本还是输入框 | P1 | `content` |
| V5. 字段来源、只读与显隐完整 | 动态内容未说明业务来源；已有值带出、只读/可编辑、编辑角色、显隐条件、空值/未知值/超长/异常值展示缺失 | P1 | `content` |
| V6. 状态驱动操作完整 | 多角色、多权限或多业务状态下操作入口显隐/可点性未写；状态变化后按钮、字段、列表项和状态标签如何刷新未写；只写“已完成状态只读”不说明变化 | P1 | `content` |
| V7. 页面过程状态完整 | 加载中、空数据、加载失败、无权限、离线、部分失败或外部资源不可用时未写用户可见结果、已有数据保留和恢复；范围切换失败未写旧数据处理，留下展示上一组织数据的歧义 | P1 | `content` |
| V8. 导航与状态保留完整 | 页面入口、成功后停留/跳转/返回、返回目标，以及返回后筛选、排序、分页、滚动位置或未提交内容保留缺失（仅实际存在且影响继续工作时要求） | P1 | `content` |
| V9. 多终端差异分别表达 | 管理端、移动端、小程序共同参与闭环时，未分别写各终端页面内容、编辑能力、状态变化和角色衔接；仅用“管理端只读、移动端可操作”概括 | P1 | `content` |

## 后端业务闭环专项检查

后端只读 `4.x.6` 即可确定业务数据流和状态结果，不查看 Design。以下检查项按业务实际能力判断适用性；无提交动作的页面不要求写入对象，无外部系统协作的页面不要求补偿。

| 检查项 | 触发证据 | 默认严重度 | 输出位置 |
|---|---|---:|---|
| W1. 数据来源可判断 | 关键数据来自哪个业务对象、用户录入、系统计算、组织权限、设备或外部系统不可判断；仅写“系统展示”“系统获取” | P1 | `content` |
| W2. 权威来源与覆盖关系 | 多来源字段未写当前权威值、人工修改是否覆盖原值、后续同步是否再次覆盖；未确认且影响业务结果 | P1 | `consistency` / `needs_upstream_sync` |
| W3. 查询和计算口径完整 | 查询、指标、趋势、下钻和导出未写对象、组织、时间、状态和筛选范围，或纳入、排除、去重和计算规则；仅写“系统统计今日数量”“系统计算占用率” | P1 | `content` |
| W4. 输入与校验完整 | 必填、取值、字段联动或互斥、校验时点、校验失败后业务对象和页面状态缺失；冲突二次确认后的业务处理结果未写 | P1 | `content` |
| W5. 写入对象明确 | 保存、提交、修改、绑定、领取、撤回、删除、作废或归档未明确修改哪个业务对象，研发无法判断是主信息、当前任务、业务快照、关联记录还是多个对象 | P1 | `content` |
| W6. 字段、状态与关联变化完整 | 成功后哪些字段和状态变化、是否同步改变关联对象、状态变化后哪些动作不再允许未写；只写“保存成功”“提交成功”或“进入已完成” | P1 | `content` |
| W7. 新增记录与留痕完整 | 生成任务、台账、告警、处理记录、修改历史或审计记录时未写生成时机、核心内容、查看角色和下游用途；只写“记录操作日志” | P1 | `content` |
| W8. 下游影响完整 | 操作结果会进入哪些列表、详情、台账、统计、告警、待办或其他角色业务环节未写；结果写入后是否生效仍需询问产品 | P1 | `content` |
| W9. 重复、并发和外部变化完整 | 任务可能被他人领取/处理、用户可能重复提交、外部事件可能改变状态时，未写最终业务结果、是否覆盖原结果、已填内容保留和下一步；冲突后的业务结果交给研发决定 | P1 | `content` |
| W10. 外部系统失败边界完整 | 外部系统未写数据提供方、使用方式、失败后对象状态、用户可见结果和恢复责任；未确认的重试/超时/补偿阻塞核心业务 | P1 | `consistency` / `needs_upstream_sync` |

## 数据范围与统计口径专项检查

出现指标卡片、数字统计、图表趋势、汇总列表、组织下钻、导出结果、按组织/时间/车型/状态/任务范围筛选的页面，或“当前/今日/实时/平均/占用率/完成率/异常数”等业务结果时，逐项确认：

| 检查项 | 触发证据 | 默认严重度 | 输出位置 |
|---|---|---:|---|
| U11. 组织与数据范围明确 | 当前角色能看到的组织和数据范围不明确，或用全局权限摘要代替页面范围 | P1 | `content` / `consistency` |
| U12. 同一范围贯穿 | 页面选择器、筛选条件、指标卡片、明细列表、趋势和导出使用不同范围 | P1 | `consistency` |
| U13. 时间口径明确 | 时间窗口和统计时点（自然日、近 24 小时、实时当前值）不明确 | P1 | `content` |
| U14. 分子分母与纳入排除明确 | 占用率等统计的分子、分母、去重规则、状态纳入和排除规则不明确 | P1 | `content` |
| U15. 空值零值区分 | 无数据、确实为零、数据缺失、统计失败未区分展示 | P2 | `content` |
| U16. 下钻继承条件 | 指标下钻后的明细未继承组织、时间和筛选条件 | P1 | `consistency` |
| U17. 敏感信息与导出权限 | 敏感字段、车辆级明细和导出未遵循角色权限 | P1 | `consistency` |
| U18. 刷新与局部失败 | 缓存、刷新或部分失败可能展示超出权限或过期范围的数据 | P1 | `content` |

“字段来源已写”“全局权限章节已写”“页面有服务区选择器”不能代替以上验收。

## 统计页与复杂动作逐页验收专项检查

含统计、看板、趋势、下钻或导出的模块，每个统计页必须单独回答以下问题，不能只凭“支持查询、重置、下钻、导出”或“指标卡片”一句带过；含多角色、多状态、多分支、破坏性或外部协作动作的模块，每个复杂动作必须单独回答以下问题。

| 检查项 | 触发证据 | 默认严重度 | 输出位置 |
|---|---|---:|---|
| R1. 统计页逐页（前端） | 任一统计页无法确定页面区域、指标集合、筛选条件、空态、失败态和下钻入口/目标；指标只是名称罗列，没有页面级正文 | P1 | `content` |
| R2. 统计页逐页（后端） | 任一统计页无法确定统计对象、组织范围、时间边界、状态纳入/排除/去重、计算口径、写入对象（如有）和下游结果；只写“系统统计”或引用 Design §x.x 代替页面正文 | P1 | `content` |
| R3. 复杂动作逐项 | 任一复杂动作缺少角色、允许状态、输入、校验、成功后的对象和状态变化、失败保留或下一责任人 | P1 | `content` |
| R4. 状态条件“或”无依据 | 状态条件或动作分支出现“或”，但没有分支依据、触发条件或 Design 依据，研发无法判定何时走哪条分支 | P1 | `content` / `consistency` |
| R5. 未评估项如实记录 | 脚本无法提取权限、输出 possible_omission 或 needs_semantic_judgment 时，审查结论未明确写“未评估”而是写成通过或“零冲突” | P2 | `structure` |
