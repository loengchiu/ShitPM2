# Review 检查项清单

> 本文件是 reviewer skill 的执行依据，不是 writer 的写作指导。
> 检查项引用规约 §3.4 和 §7.2。

## 一、design review 检查项

### 结构完整性

1. 核心章节是否全部存在（角色定义、模块定义、页面清单、字段定义、规则与状态定义、权限定义）
2. 辅助章节是否存在（可选，不强制）

### 内容质量

3. 字段定义属性是否齐全（9 属性：名称、类型、长度、必填、默认值、枚举值、格式、业务来源、说明）
4. 权限定义是否覆盖到字段级
5. 权限是否按"页面 > 角色 > 字段权限例外"组织
6. 状态定义是否覆盖完整

### 一致性

7. metadata/design 与 design.md 是否一致
8. 稳定 ID 是否正确生成（6 种前缀）
9. design.md 正文中是否有稳定 ID 泄漏
10. 不新增 align 未确认的范围

## 二、PRD review 检查项

### 坏味道检查（引用规约 §7.2）

1. 是否为标签式正文（`**页面目标：**`、`**关键动作：**`、`**状态变化：**`、`**异常提示：**`）
2. 是否为动作流水账（只按点击顺序描述动作过程）
3. 是否为纯表格式页面正文
4. 是否过多加粗
5. 是否有模板腔（"用于承载""用于支撑""需支持""同常规"）
6. 是否有模糊表述（"按配置"、"按规范"、"同常规"、"待补充"、"详见原型"、"待定"、"按业务规则"）
7. 是否出现原因腔（"方便用户理解""避免用户误判""符合操作习惯"）

### 三层覆盖检查

8. 每个页面是否覆盖界面元素与展示规则
9. 每个页面是否覆盖交互逻辑与状态流转
10. 每个页面是否覆盖异常处理与边界场景

### 写作质量检查

11. Markdown 标题层级是否稳定，中文编号前缀是否仅增强结构感且未跳级
12. 页面内部是否按用户动作组织（动词短语），非 UI 区域盘点
13. 页面开头可用一段交代区域职责，但后文不得退回按区域逐项说明
14. 每个动作是否覆盖触发、过程、结果、异常四类信息，但不套用固定四段格式
15. 简单动作是否一段话带过，复杂动作是否按复杂度展开
16. 有顺序的流程是否用 `1. 2. 3.`，并列规则是否用 `·`
17. 所有数值是否写死具体数字，无占位符（"按配置""N 条"等）
18. 静态内容是否用双引号标明，动态内容是否说明数据来源
19. 超长文本场景是否写清截断/换行/滚动/悬停查看全文的处理方式
20. 按钮是否写清可点击/不可点击条件、点击反馈、成功变化、失败提示
21. 表单是否写清输入限制、校验时机（实时/失焦/提交时）和错误提示文案
22. 列表是否写清加载方式、加载中提示、无数据/失败/完毕状态
23. 弹窗是否写清触发/关闭方式、遮罩层行为、多弹窗优先级
24. 异常是否写清网络异常、权限不足、关键功能失效时的降级处理
25. 标题下内容是否连续完整，无空栏目、无占位段
26. 是否未使用伪缩进字符、手敲空格模拟首行缩进、空行制造视觉层级
27. 表格是否只用于数据字典、权限矩阵、状态映射、枚举定义
28. 是否禁用模板腔和模糊表述

### 一致性检查

29. PRD 字段列表与 design.md 字段定义是否一致
30. PRD 权限口径与 design.md 权限定义是否一致
31. PRD 状态机与 design.md 状态定义是否一致
32. 页面编号是否重复
33. 是否存在动作复用（不同页面的动作描述完全照抄）
34. 是否跨节代写（一个页面的规则在另一个页面描述）

### 结构检查

35. 核心章节是否完整（详细需求说明、权限汇总、数据字典、状态机）
36. 数据字典是否使用 9 列格式（字段、类型、长度、必填、默认值、枚举值、格式、业务来源、说明）
37. 数据字典按实体分组，"业务来源"限于：用户填写、系统生成、外部同步、关联带出
38. 状态机是否按核心业务对象组织，包含状态集合、迁移、触发动作和限制条件
39. 权限汇总是否包含页面级、按钮级、字段级

### 一致性校验（机读交叉校验）

40. 功能覆盖：design 页面清单中每个页面是否有对应章节
41. 字段覆盖：design 字段定义中每个字段是否在数据字典或页面章节中体现
42. 字段落地：数据字典每个业务字段是否在详细需求说明、权限汇总、状态流转、验收标准或风险待确认中有明确落点
43. 字段一致性：同一字段在不同页面的展示格式和校验规则是否一致
44. 权限一致性：权限汇总与各页面按钮可见性/可操作性是否匹配
45. 状态一致性：状态机与各页面状态筛选/展示是否一致
46. 变更传播：本轮若修改了字段、页面动作、状态、权限、规则阈值或验收项，相关章节是否已同步更新

### 门禁规则

47. 一致性校验为必做门禁，不是建议
48. 功能/页面/字段/字段落地/模糊表述有任何缺口，不得通过 review
49. 仅表达不足：留在当前稿件修正
50. 问题来自上游（design 缺失或错误）：停止，回退到 design 修复

### 角色视角自审

生成完毕后从三个视角审读：

- **开发视角**：能否直接写代码（字段定义是否完整、接口行为是否隐含在描述中、边界是否明确）
- **测试视角**：能否直接写用例（触发条件是否清楚、预期结果是否可验证、异常路径是否覆盖）
- **设计视角**：能否直接画原型（页面结构是否清楚、交互反馈是否明确）

上游事实源缺失不得脑补，标记 `[待确认]` 或回退上游。
