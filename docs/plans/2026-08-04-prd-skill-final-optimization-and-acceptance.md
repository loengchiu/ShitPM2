## 2. 真实项目暴露的问题

### 2.1 属于 Skill 约束不足的问题

| 问题 | 真实表现 | 当前规则为什么没有拦住 |

| Design 内同一状态存在两种口径 | 状态表写“未处理 → 处理中”，页面操作写“未处理 → 处理中或已处理”，PRD 同时保留两种口径 | 阶段 A-1 要求识别冲突，但没有强制把状态表、页面操作和字段校验放在一起逐项比较 |

### 2.2 不是本轮 Skill 根因的问题

以下问题不能由 PRD Skill 静默解决：

- Design 本身的状态冲突；
- Design 页面清单与数据字典的必填属性冲突；
- Design 中角色、权限、状态或历史处理方式没有拍板；
- `prd-consistency-check.py` 无法正确解析某种自然语言表达。

遇到这些问题时，正确结果是停止受影响模块、指出冲突并回到 Design Fix，而不是由 PRD 选择其中一种口径。

### 2.3 尚未被智慧停车项目验证的规则

智慧停车 Design 的“非页面落点字段”数量为 0，因此该项目不能证明“内部字段回读”规则已经有效。

## 3. 本轮四个核心直接约束

以下四条必须直接写入 `skills/spm-prd/SKILL.md`。可以同步展开到写作规则和 Review 清单，但不能只写在参考文档或验收文档中。

### 3.1 直接约束一：同一事实三处交叉比较

阶段 A-1 不只按章节顺序浏览 Design，还必须针对同一高影响事实做交叉比较：

1. 状态表或状态流转说明；
2. 页面操作、按钮条件和动作结果；
3. 字段必填、默认值、校验和提交条件。

至少比较以下属性：

- 当前状态；
- 目标状态；
- 允许角色；
- 允许状态；
- 必填属性；
- 默认值；
- 校验条件；
- 生效时点；
- 失败和恢复结果。

发现同一事实存在不兼容口径时：

- 记录冲突位置、冲突内容、影响对象和受影响模块；
- 停止对应模块写作；
- 回到 Design Fix；
- 不得以“页面优先”“状态表优先”“数据字典优先”等通用规则自行裁决。

低影响的纯展示差异可以保守表达；会改变流程、权限、状态、数据边界或提交结果的冲突不能继续写。

### 3.2 直接约束二：引用必须指向真实存在的当前章节

阶段 D 和最终回读必须检查 PRD 内部引用。

规则如下：

- PRD 内部引用必须指向当前 `prd.md` 中真实存在的章节、页面或规则名称；
- 不得把 Design 原章节编号直接写成 PRD 内部章节编号；
- 不得残留“见 6.1”“按第十二章”等无法在当前 PRD 中定位的引用；
- 确实需要引用上游 Design 时，必须明确写成 `Design §6.2` 或“Design 的××规则”，不能伪装成 PRD 自身章节；
- 章节重编号、移动或删除后，所有受影响引用必须同步修正；
- 引用无法定位时，不能以“读者应该知道”为由保留。

阶段 D 仍只允许局部修正，不得为了修复引用整篇重新生成 PRD。

### 3.3 直接约束三：不得从生效描述推导时间范围

Design 出现“立即生效”“修改后生效”“启用后生效”等描述时，PRD 只能承接已明确写出的事实。

除非 Design 已明确说明，否则不得继续推导：

- 只影响后续新建对象；
- 是否影响当前进行中的对象；
- 历史记录不受影响；
- 历史记录需要重算；
- 已产生结果需要追溯更新；
- 当前任务继续使用旧规则；
- 新旧规则并行；
- 自动迁移、补偿或回滚。

时间范围会影响业务结果时，必须列为高影响未知并回到 Design；不能把常见产品经验写成确定事实。

### 3.4 直接约束四：最后一次写入后重新验收

最终顺序固定为：

1. 完成最后一次 `prd.md` 写入；
2. 回读本次受影响的模块；
3. 运行现有 PRD 检查；
4. 处理检查发现的真实问题；
5. 如再次修改 `prd.md`，回到第 2 步；
6. 确认最终内容不再变化后，更新 `.workflow/status.json`；
7. 最终交付前再次直接阅读真实 `prd.md`。

任何发生在检查或模块验收之后的正文、字段、状态、权限、异常、引用、标题或格式修改，都会使前次检查和对应模块验收失效。

不得出现：

- 先更新状态，再修改 PRD；
- 使用修改前的检查结果证明修改后的 PRD 已通过；
- 文件已变化，但仍宣称“上一轮零冲突”；
- 将“无法提取”“无法判断”表述为“零冲突”。

“无法提取”只能报告为无法判断，并触发人工回读；它不等于通过，也不等于确定存在问题。

## 4. 页面操作逐项承接

页面覆盖不能只检查页面名称。每个模块完成前还必须回读当前模块的 Design 页面操作。

### 4.1 承接规则

- Design 明确列出的页面操作必须在对应页面下展开；
- 操作可以写成独立动作，也可以明确说明复用哪个已完整定义的动作；
- 不得用“同上”“按常规处理”“支持相关操作”等表达掩盖角色、条件、结果或异常；
- 查询、重置、返回、取消、关闭、导出、下钻、上传、删除等操作，只要 Design 明确描述了业务效果或状态保留规则，就必须承接；
- 同名动作在不同页面的角色、状态、数据范围或结果不同，必须分别说明；
- 纯浏览器行为、无业务差异且 Design 未定义业务结果的控件，不要求人为扩写。

### 4.2 模块完成条件补充

在现有模块完成条件中补充：

> 当前模块的 Design 页面操作已逐项回读；每个有业务结果、状态影响、数据影响、筛选恢复或权限差异的操作，均已在对应页面下展开，或明确指向当前 PRD 中唯一且完整的复用定义。

### 4.3 真实项目回归重点

智慧停车回归时至少复查：

- 车辆详情返回列表后是否保留原筛选条件；
- Design 已定义“重置”的页面是否说明重置范围和结果；
- 页面动作是否仍存在名称落点但业务效果缺失；
- 同一操作在 PC 管理端和移动端的权限或结果是否被错误合并。

## 5. 页面、动作和终端命名格式

### 5.1 最终格式

页面固定使用六级标题：

```markdown
###### 车辆信息记录
```

动作固定使用单独一行加粗：

```markdown
**查询车辆记录**
```

完整示例：

```markdown
###### 车辆信息记录

页面职责、使用对象和所在业务阶段。

**查询车辆记录**

动作的角色、前置条件、输入、处理、成功结果、失败结果和恢复方式。

###### 待核查任务（移动端）

页面职责、使用对象和所在业务阶段。

**领取核查任务**

动作正文。
```

### 5.2 终端命名规则

- 默认页面为 PC 管理端页面；
- PC 管理端页面名称不加“（管理端）”“（PC端）”或“（终端）”；
- 只有移动端、小程序、自助终端等特殊终端需要在页面名称后保留终端标识；
- 移动端页面示例：`###### 待核查任务（移动端）`；
- 页面清单中的“终端”列可以继续保留，用于表达终端属性；
- 页面正文标题和页面映射中的名称必须一致；
- 同一业务页面同时存在 PC 与移动端版本时，PC 使用无后缀名称，移动端使用“（移动端）”后缀。

### 5.3 禁止格式

```markdown
**车辆信息记录（管理端）**

###### 查询车辆记录
```

禁止原因：

- 页面不能使用加粗行；
- PC 页面不能默认附加“（管理端）”；
- 动作不能使用六级标题；
- 六级标题只用于页面名称。

### 5.4 与现有标题层级的关系

- `#### 4.x.6 功能详细说明`：模块固定章节；
- `##### 业务阶段名称`：业务阶段；
- `###### 页面名称`：页面；
- `**动作名称**`：页面动作。

不得再为动作增加数字标题层级。

### 阶段 4：确认分片命令真实执行

阶段 C 的每个模块必须实际运行：

```text
python $BUNDLE/scripts/python/context-pack.py --bundle-root $BUNDLE --project-root . --stage prd --pass module --card scenes
```

要求：

- 不能只在 Skill 中保留命令而执行时跳过；
- 未运行模块上下文装载，不得宣布该模块按全量分片流程完成；
- 不要求新增永久日志或证明文件；
- 执行失败时报告真实错误，不能假装已加载清单。

### 阶段 5：同步既有测试

1. 运行与 PRD Skill、模板、上下文装载、文风相关的现有测试；
2. 因页面/动作格式变化导致旧断言失败时，更新原测试；
3. 只补最小的确定性断言，例如模板包含新格式且不再宣称旧格式；
4. 不新增语义覆盖率检查器；
5. 不把“模型是否完整理解业务”伪装成正则通过。

### 阶段 6：执行样本与真实项目验收

按第 8 章执行。发现问题时先判断属于：

- Skill 约束缺失；
- 模板或参考规则未同步；
- Design 上游冲突；
- 校验器误报；
- 执行者没有遵守已有命令和顺序。

只有前两类直接在本轮修复。第三类回 Design，第四类单独说明，第五类重新按 Skill 执行。

## 8. 验收方案

### 8.1 静态同步验收

必须同时满足：

- Skill 本体可找到四个核心直接约束；
- 模板、规则、场景清单和 Review 清单没有相反口径；
- 活动示例不再使用页面加粗、动作六级标题；
- PC 页面默认不带“（管理端）”；
- 移动端页面保留“（移动端）”；
- 六级标题只用于页面；
- 动作使用单独一行加粗；
- 现有 `writing` 和 `module + scenes` 上下文仍能装载所需规则。

建议使用 `rg` 做确定性搜索，但最终必须人工阅读上下文，不能只看命中数量。

### 8.2 页面与动作格式验收

正向样本：

```markdown
##### 车辆记录查询

###### 车辆信息记录

页面职责正文。

**查询车辆记录**

动作正文。

###### 待核查任务（移动端）

页面职责正文。

**领取核查任务**

动作正文。
```

通过条件：

- 两个 `######` 均为页面；
- 两个动作均为加粗行；
- PC 页面没有终端后缀；
- 移动端页面保留终端后缀；
- 动作没有数字编号或标题层级。

失败条件：

- `**页面名称**`；
- `###### 动作名称`；
- `###### 车辆信息记录（管理端）`；
- `###### 车辆信息记录（PC端）`；
- 页面名称写成 `###### 页面：车辆信息记录`。

### 8.3 Design 冲突阻断探针

构造同一对象的冲突片段：

- 状态表：处理后只能进入“处理中”；
- 页面操作：处理后可进入“处理中”或“已处理”；
- 字段说明：处理备注选填；
- 页面提交规则：处理备注缺失不能提交。

通过条件：

- 阶段 A-1 同时识别状态目标冲突和必填冲突；
- 明确指出冲突位置和影响模块；
- 对应模块不进入正文写作；
- 不选择其中一种口径生成 PRD；
- 结论为回 Design Fix。

失败条件：

- 同时把两种口径写入 PRD；
- 默认页面规则优先；
- 默认状态表优先；
- 把冲突降级为普通写作提示后继续生成。

### 8.4 历史数据补造探针

Design 只提供：

> 阈值修改后立即生效。

通过条件：

- PRD 只承接“修改后立即生效”；
- 不写“历史记录不受影响”；
- 不写“仅后续车辆使用新阈值”；
- 不写当前进行中车辆使用新规则或旧规则；
- 如业务必须明确作用范围，则列为高影响未知并回 Design。

### 8.5 无效章节引用验收

在验收副本中设置以下错误：

- `见 6.2`，但 PRD 不存在 6.2；
- `按第十二章非功能要求执行`，但 PRD 没有第十二章；
- 模块重编号后仍引用旧编号；
- 标题和表格粘连。

通过条件：

- 所有 PRD 内部引用均能在当前文件中定位；
- 上游引用明确写成 `Design §6.2`；
- 不残留 Design 原编号伪装成 PRD 内部编号；
- 不存在标题与表格粘连；
- 修复只触达相关引用和格式，不重写模块正文。

### 8.6 页面操作逐项承接验收

选取至少两个包含多个操作的 Design 页面，其中必须包括：

- 查询与重置；
- 查看详情与返回；
- 一个有权限或状态条件的强动作。

通过条件：

- 每个有业务结果的 Design 操作都有动作正文或明确复用位置；
- 返回操作的筛选条件保留规则没有遗漏；
- 重置操作说明重置哪些查询条件；
- 强动作写明角色、允许状态、成功结果和失败/恢复；
- 不使用“同上”隐藏关键差异。

### 8.7 非页面字段专项验收

使用独立样本，至少包含：

- 主键；
- 内部关联字段；
- 系统留痕字段；
- 计算字段；
- 流程状态字段；
- 权限或数据范围依据；
- 历史或版本字段。

通过条件：

- 每个非页面字段都进入对象字段定义；
- 每个字段说明内部业务用途；
- 高影响字段原则上一字段一行；
- 不因页面没有控件而删除字段；
- 不补造 Design 未给出的类型、默认值、必填或历史处理方式。

该验收不能用智慧停车项目替代。

### 8.8 最后写入后重验收

按以下顺序做一次真实演练：

1. 完成模块写入；
2. 运行现有检查；
3. 修改一个已完成模块的动作结果或章节引用；
4. 验证前次检查被视为失效；
5. 回读受影响模块；
6. 重新运行现有检查；
7. 不再修改 PRD 后更新状态。

通过条件：

- 修改后没有沿用旧检查结论；
- 受影响模块重新执行完成条件；
- `.workflow/status.json` 在最终 PRD 稳定后更新；
- “无法提取权限”没有被报告为“权限零冲突”。

### 8.9 简单项目生成验收

使用现有简单样本的副本重新生成 PRD。

通过条件：

- 所有模块均有非空 `4.x.6`；
- 每个页面使用 `###### 页面名称`；
- 每个动作使用 `**动作名称**`；
- PC 页面无“（管理端）”；
- 移动端页面保留“（移动端）”；
- 页面操作逐项承接；
- 不补造状态、权限、历史处理或异常恢复；
- 生成过程中实际运行 `--pass module --card scenes`；
- 最终没有整篇重新生成或概括压缩。

### 8.10 智慧停车真实复杂项目验收

正式项目：

`D:\work\交投软件中心\智慧服务区\智慧停车区`

必须先复制到临时目录，在副本中验收。禁止改动正式项目的 Design、PRD 和 confirmation。

### 第一步：保持 Design 原样做冲突阻断验收

由于当前 Design 已存在状态和必填口径冲突，增强后的 Skill 应当：

- 在阶段 A-1 识别冲突；
- 停止受影响模块；
- 不覆盖副本中的原 PRD；
- 报告需要 Design Fix。

如果仍然直接生成完整 PRD 并自行选择口径，本轮验收失败。

### 第二步：全量生成回归的前置条件

只有在以下任一条件满足后，才能继续做完整生成：

1. 上游已正式修复 Design 并重新获得用户确认；或

不得由执行 AI 自行决定冲突口径并伪造“已解决”的测试基线。

### 第三步：完整生成后的通过条件

- PC 页面不带“（管理端）”或“（PC端）”；
- 移动端页面保留终端标识；
- 不再出现两种状态口径并存；
- 不再出现“备注缺失不能提交”和“处理备注选填”并存；

### 8.11 现有测试验收

结果处理：

- 本轮修改引起的失败必须修复；
- 与本轮无关的既有失败单独报告，不扩大修改范围；
- 文风检查器出现误报时先确认解析原因，不为消除误报改变正确 PRD 语义；
- 不以测试数量或退出码代替真实 PRD 人工回读。

## 9. 总体验收标准

全部满足才可宣布完成：

1. 现有全量分片、直接落盘、`4.x.6` 必需和禁止整篇重写规则保持不变；
2. 四个核心直接约束已写入 Skill 本体并同步到相关规则；
3. Design 状态、页面操作和字段校验冲突会阻断对应模块；
4. 不再补造历史、进行中或后续对象处理方式；
5. PRD 内部引用全部可定位，Design 引用有明确来源标识；
6. 检查后修改 PRD 会触发重新验收；
7. Design 页面操作逐项承接；
8. 页面统一使用 `###### 页面名称`；
9. 动作统一使用 `**动作名称**`；
10. PC 页面不带终端后缀，移动端页面保留终端标识；
11. 非页面字段专项样本通过；
12. 智慧停车原始冲突能被正确阻断；
13. 只有冲突解决并确认后才执行智慧停车完整生成；
14. 没有新增综合门禁、覆盖率文件、承接矩阵或证明流程；
15. 没有修改用户正式 Design、PRD 或 confirmation；
16. 没有执行 Git commit 或 Git push。

任一项不满足时，只能报告“部分完成”或“验收失败”，不能宣布优化完成。

## 11. 禁止重新引入的复杂度

本轮明确禁止：

- 新建 PRD 综合检查器；
- 新建 Design→PRD 覆盖率文件；
- 新建页面—动作承接矩阵；
- 新建最终验证回执、机器签名或验收 JSON；
- 为每个模块增加独立状态文件；
- 把四个直接约束拆成新的编排阶段；
- 强制使用 subagent；
- 最后由主 Agent 重新读取全部模块并整篇生成 PRD；
- 用脚本替代 Design 冲突、高影响未知和业务语义判断。

本轮判断最终产物是否正确，仍以真实 PRD 的事实一致性、业务闭环完整性、页面动作承接和可读性为准。
