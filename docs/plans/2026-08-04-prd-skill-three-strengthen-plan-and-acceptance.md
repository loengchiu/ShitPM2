# PRD Skill 三项补强执行与验收方案

> 日期：2026-08-04  
> 状态：待执行  
> 执行对象：其他 AI  
> 适用范围：PRD Skill、PRD 写作规则、PRD 模板、现有一致性校验器  
> 核心目标：补强 Design 风险识别、非页面落点字段回读和已完成模块变更后的重新验收，不新增综合门禁或复杂证明流程。

## 1. 本轮结论与边界

本轮不重新设计 PRD 分片架构。全量分片、直接落盘、`4.x.6` 必需和禁止整篇重写的规则已经存在，本轮只补以下三个 Skill 缺口：

1. Design 冲突和高影响未知没有在模块写作前被系统识别；
2. Design 的“非页面落点字段”没有被强制单独回读；
3. 已完成模块被后续修改后，没有自动失效并重新验收。

现有 `prd-consistency-check.py` 的解析误报另列为配套修复，不得把解析器问题转化为 PRD Skill 的新门禁。

## 2. 已确认的处理原则

### 2.1 Design 冲突不得由 PRD 静默拍板

如果 Design 的页面清单、数据字典、状态流转、权限矩阵或其他权威段落存在冲突，PRD 不得自行选择“页面优先”“数据字典优先”或其他解决方案。

PRD 只能：

- 保留冲突事实；
- 说明冲突位置和影响对象；
- 将高影响冲突列为待确认事项；
- 在无法确认前停止对应模块写作；
- 建议回到 Design Fix。

### 2.2 高影响未知与事实冲突分开记录

没有冲突但 Design 未定义的高影响行为，同样不得由 PRD 补造。

至少识别以下未知：

- 状态及状态转换；
- 角色、权限和数据范围；
- 异常、回退、撤回和恢复；
- 必填、默认值、校验和生效时点；
- 外部系统协作、同步和失败责任。

### 2.3 校验器不能替代语义验收

解析器返回的 `missing`、`hallucinated` 或权限数量为 0，只能作为辅助信息。

解析失败、无法提取和真实语义冲突必须分开表达。不得因为脚本退出码为 0 就宣布 PRD 完整，也不得因为解析器误报而新增覆盖率 JSON、承接矩阵或综合门禁。

## 3. 修改范围

### 3.1 Skill 必改文件

1. `skills/spm-prd/SKILL.md`
2. `references/prd-writing-rules.md`

### 3.2 模板按需要修改

`templates/prd.md` 只增加以下提示即可：

- 非页面落点字段必须进入对象字段定义；
- 高影响内部字段原则上一字段一行；
- 合并字段不能掩盖不同对象、不同属性或不同权限。

不得把所有字段强制改成固定格式，也不得把模板改造成大而全字段表。

### 3.3 校验器配套修改

仅在现有测试能复现问题时修改：

- `scripts/python/prd-consistency-check.py`
- 与该脚本直接相关的测试或样本

不得新增综合检查器、覆盖率文件、承接矩阵、统一回执或机器签名。

### 3.4 不得修改

- 用户正式 `output/design/design.md`；
- 用户正式 `output/prd/prd.md`；
- Design confirmation；
- 与本轮无关的 Skill、脚本和模板；
- Git 历史、远程分支和远程仓库。

## 4. Skill 补强一：阶段 A 增加 Design 风险清单

### 4.1 执行位置

放在全局扫描完成后、模块分片写作前。

不得要求把全部 Design 正文长期保留在上下文中。风险识别可以采用全局导航加定向回读：

1. 读取页面清单和业务模块；
2. 读取核心对象、数据字典和非页面落点字段；
3. 读取状态流转；
4. 读取权限矩阵和项目内操作权限；
5. 对高影响对象做交叉比较；
6. 记录风险后再进入模块写作。

### 4.2 风险清单至少包含

| 类型 | 必须记录的内容 |
|---|---|
| 事实冲突 | 冲突位置、涉及对象、两方事实、影响范围 |
| 高影响未知 | 未定义内容、可能影响的流程/权限/状态/数据边界 |
| 处理结论 | 已确认、待确认、回 Design Fix、可保守表达 |
| 模块影响 | 受影响的功能模块和页面 |

该清单是当前生成任务的临时工作材料，不是新的永久交付物或证明文件。

### 4.3 阻断规则

以下情况不得进入对应模块写作：

- 核心状态转换冲突；
- 角色或数据范围冲突；
- 强动作的允许角色或允许状态冲突；
- 核心字段必填、默认值或校验规则冲突；
- 异常恢复、外部协作责任或系统边界未定义且会影响业务闭环。

低影响、只影响展示表达的未知可以采用不承诺具体值的保守表达。

## 5. Skill 补强二：模块完成条件增加非页面字段回读

### 5.1 必须读取的内容

每个模块完成前，必须单独回读 Design 中的：

```text
非页面落点字段（按需）
```

同时回读本模块相关的核心业务对象字段和系统留痕字段。

### 5.2 每个字段必须有落点

每个非页面落点字段至少满足以下一项：

- 对象字段定义；
- 页面展示；
- 页面输入；
- 查询或筛选；
- 动作判断；
- 状态转换；
- 系统内部用途；
- 审计、版本或历史记录用途。

不能因为字段没有页面控件就从 PRD 中删除。

### 5.3 字段表达要求

内部字段必须说明其业务用途，并按需要分类为：

- 主键；
- 内部关联；
- 系统留痕；
- 计算字段；
- 流程状态；
- 权限或数据范围依据；
- 版本或历史记录字段。

高影响字段原则上一字段一行。只有字段含义、属性、权限和使用方式完全一致时，才允许合并表达。

### 5.4 与校验器的关系

字段一字段一行的要求是减少真实遗漏和解析歧义的写作建议，不是强制所有字段采用固定表格格式。

## 6. Skill 补强三：已完成模块变更失效规则

### 6.1 触发范围

任何阶段修改已完成模块的以下内容，都必须使该模块重新进入待验收状态：

- 功能详细说明；
- 页面；
- 字段；
- 状态；
- 权限；
- 异常和恢复；
- 验收标准；
- 待确认事项；
- 跨模块引用关系。

不只阶段 D 的整合修改才触发。

### 6.2 重新验收内容

修改后必须重新执行该模块的原完成条件：

1. `4.x.6` 存在且非空；
2. 页面和业务阶段落点正确；
3. 页面字段和非页面字段已回读；
4. 动作因果链完整；
5. 状态、权限、异常和恢复没有冲突；
6. 没有新增 Design 未确认事实；
7. 模块验收和待确认事项仍然有效。

### 6.3 上游 Design 变化

如果 Design 发生变化：

- 只使受影响模块失效；
- 与受影响模块存在共享对象、状态、权限或页面引用的模块同步进入影响评估；
- 不得默认把全部模块标记为已验收；
- 不得直接覆盖确认记录。

## 7. 校验器配套修复计划

校验器修复与 Skill 补强分开实施、分开验收。

### 7.1 斜杠合并字段

对“反馈人/回复人”等表达：

- 支持按语义拆分；
- 保留字段所属对象；
- 不把合并字段误判为全部缺失或全部新增；
- 无法拆分时标记为人工判断，不直接判定冲突。

### 7.2 页面名与章节黑名单

“数据字典”等名称既可能是页面名，也可能是 PRD 章节名。

解析时必须根据上下文区分：

- 页面清单中的页面；
- 页面正文中的页面；
- PRD 结构章节。

不能因为命中章节黑名单就把真实页面判为缺失。

### 7.3 状态组合值

对“已启用/已停用”“待整改/整改中/待销号”等组合表达：

- 按枚举或状态集合拆分；
- 保留状态所属对象；
- 不把展示标签误当成状态机转换；
- 无法确认语义时归入人工判断。

### 7.4 同名字段按对象区分

字段匹配至少使用：

- 业务对象；
- 页面或模块；
- 字段所属区块；
- 字段类型和属性。

不能只按字段名称全局匹配。

### 7.5 权限提取为零

当权限解析结果为 0 时，输出必须明确为：

```text
权限无法从当前正文提取，需人工验收
```

不得显示为“权限一致”或等价通过结论。

## 8. 执行顺序

1. 读取当前 `spm-prd`、写作规则、模板和验收报告；
2. 在 `spm-prd` 中加入 Design 冲突与高影响未知清单；
3. 在模块完成条件中加入非页面字段回读；
4. 增加所有阶段触发的模块失效和重验收规则；
5. 按需同步模板提示；
6. 使用简单样本验证三个 Skill 补强；
7. 使用复杂真实 Design 副本验证三个 Skill 补强；
8. 单独修复校验器解析问题；
9. 重新运行现有脚本，区分真实语义问题和解析噪声；
10. 按本文件验收；
11. 报告修改范围和残余问题；
12. 不执行 Git commit 或 Git push。

## 9. 验收总原则

必须同时满足：

1. **Skill 规则通过**：三项补强都有明确执行位置和停止条件；
2. **真实遗漏通过**：非页面落点字段不会再因流程遗漏而丢失；
3. **事实边界通过**：简单样本不能补造状态、权限和异常规则；
4. **变更失效通过**：修改已完成模块后，必须重新验收；
5. **解析器修复通过**：已知格式误报被正确分类，不新增综合门禁。

## 10. Skill 规则验收

### 10.1 Design 风险清单

通过条件：

- Skill 明确同时识别事实冲突和高影响未知；
- 明确列出状态、权限、异常恢复、默认值校验和外部协作；
- 明确高影响风险未处理前不得进入对应模块；
- 明确 PRD 不得自行选择冲突的一方作为最终事实。

失败条件：

- 只检查冲突，不检查未定义的高影响行为；
- 允许模块先写、最后再处理冲突；
- 以“页面优先”或“数据字典优先”作为未授权通用规则。

### 10.2 非页面字段回读

通过条件：

- 明确读取 Design 的非页面落点字段；
- 每个字段都有对象或系统内部用途落点；
- 高影响字段原则上一字段一行；
- 页面字段和内部字段不会因页面导向写作被忽略。

验收样本必须包含至少一个：

- 主键或内部关联字段；
- 系统留痕字段；
- 计算字段；
- 流程状态字段。

### 10.3 变更失效

通过条件：

- 任意阶段修改已完成模块都会触发重新验收；
- 重新验收包含字段、状态、权限、异常和待确认项；
- Design 上游变化只影响相关模块，但共享引用会进入影响评估；
- 没有以旧快照或旧哈希掩盖后续修改。

## 11. 简单样本验收

使用包含状态、复核、驳回或异常恢复的简单 Design。

必须验证：

1. Design 未定义“复核驳回后状态”时，PRD 不得自行补造；
2. 该事项必须进入高影响未知清单或待确认事项；
3. 已定义的状态转换仍然被完整承接；
4. 模块完成条件能够发现状态和异常遗漏。

## 12. 复杂样本验收

使用审计管理系统的 Design 副本，不修改用户正式文件。

必须验证：

- 15 个非页面内部字段全部有 PRD 落点；
- 页面字段、内部字段、状态字段没有被混为一类；
- 组织、用户、角色、审批流程等高影响页面保持独立语义；
- 项目组长/主审和字段必填冲突被识别为 Design 上游问题；
- PRD 不自行宣布某一方为最终权威；
- 受影响模块的 `4.x.6` 内容完整。

## 13. 变更失效验收

按以下步骤执行：

1. 完成一个模块并通过模块验收；
2. 修改该模块的一个字段、状态、权限或异常规则；
3. 检查模块是否自动或明确标记为待重新验收；
4. 重新执行模块完成条件；
5. 确认旧验收结论不能继续直接复用；
6. 确认未被修改的模块不被无理由重写。

如果报告只说明“哈希变化是定向补字段造成的”，但没有最后一次重验收证据，则该项不通过。

## 14. 校验器验收

### 必须通过

- 斜杠合并字段不再被一律判为遗漏或新增；
- 页面“数据字典”不再因章节黑名单而误报缺失；
- 状态组合值可以被正确分类；
- 同名字段按对象区分；
- 权限提取为 0 时显示“无法评估”；
- 真实的字段属性冲突仍能被发现。

### 不得通过的假设

- 脚本返回 0 就代表权限完整；
- 所有 `missing` 都是真实遗漏；
- 所有 `hallucinated` 都是真实新增；
- 解析器不支持的表达可以直接判定为产品语义错误。

## 15. 范围和交付验收

允许修改：

- `skills/spm-prd/SKILL.md`
- `references/prd-writing-rules.md`
- `templates/prd.md`
- 现有 `prd-consistency-check.py` 及直接相关测试

不允许：

- 新增综合门禁；
- 新增覆盖率 JSON、承接矩阵或机器证明文件；
- 修改用户正式 Design、PRD 或 confirmation；
- 无关格式化和重构；
- Git commit 或 Git push。

最终报告必须包含：

1. 修改文件清单；
2. 三项 Skill 补强的实际落点；
3. 简单样本结果；
4. 复杂样本结果；
5. 变更失效重验收结果；
6. 校验器误报修复结果；
7. 未解决的 Design 上游冲突；
8. 明确说明未执行 Git commit、Git push。

## 16. 最终判定

只有以下条件全部满足，才能报告本轮完成：

- Design 冲突和高影响未知在模块写作前被识别；
- 非页面落点字段全部完成回读和落点；
- 已完成模块被修改后不能绕过重新验收；
- 上游 Design 冲突没有被 PRD 静默拍板；
- 校验器误报得到单独修复；
- 没有新增复杂证明流程；
- 简单样本和复杂样本均通过；
- 用户正式 Design、PRD 和 confirmation 未被修改；
- 未执行未经授权的 Git commit 或 Git push。
