## 3. 目标行为

### 3.1 Design 侧目标

Design 生成和 Review 必须主动识别以下事实是否已定义、局部定义、未定义或冲突：

- 待办生成、分配、转办、处理、完成、撤回、过期和异常；
- 提醒/通知的触发对象、时机、渠道和频率；
- 编号生成时机、作用域、唯一性和断号处理；
- 数据字典来源、初始化、变更权限和对已有数据的影响；
- 文件存储、引用、版本、归集和档案边界；
- 审计侧、被审侧、管理端、移动端的入口和切换；
- 系统自动动作的触发、成功、失败和人工处理；
- 软删除、停用、撤回、作废、归档及关联传播；
- 枚举候选值、初始化清单或待确认状态；
- 页面区块、展示条件和状态驱动的操作条件。

Design 必须保留页面的以下事实：

- 页面所属业务侧；
- 入口、菜单或路由上下文；
- 所处业务阶段；
- 返回目标；
- 区块及区块业务目的；
- 字段和操作承载；
- 展示条件、操作条件和状态差异；
- 无权限、加载中、空态、异常、超长文本等展示状态。

高影响事实不能由 Skill 自动拍板。无法确认时进入待确认事项，并说明影响范围。

### 3.2 PRD 侧目标

PRD 生成必须在现有分片流程内增加以下承接责任：

1. 阶段 A-1 建立 Design 风险清单；
2. 每个模块写作前检查横切能力；
3. 每个页面在 `4.x.6` 中有页面职责、区块、展示行为和动作落点；
4. 具备状态条件的页面能回读状态驱动展示；
5. 系统自动动作具备失败处理或待确认；
6. 删除类动作具备关联传播或待确认；
7. 枚举、分页、导出和批量规则具备来源或待确认；
8. Design 页面操作逐项承接；
9. PRD 内部引用能定位当前 `prd.md`；
10. 最后一次写入后重新回读、检查和验收。

## 5. 具体规则要求

### 5.1 页面展示行为

在每个有页面的 `4.x.6 功能详细说明` 中，按实际适用情况承接：

- 加载中/骨架屏；
- 空态；
- 异常态；
- 无权限态；
- 超长截断、悬停全文、滚动或点击查看；
- 默认值和默认选中；
- 标签、颜色和状态展示；
- 分页、排序和列表上限；
- 返回、刷新和筛选条件保留。

无权限状态必须承接 Design 的具体语义。Design 写明“无权限不显示入口”时，PRD 必须明确入口、菜单或路由对该角色隐藏；不能改写成按钮置灰或进入后提示无权限。

加载中状态必须按页面或页面类型可定位，不能只写一句无法回读的“统一处理”。

超长文本必须承接 Design 已确认的显示方式和长度；没有确认长度时不得补数字，但要列为待确认。

### 5.2 页面区块和字段展示条件

页面正文至少说明：

- 页面职责；
- 使用对象和业务侧；
- 所处业务阶段；
- 页面区块；
- 区块业务目的；
- 区块承载的字段和操作；
- 已确认的区块联动、跳转、弹窗或抽屉关系。

Design 的字段“展示条件”不要求在 PRD 中机械复制八列表格，但每个条件显隐字段必须能在以下位置之一定位：

- 页面展示行为；
- 状态驱动展示；
- 页面字段使用差异；
- 动作结果或状态变化。

例如“未上报告原因仅在是否上报告=否时展示”“审批记录区仅提交后展示”，不能因字段已经在对象级定义就删除。

### 5.3 状态驱动展示

对存在状态机或状态标签的列表、详情、编辑页面，必须覆盖：

```text
状态：
可见操作：
置灰操作及原因：
隐藏操作：
字段展示/隐藏条件：
行点击和跳转条件：
标签和颜色：
状态变化后的按钮/字段刷新或消失时机：
```

可使用状态分组段落或局部表格，不强制固定矩阵，但不能只把状态条件分散在动作段落后要求前端自行拼装。

### 5.4 自动动作

出现“自动生成、自动挂号、自动归档、自动迁移、系统自动”等表达时，必须检查：

- 触发条件；
- 成功结果；
- 重复触发的产品结果（Design 已定义时）；
- 失败结果；
- 重试、补偿或人工处理入口；
- 失败后状态和数据保留；
- 用户可见提示、查询或待办入口。

Design 未定义的部分列入待确认，不补造技术实现。

### 5.5 删除传播

出现删除、软删除、停用、撤回、作废或归档时，必须检查：

- 主对象可见性；
- 子对象；
- 关联对象；
- 审批记录和操作日志；
- 附件、历史版本；
- 引用关系；
- 查询、恢复和审计追溯。

未定义的传播关系列入待确认，不擅自写级联删除或自动恢复。

### 5.6 枚举、分页和上限

高影响枚举统一采用三选一：

1. Design 已确认，写具体值；
2. 存在正式初始化清单，明确引用；
3. 尚未确认，列为待确认。

分页、导出上限、批量上限、首页摘要条数和文件限制必须分别表达。一个局部上限不能替代另一个规则。

### 5.7 页面操作逐项承接

Design 明确的查询、重置、返回、取消、关闭、导出、下钻、上传、删除和强动作，凡存在业务结果、状态影响、数据影响、筛选恢复或权限差异，必须在对应页面展开或明确复用唯一完整定义。

- 返回说明筛选是否保留；
- 重置说明重置范围和恢复结果；
- 强动作说明角色、允许状态、成功结果和失败/恢复；
- 同名动作存在页面差异时分别说明；
- 不使用“同上”“按常规处理”“支持相关操作”隐藏差异。

### 5.8 三处交叉比较

PRD 模块写作前必须比较同一高影响事实的：

1. 状态表或状态流转；
2. 页面操作、按钮条件和动作结果；
3. 字段必填、默认值、校验和提交条件。

发现不兼容口径时：

- 记录冲突位置、冲突内容、影响对象和影响模块；
- 停止受影响模块；
- 回到 Design Fix；
- 不采用“页面优先”“状态表优先”“字段表优先”等通用裁决。

### 5.9 生效时点和历史影响

Design 只写“立即生效”“修改后生效”“启用后生效”时，PRD 不得自行推导：

- 仅影响后续对象；
- 历史记录不受影响；
- 当前进行中对象使用旧规则；
- 历史数据重算；
- 自动迁移、补偿或回滚。

这些内容会影响业务结果时，列为高影响待确认。

### 5.10 内部引用和最终重验收

PRD 内部引用必须指向当前 `prd.md` 中真实存在的章节、页面或规则名称。上游引用必须明确写为 `Design §...` 或“Design 的××规则”。

最终顺序固定为：

```text
最后一次写入 prd.md
→ 回读受影响模块
→ 运行现有检查
→ 修复真实问题
→ 如再次写入，重新回读和检查
→ 文件稳定后更新状态
→ 交付前再次直接阅读 prd.md
```

“无法提取”“无法判断”“权限自动分析不可评估”不能写成“零冲突”或“通过”。

### 阶段 4：隔离样本验证

必须至少验证：

1. 简单项目：两个模块、多个页面、共用对象；
2. Design 状态和字段冲突阻断；
3. “立即生效”不得补造历史影响；
4. 自动动作失败和人工入口；
5. 软删除传播；
6. 枚举、分页、导出和批量上限；
7. 状态驱动展示；
8. 页面操作逐项承接；
9. 中断后从最终 PRD 恢复；
10. 审计系统复杂 Design 副本。

### 阶段 5：复杂真实项目回归

使用审计系统项目副本重新生成 PRD，重点抽查：

- 无权限入口；
- 骨架屏和加载失败；
- 超长文本；
- 字段展示条件；
- 页面区块；
- 审计侧/被审侧；
- 自动动作失败；
- 删除传播；
- 枚举和列表上限；
- 状态驱动展示；
- 权限、数据范围和页面操作；
- 内部字段；
- PRD 内部引用；
- 最后一次写入后的重验收。

不得把旧 PRD 当事实源，也不得手工把旧 PRD 遗漏内容补回新 PRD。

## 7. 验收标准

### 7.1 总体通过门槛

必须同时满足：

- 12 项缺陷均有对应规则和验收；
- 0 个未标识的 P0 级产品事实遗漏；
- 0 个高影响未知被静默拍板；
- 无权限、加载中、超长文本和字段展示条件均可回读；
- 自动动作都有失败处理或待确认；
- 删除传播都有规则或待确认；
- 枚举都有具体值、正式清单引用或待确认；
- 状态页面可回读操作、字段、点击、标签和刷新变化；
- 页面操作逐项承接；
- PRD 内部引用可定位；
- 检查后再次修改的 PRD 已重新验收；
- 既有分片、`4.x.6`、中断恢复和事实源边界未被破坏；
- 未修改用户正式项目，未执行 Git commit/push。

### 7.2 分项验收

| 验收编号 | 对应问题 | 通过标准 |
|---|---|---|
| A-01 | 1、6 | Design 已确认的无权限入口语义、骨架屏/加载中、空态、异常、超长截断/悬停全文、默认值和标签色值能在 PRD 找到具体落点。 |
| A-02 | 8、12 | 页面区块、区块目的、字段承载、操作承载和条件显隐可回读；不要求复制全部 Design 标题，但不得无理由压缩。 |
| A-03 | 2 | 待办、提醒、编号、字典、文件和归档逐项判定已定义/局部/未定义/冲突。 |
| A-04 | 3 | 列表分页、导出上限、批量上限、首页条数和文件限制分别有规则或待确认。 |
| A-05 | 4 | 检查结果明确区分产品事实冲突、结构适配差异和人工语义判断。 |
| A-06 | 5 | 审计侧/被审侧、入口、菜单、路由和切换关系可回读。 |
| A-07 | 7 | 完成条件可定位到 PRD 的模块、页面、字段、动作、验收或待确认事项。 |
| A-08 | 9 | 自动动作都有触发、成功、失败、状态保留、重试/补偿/人工入口或待确认。 |
| A-09 | 10 | 高影响枚举不再只有“枚举/字典”无来源描述。 |
| A-10 | 11 | 软删除等生命周期动作的主对象、子对象、关联、审批、附件、历史、引用和恢复均有规则或待确认。 |
| A-11 | 12 | 状态到操作、字段显隐、点击、标签、置灰/隐藏和刷新时机可回读。 |
| A-12 | 全局 | 三处交叉比较、有效引用、最终写入后重验收和权限不可评估语义均正确。 |

### 7.3 失败分级

- P0：高影响事实遗漏或冲突、权限/状态反转、自动动作只有成功路径、状态驱动页面不可实现、Design 未确认事实被拍板；
- P1：页面展示、区块、枚举、删除传播、页面操作或完成条件可回读性不足，但未直接改变核心权限/流程/数据边界；
- P2：不影响产品事实的写法、标题或局部检查提示。

### 7.4 不得作为通过依据

以下内容不能单独证明通过：

- PRD 行数、字数、标题数或表格数；
- Skill 行数或规则条数；
- 脚本退出码 0；
- 生成次数、subagent 数量或运行日志；
- 中间 JSON、回执或上下文包存在；
- 没有运行时报错。

## 10. 停止条件

出现以下情况必须停止并报告：

1. 无法确定 Design 的事实源、模块边界或页面归属；
2. Design 存在状态、权限、必填、默认值或外部责任冲突；
3. 需要修改用户正式项目才能证明 Skill 有效；
4. 需要新增承接矩阵、覆盖率 JSON、综合门禁、回执链或复杂检查器；
5. 规则、模板、Skill 和上下文装载无法形成同一执行路径；
6. 脚本无法区分结构差异和产品事实，且修复会扩大到业务判断；
7. 无法确定正面改写是否削弱原有硬护栏；
8. 最终 PRD 在检查后继续变化，但无法重新回读和验收。

停止时必须说明已完成内容、阻塞原因、影响文件和需要确认的人，不得宣称本轮优化完成。
