# 旧单体 Design 迁移提示词

把下面整段提示词复制到已经手工复制好的旧项目中执行：

~~~text
请把当前项目的旧单体 Design 迁移为多文件 Design。

当前目录就是我已经手工复制好的迁移副本，请直接执行，不再询问我是否确认目录或 Design。

读取 output/design/design.md，把它拆分为以下结构：

output/design/
├── 设计地图.md
├── 设计集清单.json
├── 系统级基线/
├── 跨模块契约/
└── 模块设计/

迁移要求：

1. 只改变内容组织，不改变、补充或优化任何产品事实。
2. 旧 design.md 是本次迁移的唯一事实来源；不得根据 PRD、Prototype、测试环境或常见经验反向补充 Design。
3. 系统目标、范围、角色、全局对象和全局规则放入“系统级基线”；模块之间的交接、状态衔接、数据传递和共同约束放入“跨模块契约”；模块内部流程、页面、字段、操作、状态、规则和异常放入“模块设计”。
4. 未决问题和明确排除项写入拥有该事实的正式 Design 文件，不创建独立目录。
5. 不生成 decision-notes.md、合并视图或其他过程记录文件。
6. `设计集清单.json` 使用 `shitpm-design-set/v1`，只保存文件 ID、相对路径、类型、模块、业务链、依赖、指纹和高影响事项定位，不保存业务正文。
7. 先在临时区域构建全部新文件。旧 design.md 的每一段内容必须有明确结果：迁入新文件、有证据地合并重复内容、有证据地标明废弃，或在对应归属处标记为未决。
8. 完成内容覆盖、事实归属、跨文件引用和设计集清单检查后，再一次性切换到新目录结构。检查未通过时不得切换。
9. 切换完成后，按原相对路径把旧文件分别移到 `.workflow/migration-backup/output/design/design.md`、`.workflow/migration-backup/output/design/decision-notes.md` 和 `.workflow/migration-backup/.workflow/confirmations/design.json`；原项目中不存在的旧文件不创建空备份；不得让旧文件和新文件同时作为事实源，迁移备份也不得进入新事实闭包。
10. 不修改 PRD、Prototype 或其他业务产物正文。若项目已存在 PRD 或 Prototype，只读取其模块标题、路由和源码模块目录，用于建立 `.workflow/provenance/prd.json` 或 `.workflow/provenance/prototype.json`；不得根据下游正文反向补充 Design。无法可靠映射的下游模块标记为 `affected` 并报告。
11. 不执行 git commit，不执行 git push。
12. 最后向我报告：生成了哪些文件、旧内容是否全部覆盖、哪些内容被判定为重复或废弃、哪些下游已建立依据、哪些下游被标记为受影响、还有哪些事项无法判断。

如果拆分过程中发现必须改变产品含义才能继续，停止该部分迁移，保留原文并把具体冲突告诉我，不要自行决定。
~~~
