# Tabler 设计语言 + Ant Design 原型视觉迭代计划与验收方案

> 目的：为其他 AI 提供一份可直接执行的 Prototype 视觉迭代方案。
> 范围：只改 Prototype 的视觉实现、共享 UI、写法规则和 Review 验收；不改变 Design 的业务事实、权限、状态、流程或模块边界。
> 技术方向：Ant Design 6 负责组件行为、可访问性和交互能力；Tabler 负责视觉语言、颜色、间距、表面、图标和页面节奏。
> 中文字体：优先使用思源黑体；未安装时回退系统默认无衬线字体。本轮不把下载或内置字体文件作为阻塞条件。
> 建议执行顺序：按阶段逐个放行，不要一次性修改全部文件。

## 1. 最终目标

完成后，Prototype 应具备以下特征：

1. 生成者只需要读取一套视觉事实源，就能稳定生成 Tabler 风格页面；不再在 `SKILL.md`、`prototype-writing.md`、模板 CSS 和主题文件之间寻找互相冲突的数值。
2. 页面仍然使用 Ant Design 6 的标准组件和行为，不自行重写一套组件库。
3. 高频页面结构由共享 UI 承担，页面代码只表达 Design 规定的业务事实。
4. Tabler 视觉覆盖从“颜色和圆角”扩展到完整状态：默认、悬停、聚焦、激活、禁用、加载、错误、空态、只读、选中、响应式和弹层。
5. 新建或修改原型的效率在基础设施建设后能够回本，并有可复现的效率基线和放行阈值。
6. Review 能够发现“源码可用但视觉语言未落地”的问题，但不新增只产生报告、不改变最终产物的复杂检查链路。

## 2. 当前基线与必须先解决的冲突

执行者先把以下问题当作现状，不要假设现有 Tabler 适配已经完整：

- `references/prototype-visual-spec.md` 已被指定为视觉事实源，但 `references/prototype-writing.md` 仍保留一套独立的 Ant Design 视觉值和 Arco 风格图表规则。
- `templates/prototype-vite/src/theme/tablerTheme.ts` 目前只覆盖 `Layout`、`Card`、`Table`、`Button`、`Select` 五类组件，且未形成可复用的共享 UI 层。
- `templates/prototype-vite/src/styles/global.css` 使用 `calc(100vh - 64px)`，而主题文件将 Header 设置为 56px，存在可见的壳层高度不一致。
- `@tabler/icons-react` 已加入依赖，但模板壳层和占位页面没有形成统一的 Tabler 图标使用方式。
- 图表规则仍出现 `ECharts + Arco 风格主题`，与 Tabler 方向不一致，必须统一。
- 当前规范同时出现“5 类页面骨架”和“7 类页面骨架”，需要明确基础骨架与结果/异常页的关系。
- 当前模板没有本地字体资源；中文应采用“思源黑体优先、系统默认回退”的无阻塞策略。
- 工作区已有大量未提交改动。执行者只能修改本计划明确列出的文件，不得清理、覆盖或格式化无关改动。

## 3. 不做什么

本轮明确不做以下事情：

- 不重建完整 Tabler 组件库，不替换 Ant Design 的组件行为。
- 不为每个页面手写一套 Tabler CSS。
- 不在 Prototype 阶段新增业务字段、状态、权限、流程、跨系统责任或页面。
- 不把视觉验收做成新的“综合门禁”、评分器、机器回执或大规模 AST 检查器。
- 不直接修改 `dist/`、`node_modules/` 或带哈希的构建资源。
- 不为了证明“视觉完整”而引入字体下载、网络 CDN 或第二套构建链。
- 不把现有草稿中的值直接视为官方事实；需要逐项核对后再锁定。

## 4. 目标架构与单一事实源

采用“薄适配层”架构：

```text
Design 事实
    ↓
spm-prototype 生成流程
    ↓
prototype-visual-spec.md（唯一视觉规则）
    ↓
tablerTokens.ts（原始/语义 Token）
    ↓
tablerTheme.ts + global.css + shared/ui
    ↓
业务页面只组合 Ant Design 与共享 UI
```

### 4.1 文件职责

| 文件或目录 | 唯一职责 | 允许出现的内容 |
| --- | --- | --- |
| `references/prototype-visual-spec.md` | 视觉规则唯一事实源 | Token、页面骨架、状态规则、响应式、视觉验收清单 |
| `references/prototype-writing.md` | Ant Design 写法和工程边界 | 组件调用方式、表格/表单/路由/构建规则；不重复定义视觉 Token |
| `skills/spm-prototype/SKILL.md` | 生成流程入口 | 读取哪个文件、何时停止、生成/修改/验证顺序；保持短小 |
| `skills/spm-prototype-review/SKILL.md` | 独立审查流程 | 如何读取视觉规范并输出问题；不修改原型 |
| `contracts/prototype-review-checklist.md` | Prototype Review 检查项映射 | 增加视觉覆盖检查项，不复制完整视觉规则 |
| `templates/prototype-vite/src/theme/tablerTokens.ts` | 可执行 Token | 颜色、尺寸、字体、层级、动效、断点、图表色板 |
| `templates/prototype-vite/src/theme/tablerTheme.ts` | Ant Design 映射 | `ConfigProvider` 的 token 和 component token |
| `templates/prototype-vite/src/styles/global.css` | 全局补丁 | reset、壳层、焦点、sticky 操作栏、无法由 token 覆盖的少量样式 |
| `templates/prototype-vite/src/shared/ui/` | 高频共享 UI | 页面头、工具栏、表格、状态、空态、指标卡、表单分区等 |
| `templates/prototype-vite/src/shared/icons/` | 图标语义映射 | 常用操作和状态的 Tabler 图标映射；不维护完整图标库 |
| `templates/prototype-vite/src/shared/charts/` | 图表视觉适配 | Tabler 图表色板、坐标轴、Tooltip、Legend、响应式默认值 |

所有新值先进入视觉规范和 Token；页面内出现新的颜色、圆角、阴影、字号或间距时，必须说明为什么不能使用已有 Token。

## 5. 分阶段实施计划

### 阶段 0：冻结基线与记录效率

**目标**：在动实现前知道当前效果和效率，避免迭代后只凭感觉判断。

**实施**：

1. 保留当前工作区改动，不做清理。
2. 选择 3 个代表页面作为基线：
   - 简单列表页：查询、表格、分页、行操作、空态；
   - 表单/详情页：分区表单、校验、只读字段、底部操作栏；
   - 复杂聚合页：指标卡、图表、动态列表、不同状态。
3. 对每类页面各执行一次“从任务开始到构建预览可用”和一次“从修改要求到最终验收”的计时。
4. 记录：总耗时、首次可运行耗时、返工轮次、构建失败次数、修改文件数、视觉问题数、最终通过时间。
5. 记录当前模板的截图或浏览器观察结果，至少覆盖 1440px 和 390px 宽度。

**阶段验收**：

- 三类页面都有可复查的基线数据；
- 基线页面能通过现有源码检查和构建流程，或明确记录现有失败；
- 未记录基线前不得用“迭代后更快/更慢”下结论。

### 阶段 1：收敛视觉规范和规则入口

**目标**：消除规范冲突，建立唯一视觉事实源。

**实施**：

1. 逐项核对 Tabler 参考实现中的颜色、文字、边框、页面背景、圆角、间距、尺寸、阴影、字体和图标约束。每一项标记为：
   - `tabler-source`：直接采用 Tabler 参考值；
   - `antd-adapter`：为了映射 Ant Design 必须使用的适配值；
   - `shitpm-business`：ShitPM 为业务可用性做的明确适配值。
2. 在 `references/prototype-visual-spec.md` 中补齐：
   - 颜色角色与状态色；
   - 间距、字号、行高、圆角、边框、阴影；
   - 断点、内容区宽度、壳层高度、密度；
   - 图标、动效、焦点和无障碍对比度；
   - 所有高频组件的状态矩阵；
   - 7 类页面的统一定义：聚合、列表、表单、详情、看板、结果、异常。
3. 修改 `references/prototype-writing.md`：
   - 删除或改写重复的 Ant Design 视觉 Token；
   - 删除 `Arco 风格主题` 和 `ARCO_COLORS` 等冲突规则，改为引用 Tabler 图表适配；
   - 保留 Ant Design 组件 API、工程边界、字段表达、路由、表格硬规则和构建规则。
4. 修改 `skills/spm-prototype/SKILL.md`：只保留流程、停止条件、输入边界和“生成前读取视觉规范”的指针，不把完整视觉细则继续塞进 Skill。
5. 修改 `skills/spm-prototype-review/SKILL.md` 和 `contracts/prototype-review-checklist.md`，加入视觉语言覆盖检查入口；Review 只指出问题，不自动修复。

**阶段验收**：

- 视觉数值只有一个权威来源；
- `prototype-writing.md` 不再与视觉规范定义第二套颜色、图表主题或页面视觉规则；
- `SKILL.md` 能明确指向视觉规范，且正文没有重复长篇 Token；
- 能从规范找到每一类页面、每一类组件状态和响应式要求；
- 找不到合适 Token 时，规则明确要求记录新 Token 的来源和用途，而不是现场拍值。

### 阶段 2：建立 Token 和 Ant Design 主题适配层

**目标**：把视觉规则变成可执行的全局配置，减少页面级 CSS。

**实施**：

1. 新建 `templates/prototype-vite/src/theme/tablerTokens.ts`，分为：
   - `colors`：主色、功能色、文本色、边框色、表面色；
   - `spacing`：4px 基准下的间距阶梯；
   - `typography`：中文字体优先思源黑体，未安装回退系统默认；西文/数字可使用 Inter，未安装不阻塞；
   - `radii`：控件、标签、卡片、弹层和圆形；
   - `layout`：Header、Sider、Content、Card、Table 的尺寸；
   - `elevation`：平面、边框、轻阴影、弹层阴影；
   - `motion`：hover/focus/弹层过渡时长；
   - `breakpoints`：桌面、平板、移动端；
   - `chart`：图表色板和坐标轴基础色。
2. 重写 `tablerTheme.ts`，只做 Token 到 Ant Design 的映射，不在其中堆页面业务判断。
3. 统一 Header 高度。默认按当前 Tabler 目标采用 56px；如果核对参考实现后必须调整，先改 Token，再同步 `Layout`、`global.css` 和壳层，不允许保留 56/64 两套值。
4. 修正 `global.css` 中与 Header 高度、内容区高度、字体顺序、focus ring、页面底色、表格表头和 sticky 操作栏相关的全局规则。
5. 保留 Ant Design 的语义状态机制：`disabled`、`loading`、`status`、`required`、`aria-*`，不要用颜色或解释性文字替代行为表达。

**阶段验收**：

- `npm ci` 和 `npm run build` 通过；
- 模板默认页可运行，壳层没有上下错位、底部空白或纵向跳动；
- 主题中的颜色、字体、圆角、边框、阴影和尺寸都来自 `tablerTokens.ts`；
- 中文字体声明满足“思源黑体优先、系统默认回退”；不要求机器一定安装思源黑体；
- Header 高度和 Content 的计算一致；
- 页面级代码不需要重新声明全局视觉值才能呈现基础风格。

### 阶段 3：实现高频共享 UI

**目标**：把重复视觉和交互集中在共享组件中，降低后续生成和修改成本。

在 `templates/prototype-vite/src/shared/ui/` 中按需实现以下组件。组件只封装稳定的视觉和交互，不承载 Design 业务规则。

| 组件 | 最小职责 | 必须覆盖的状态 |
| --- | --- | --- |
| `TablerPageHeader` | 标题、前缀、返回、轻量页面入口 | 普通、带返回、窄屏换行 |
| `TablerSectionCard` | 统一 Card 表面、标题和区块间距 | 普通、hover、无标题 |
| `TablerMetricCard` | 指标标题、数值、趋势、Tabler 图标徽章 | 正常、上涨、下降、无数据 |
| `TablerToolbar` | 查询区、工具栏、批量操作的布局节奏 | 普通、换行、窄屏堆叠 |
| `TablerDataTable` | 表格密度、表头、空态、分页、操作列 | 加载、空、错误、选中、横向滚动 |
| `TablerStatusTag` | 统一状态语义映射 | 成功、进行中、警告、失败、弱状态 |
| `TablerIconButton` | Tabler 线性图标按钮 | hover、focus、disabled、loading、危险 |
| `TablerFormSection` | 表单分区和字段间距 | 普通、错误、只读、禁用 |
| `TablerEmptyState` | 空数据的说明和主操作 | 空、无权限、失败可重试 |
| `TablerActionBar` | 页面底部 sticky 操作栏 | 普通、提交中、禁用、窄屏 |

组件 API 要求：

- props 命名直接表达行为，不使用业务专属名；
- 默认值来自 Token；
- 允许通过 `className` 或少量 slot 扩展，但不允许让页面重新接管整套视觉；
- 不在组件内部偷偷新增业务字段、状态或权限判断；
- 不为了抽象而封装低频一次性组件。

同时建立：

- `shared/icons/`：常用搜索、刷新、查看、编辑、删除、返回、保存、确认、警告、错误等语义图标映射；
- `shared/charts/`：Tabler 图表色板、网格、坐标轴、Tooltip、Legend 和 resize 处理；
- 图标统一使用 `@tabler/icons-react`，不混用 `@ant-design/icons`；无法找到精确图标时选择语义接近的官方 Tabler 图标并记录，不臆造名称。

**阶段验收**：

- 上述高频组件至少能被模板占位页面或样例页面真实调用；
- 共享组件不依赖具体业务模块；
- 每个组件都能表达至少一个异常或非默认状态；
- 页面业务代码不再重复实现同样的页头、状态标签、表格工具栏、空态和底部操作栏；
- 组件在 1440px、768px、390px 下不产生不可接受的溢出或文字遮挡。

### 阶段 4：统一壳层、页面骨架和全状态视觉

**目标**：让不同页面看起来属于同一个 Tabler 产品，而不是只共享一组颜色。

**实施**：

1. 壳层：
   - 深色 Sider、白色 Header、浅色 Content；
   - Sider 独立滚动，菜单激活态明确；
   - Header 只承载 Breadcrumb、角色/用户区等壳层内容；
   - 内容区统一边距和最大宽度策略；
   - 移动端折叠 Sider，不能让桌面导航横向挤压业务内容。
2. 页面骨架：
   - 聚合页：页头 → 指标卡 → 图表/动态 → 待办或列表；
   - 列表页：页头 → 查询区 → 工具栏 → 表格 → 分页；
   - 表单页：页头 → 分区 Card → 校验/反馈 → sticky 操作栏；
   - 详情页：返回/页头 → Descriptions → 关联明细；
   - 看板页：筛选/工具栏 → 列容器 → 条目卡片；
   - 结果页和异常页：居中内容卡 → Result → 恢复操作。
3. 状态矩阵逐页落实：
   - 默认：表面、边框、层级；
   - hover：行、卡片、按钮和图标按钮；
   - focus-visible：键盘可见焦点 ring；
   - active/selected：导航、Tabs、Table row、Select option；
   - disabled/readonly：使用 Ant Design 行为和视觉，不靠“只读”文字解释；
   - loading：Skeleton、Spin、Button loading 或 Table loading；
   - empty：Table 内置空态或统一 EmptyState；
   - error/forbidden：可观察错误和恢复/返回动作；
   - responsive：窄屏堆叠、表格横向滚动、操作不被拆字。
4. 表格、表单、弹层、分页、Tag、Alert、Result、Tabs、Drawer、Modal、Descriptions 等 Ant Design 组件统一通过主题和共享包装呈现 Tabler 观感。
5. 图表改为 Tabler 适配：不再使用 Arco 的颜色、文字色和主题命名。

**阶段验收**：

- 7 类页面骨架定义无互相冲突；
- 每类页面至少有一个可复用示例结构；
- 全部高频组件状态都能在模板或样例中观察到；
- 1440px 下有完整桌面层级，768px 下布局可用，390px 下不出现横向页面溢出；
- 页面中没有“入口：”“去向：”“（只读）”“（必填）”等解释性标注代替真实 UI 状态；
- 业务页面只组合组件，不复制一套局部 Tabler 规则。

### 阶段 5：同步生成 Skill、写法和 Review 链路

**目标**：让后续 AI 真正按新规范工作，而不是模板改了、生成规则仍旧指向旧写法。

**实施**：

1. `spm-prototype`：
   - 生成/修改前读取视觉规范；
   - 先选页面骨架，再选共享 UI，再填 Design 字段；
   - 只在共享 UI 或 Token 层解决重复视觉；
   - 生成后按视觉自检清单自修，不单独生成“检查报告”作为完成证明。
2. `prototype-writing`：
   - 保留 Ant Design API 和工程约束；
   - 改为引用视觉规范中的 Token 和页面骨架；
   - 删除过时 Arco 图表规则和重复视觉数值。
3. `spm-prototype-review`：
   - 增加“视觉事实源是否被读取”“页面是否使用共享 UI”“是否存在局部硬编码风格”“状态矩阵是否可观察”等检查；
   - Review 仍保持只读，只输出问题、严重度、位置、影响和建议。
4. `prototype-review-checklist.md`：
   - 增加视觉覆盖项；
   - 不复制 Token 全文；
   - 不把视觉检查改造成新的机器门禁。

**阶段验收**：

- 新 AI 只根据 `spm-prototype` 的指针就能找到正确视觉规范；
- 从所有活动规则中搜索不到 Arco 作为当前图表视觉基线；
- 视觉问题、业务语义问题和源码结构问题仍能分开归类；
- Review 不修改原型、不自动推进阶段。

### 阶段 6：三类真实页面试点与效率回归

**目标**：验证薄适配层是否真的提高后续生成和修改效率。

**实施**：

1. 使用阶段 0 的三类页面，分别完成：
   - 一次从 Design 生成；
   - 一次视觉修改；
   - 一次包含状态/响应式要求的修改。
2. 使用与阶段 0 尽量相同的提示词和 Design 输入，记录同一组指标。
3. 重点比较“最终通过时间”，不要只比较首次生成时间。
4. 记录返工原因：规则冲突、组件缺失、页面级 CSS、业务事实问题、构建问题、视觉验收漏项。
5. 如果发现效率下降，优先删减规则和抽象，不要通过降低视觉验收标准来制造提速。

**效率放行阈值**：

| 时点 | 可接受结果 | 处理方式 |
| --- | --- | --- |
| 基础设施完成后 | 一次性投入允许达到当前单页等效工作量的 1.5–3 倍，但不得超过 3 个简单页面等效工作量 | 超过则停止扩张组件范围，先收敛 Token 和共享组件 |
| 三页试点完成后 | 三页总交付时间不超过原基线 +30%；构建失败和白屏不得增加 | 超过则回退低频组件、精简文档和生成步骤 |
| 累计约 5 个页面等效工作量后 | 后续页面的中位最终通过时间不高于原基线 | 未回本时暂停新增视觉范围，修复重复劳动根因 |
| 累计约 10 个页面等效工作量后 | 简单 CRUD 页面目标为原基线的 85% 或更低；纯视觉修改目标为 75%–85%；复杂页面不得超过原基线 +10% | 达标后才扩大到更多低频组件 |

以下情况不能算效率提升：跳过 Design 读取、减少状态表达、只验证默认页、交付未构建的页面、把视觉问题留给用户、或用更少文件换来更多页面级重复代码。

**阶段验收**：

- 三类页面都有前后对比数据；
- 最终通过时间没有因“首次生成变快”而被掩盖；
- 返工轮次、构建失败次数和修改文件数至少有一项明显下降，且没有牺牲语义/状态覆盖；
- 未达到阈值时有明确的删减或回滚动作，不得直接宣布成功。

### 阶段 7：全量交付与回归

**目标**：确保新规范进入后续真实原型生成链路，不留下半迁移状态。

**实施**：

1. 对模板执行 `npm ci`、`npm run build`。
2. 运行现有 `prototype-source-check.py` 和 `prototype-consistency-check.py`。
3. 使用开发预览和构建预览分别打开默认页及全部注册路由。
4. 检查浏览器 console，不允许出现运行时错误。
5. 对代表性页面进行视觉检查：1440、1280、1024、768、390 宽度。
6. 逐项检查视觉状态：默认、hover、focus、active、disabled、loading、empty、error、forbidden、readonly、selected。
7. 检查字体：中文优先思源黑体，未安装时系统默认仍可正常显示；不出现因字体缺失造成的布局崩坏。
8. 检查图标：共享 UI 和模板业务代码使用 Tabler 图标，不混入 Ant Icons。
9. 检查当前工作区差异，只确认计划内文件被修改；不处理原有无关改动。

## 6. 最终验收矩阵

### A. 规范一致性

- [ ] 视觉 Token 只有一个权威文件。
- [ ] 所有颜色、间距、圆角、字体、阴影和尺寸都有来源分类。
- [ ] 没有两套 Header 高度、页面背景、边框色或图表主题。
- [ ] `prototype-writing.md` 不再复制视觉规范正文。
- [ ] `SKILL.md` 保持流程化、短小，并正确指向视觉规范。

### B. Tabler 视觉覆盖

- [ ] 壳层、页面头、卡片、表格、表单、弹层、Tag、按钮、分页、Tabs、Drawer、Modal、Descriptions、Result 和异常页具有一致的表面语言。
- [ ] 主色、状态色和中性色的用途稳定；功能色不作为装饰。
- [ ] 间距、圆角、边框和阴影形成稳定阶梯，不出现页面临时拍值。
- [ ] 默认、hover、focus-visible、active、disabled、loading、error、empty、readonly、selected 状态可观察。
- [ ] 图标统一 Tabler 线性图标，尺寸和文字间距一致。
- [ ] 动效克制，不能造成页面跳动或影响原型讨论。

### C. 中文与响应式

- [ ] 中文字体栈以思源黑体为优先，系统默认无衬线为可靠回退。
- [ ] 不依赖外部 CDN 或必须下载字体才能构建。
- [ ] 1440px 桌面布局完整。
- [ ] 1024px/768px 布局可操作，侧栏、工具栏和表单能合理收缩。
- [ ] 390px 下无页面级横向溢出；表格允许局部横向滚动，操作不被拆字。

### D. 工程和业务安全

- [ ] `src/` 是唯一编辑源，未直接修改 `dist/`。
- [ ] `npm ci`、`npm run build` 通过。
- [ ] 默认页和所有注册路由在开发预览、构建预览中均能打开。
- [ ] console 无错误，无白屏，无错误路由。
- [ ] Design 字段、状态、权限、操作限制和异常路径没有因视觉重构而改变。
- [ ] 视觉问题与语义问题分开；发现 Design 问题时停止并回上游，不在 Prototype 静默拍板。

### E. 效率和可维护性

- [ ] 三类真实页面完成前后效率对比。
- [ ] 试点总耗时不超过基线 +30%，或有明确的删减/回滚记录。
- [ ] 后续简单页面不再重复实现页头、工具栏、表格状态、空态和操作栏。
- [ ] 页面级视觉硬编码显著减少。
- [ ] 新增共享组件有真实消费者，不存在只为“看起来完整”而创建的低频抽象。
- [ ] 没有新增只生成报告、不修正最终产物的检查器。

## 7. 执行停止条件与回滚边界

任何一个条件成立时，停止当前阶段并先修复：

- 视觉规范仍存在互相冲突的数值或图表主题；
- 共享组件开始承载业务事实或权限判断；
- 模板构建失败、默认页/任一路由白屏或 console 报错；
- 为完成视觉效果需要直接修改 `dist/`；
- 发现 Design 事实缺失、冲突或待确认项被静默拍板；
- 三页试点效率超过基线 +30%，且无法通过删减低频范围修复；
- 为通过视觉检查而减少状态、权限或异常表达。

回滚原则：

1. 只回滚当前阶段引入的文件，不使用破坏性 Git 操作覆盖用户已有改动。
2. 优先回退低频共享组件和非必要文档扩展，保留已经验证有效的 Token、主题和基础组件。
3. 如果视觉范围需要继续扩大，先补充真实页面证据，再决定是否新增组件或检查工具。
4. 未通过最终验收前，不要把“模板已改”描述为“Prototype 视觉体系已完成”。

## 8. 建议交付顺序

其他 AI 执行时按以下顺序提交中间结果，每个阶段先验收再进入下一阶段：

1. 阶段 0：基线记录和现状问题表；
2. 阶段 1：规范冲突清单和文档收敛；
3. 阶段 2：Token、主题和全局样式；
4. 阶段 3：共享 UI、图标映射和图表适配；
5. 阶段 4：模板壳层、页面骨架和状态覆盖；
6. 阶段 5：Skill、写法和 Review 同步；
7. 阶段 6：三类真实页面试点与效率评估；
8. 阶段 7：全量工程、路由、响应式和最终验收。

阶段 6 未达到效率阈值时，不得进入阶段 7 的全面扩展；应先缩小范围，确保“视觉更完整”没有变成“每次原型都更慢”。
