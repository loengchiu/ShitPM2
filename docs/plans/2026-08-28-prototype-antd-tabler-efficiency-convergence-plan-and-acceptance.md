# Prototype 默认 Ant Design + Tabler 视觉收敛改造计划、执行与验收文档

> 日期：2026-08-28
> 状态：计划已形成，等待用户确认后实施
> 边界：本文件同时承担改造计划、执行顺序、实验方案和最终验收标准。写完后不自动修改 Skill、模板或真实项目。

## 1. 结论先行

当前效率变差的主要原因不是 Ant Design 运行时套 Tabler 皮肤本身，而是生成流程把视觉系统暴露成了每次任务都要重新决策的一组问题：选择主题、判断页面骨架、读取多份视觉规则、判断 Tabler 组件、处理品牌命名，再叠加共享 UI 和状态验收。

本次采用收敛方案：

- Ant Design 继续作为唯一行为和组件底座；
- Tabler 作为唯一默认视觉基线，由模板 Token、主题和全局样式自动注入；
- Prototype 生成时删除 Claude、traework 和其他主题选择，不再让页面决定皮肤；
- 页面优先使用品牌无关的 `shared/ui` 语义入口，页面代码只表达 Design 中的业务事实；
- 视觉规范降为模板基础设施和特殊场景参考，普通页面不再重复拼接完整视觉规则；
- Claude 移出正式 Prototype 生成机制；
- 通过同一便宜模型的真实 A/B/C 实验验证生成效率，不能用构建耗时或手工样例代替。

目标不是把 Ant Design 改造成完整的 Tabler 组件库，而是让生成模型只需选择业务结构，默认得到 Tabler 观感。

## 2. 背景、历史方案与根因

历史迭代已经建立了 Ant Design + Tabler 的基础设施，包括 `tablerTokens.ts`、`tablerTheme.ts`、全局 CSS、模板壳层和部分共享 UI。2026-08-18 的计划又尝试把共享 UI 和行为规则改为按需加载。

但原有方案没有真正切断以下成本：每次生成前选择主题；在视觉规范、写法规范、组件行为和模板实现之间寻找重复信息；按品牌命名理解共享组件；在页面代码中判断哪些视觉规则应该由页面实现；保留 Claude/traework 等额外分支。

已确认事实：模板运行时已经默认使用 Tabler，`main.jsx` 通过 `ConfigProvider` 注入 Tabler 主题，CSS 也使用 Tabler 变量。因此运行时套皮肤不是主要瓶颈。当前最可信的根因是视觉系统没有充分下沉为默认基础设施，模型在每个页面重复承担视觉决策和规则拼接。这个判断必须由真实模型实验验证，不能仅凭源码长度或 build 时间成立。

上一轮实验中的 A/C 页面是手工写入的，build 时间只是编译时间，所以只能作为初步结构性证据，不能作为模型生成提效结论。

## 3. 目标、非目标与成功标准

### 3.1 目标

- 普通 Prototype 页面不再选择主题，默认即为 Tabler；
- Claude 不再参与正式 Prototype 生成路径；
- 高频结构有品牌无关的语义入口：`PageHeader`、`SectionCard`、`Toolbar`、`DataTable`、`StatusTag`、`IconButton`、`RowActions`、`FormSection`、`EmptyState`、`ActionBar`；
- 普通任务走短规则路径，复杂表格、Modal、Portal、sticky、响应式等场景仍按触发条件加载完整行为契约；
- 业务事实、权限、状态、流程、异常路径和真实浏览器验收标准不降低；
- 用审计知识库真实任务验证生成、修改和最终验收效率。

### 3.2 非目标

- 不重建脱离 Ant Design 的组件库；
- 不修改审计系统 Design、PRD 或业务事实；
- 不全面迁移已有真实 Prototype；
- 不第一步全面重命名或删除所有 `Tabler*` 内部实现；
- 不新增统一检查器、评分器、检查 JSON、回执文件或只证明步骤执行过的复杂链路；
- 不通过减少 Design 读取、状态表达或视觉验收换速度；
- 不执行 commit 或 push，除非用户另行明确授权。

成功标准：普通页面生成路径明显变短，同时 C 方案业务、交互和视觉质量不低于当前 Tabler 基线；只变快但返工更多，视为失败。

## 4. 目标架构与职责边界

```text
已确认 Design 业务事实
        ↓
页面业务代码（字段、状态、权限、操作、流程）
        ↓
品牌无关的 shared/ui 语义组件
        ↓
Ant Design 行为组件 + Tabler Token/CSS
```

| 层 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| Design | 页面、字段、状态、权限、流程和范围事实 | 视觉拍板和源码细节 |
| 页面代码 | 组合业务结构并表达 Design 事实 | 重复实现全局视觉和共享交互 |
| `shared/ui` | 高频结构的稳定视觉、布局和通用行为 | 业务字段、权限、接口和状态机 |
| Ant Design | 表单、表格、弹层、选择器等行为和可访问性 | Tabler 品牌规则 |
| Tabler Token/CSS | 颜色、字体、圆角、边距、阴影、密度和状态视觉 | 业务判断 |
| Skill/Reference | 事实读取、规则入口和例外触发条件 | 第二套视觉数值 |

`Tabler*` 可以先作为内部实现保留，以降低迁移风险；先增加品牌无关别名并让页面使用别名，真实消费者迁移完成后再评估清理旧命名。

## 6. 目标生成路径

当前路径：

```text
Design → 选择主题 → 读取视觉规范 → 选择页面骨架
      → 查 shared/ui → 组合 AntD/Tabler → 逐页视觉判断 → 返工
```

目标普通路径：

```text
Design → Skill 和必要行为规则 → 查 shared/ui 真实导出
      → 组合业务页面 → 构建 → 必要的真实浏览器验收
```

目标例外路径：普通路径命中复杂表格、Modal、Portal、sticky 或响应式例外时，读取 behavior 对应章节和特殊视觉规则，再实施、构建和做真实交互验收。例外路径不能被提效要求删除。

## 7. 分阶段执行计划

### 阶段 0：真实效率基线

在改实现前，用同一便宜模型、同一环境和同一 Design 输入，测试简单 CRUD 列表、表单/详情、指标或图表聚合三类任务。每类记录首次可运行和最终验收两组时间。

记录：总耗时、首次可运行、最终通过、生成轮次、返工轮次、构建失败、运行时错误、视觉问题、业务事实遗漏、修改文件数和输入上下文体量。原始任务和结果只作为实验材料，不生成新的长期回执体系。

### 阶段 1：收敛规则入口

删除 `spm-prototype` 的主题选择和多主题分支，默认指向 Tabler；把基础视觉和普通页面骨架下沉到模板；清理 Claude、traework、Arco 等过时正式路径引用；保留 Design 唯一事实源、停止条件、构建、路由、console、真实交互和响应式验收。

### 阶段 2：建立语义 shared/ui 入口

为已有稳定实现增加品牌无关别名，页面生成前先查真实导出和实现。能承接时直接复用，不能承接时才组合 Ant Design 原生组件或新增薄适配。共享组件不得承载业务字段、权限、接口、流程或状态机。

### 阶段 3：清理主题分支和规则重复

检查 `claudeTheme.ts` 及其引用。无真实消费者时，Claude 只从正式生成机制退出；物理删除与否由引用和历史兼容决定。同步将 references、Skill 和 Review 改为唯一来源加触发指针，不做无必要的大规模历史迁移。

### 阶段 4：真实 A/B/C 模型实验

使用同一个便宜模型、同一输入、同一页面任务比较：

| 组别 | 配置 | 目的 |
| --- | --- | --- |
| A | 裸 Ant Design 短路径 | 低规则成本基线 |
| B | 当前完整方案 | 复现当前效率问题 |
| C | 收敛后的默认 Tabler 方案 | 验证目标方案 |

三类页面各完成一次生成、一次视觉修改和一次状态/响应式修改。必须记录真实模型生成和返工；build 时间只能作为工程指标。重点比较最终通过时间。

### 阶段 5：审计知识库真实回归

以 `D:/work/交投软件中心/审计系统/output/design/模块设计/审计知识库.md` 为业务事实输入，选择列表、详情/编辑和检索/状态场景盲测。不得预先把历史缺陷、评分或生成理由喂给模型。检查字段、权限、状态、操作、空态、错误态、只读、加载、响应式和最终返工。

### 阶段 6：放行或收缩

若 C 未达标，优先删除低频抽象、重复规则和页面级选择，不降低业务或视觉验收。若仅复杂页面变慢，保留普通页面短路径并重新划分例外触发条件。Claude 若造成真实需求无法表达，另提可选扩展，不恢复默认主题分支。

## 8. 验收方案

### 8.1 规则与源码

- 普通任务不再选择主题，默认主题只有 Tabler；
- 普通任务不再无条件完整读取 behavior，复杂场景有明确触发条件；
- shared/ui 有语义入口，页面不复制其 DOM、CSS 和默认行为；
- writing 不再维护第二套视觉 Token、Arco 图表主题或过时主题选择；
- Review 仍覆盖视觉、状态、权限、响应式和真实交互；
- Design 仍是业务事实唯一来源，高影响未知不得由 Prototype 静默补全。

### 8.2 工程与浏览器

适用时执行：

```powershell
python scripts/python/test-resource-integrity.py
python scripts/python/test-shitpm-regression.py
Push-Location 'templates/prototype-vite'
npm run build
Pop-Location
git -c core.whitespace=cr-at-eol diff --check
```

修改运行时代码后，必须检查默认页、全部注册路由、实际存在的表单/表格/选择器/弹层/Portal/行操作、console、键盘焦点和 1440px/768px 响应式；本轮不执行 390px 专项测试。不能用静态搜索或 build 替代真实交互。仅修改 Skill、reference 或 checklist 时，不把模板 build 宣称为本轮证据。

### 8.3 效率放行阈值

| 指标 | 放行要求 |
| --- | --- |
| C 视觉质量 | 不低于当前 Tabler 基线 |
| C 业务/交互缺陷 | 不高于 B，不能漏掉 Design 高影响事实 |
| C 首次可运行 | 不高于 B，且应接近 A |
| C 最终通过时间 | 不超过 A 基线 +30%；普通 CRUD 逐步接近 A |
| 工程运行时 | 构建失败、白屏、console 错误不得增加 |
| 返工 | 规则冲突、重复视觉实现和共享组件误用应减少 |

以下不能算提效：跳过 Design 读取、减少状态表达、只测默认页、只比较 build 时间、把视觉问题留给用户，或用更少文件换来更多页面级重复代码。

### 8.4 最终清单

- [ ] 默认 Tabler 成为唯一正式 Prototype 视觉路径。
- [ ] Claude 已从正式生成机制退出，并有引用检查证据。
- [ ] 普通页面可通过语义 shared/ui 入口生成。
- [ ] 视觉值由 Token/主题/CSS 承担，页面不重复拍值。
- [ ] 普通路径和例外路径的读取条件清楚。
- [ ] Design、权限、状态、流程、异常和浏览器验收没有被弱化。
- [ ] A/B/C 使用同一便宜模型、同一输入和真实生成过程。
- [ ] 三类任务有前后数据，最终通过时间没有被首次生成时间掩盖。
- [ ] 审计知识库真实回归完成，或明确记录未验证原因。
- [ ] 适用工程、路由、浏览器和响应式检查通过。
- [ ] 未验证、失败、延期和需确认项均已记录。
- [ ] 未执行 commit/push，用户既有改动均被保留。

## 9. 风险、停止条件与回滚边界

出现以下任一情况，停止当前阶段：C 上下文更短但返工更多或最终时间超过阈值；为提效删除 Design/状态/权限/浏览器验收；shared/ui 承载业务判断；主题清理造成真实消费者断裂；默认页、路由、Portal、console 或响应式回归；发现高影响 Design 未知却需要自行补全；为证明提效新增报告、回执或评分工具。

回滚只针对本阶段新增修改，保留用户已有改动，不使用 `git reset --hard` 或 `git checkout --`。若收敛失败，优先保留已验证的 Tabler Token、主题和共享 UI，回退低频抽象和规则入口，不恢复多主题默认分支。

## 10. 文档后的执行规则

本文件写入完成后进入“等待确认”状态。用户确认后才按阶段 0 开始执行；确认前不修改 `skills/`、`references/`、`templates/`、真实审计系统或其他实现文件。执行中每阶段报告已完成、已验证和待处理内容；未通过效率阈值不得宣布改造成功。

本次共同判断：Ant Design 与 Tabler 可以长期共存，真正需要避免的是把视觉选择暴露给每次生成任务。Tabler 应是模板默认能力，页面只表达业务，效率是否恢复由真实模型生成实验决定。
