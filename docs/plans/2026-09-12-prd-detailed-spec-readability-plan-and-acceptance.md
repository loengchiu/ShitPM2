## 1. 文档定位

本文是 PRD 写作契约改造的执行与核验依据。文档记录决策基线、实测证据、执行阶段、失败停止条件、最终完成定义与交付格式。

本轮改造对象是 ShitPM 自身的 PRD 契约（Skill / 规范 / 示例 / 模板 / profile / lint / 一致性脚本 / Review 清单），**不是真实项目的业务事实**。真实项目只用于产生重写样本与验收对照（见 §7 阶段 3），任何真实项目文件修改前必须先做带时间戳的整目录备份。

## 2. 背景与已发现问题

### 2.1 用户提出的三个问题与一个人性化判据

PM 在真实项目产出上发现：

1. `4.x.6` 的表达 AI 味十足，人类难读懂；

### 2.3 四条根因（全部有复现路径）

**A. lint 的封闭词表可以被整份绕过，这是设计层面必然失效。**
`scripts/python/prd-style-lint.py:62-72` 从 `contracts/prd-writing.profile.json` 的 `forbidden_expressions` 生成标签正则，生成形态固定为 `\*\*<词>[：:]\*\*`，即要求**冒号在加粗之内**；同时词本身必须命中封闭词表。实测三重验证：

| 输入 | 现有正则是否命中 |
|---|---|
| `**页面目标：** 这是正文`（词在表中 + 冒号在内） | 命中 |
| `- **页面目标**：这是正文`（词在表中 + 冒号在外） | **不命中** |
| `- **默认排序**：按账期倒序。`（词不在表中） | **不命中** |

后果：把旧版标签体 PRD（145 行 `- **X**：`）直接喂给 lint → **0 error、1 warning、exit 0**。

**B. 规范要求三种表达，真实产出只用一种。**
`prd-writing-rules.md §1` 定义了自然段 / 数字编号 / `·` 并列三种表达，但没有规定「什么时候必须转列表」。实测结果：规范自己的优秀样本 6 页里有 5 页用了 `·` 列表（共 17 项），真实 PRD 5 页全部为 0 项。**段长膨胀（avg 143 vs 125、max 504 vs 215）是这件事的下游结果，不是独立的病灶。**

**C. 流程/状态/权限的表达没有强制信息槽，全靠 AI 每次重新发明结构。**
`prd-writing-rules.md §5` 只写了「按复杂度写」，未给出槽位清单与逐槽判断要求；§3/§4 是事实域清单，不是落点结构。因此同一份 PRD 里有的动作写了角色×状态，有的只写了一句业务结果。

**D. 权限维度在机器上完全不存在。**
`scripts/python/prd-consistency-check.py` 实测（`--module 租金清分`）：`prd_permission_pages_count: 0`、`prd_roles_count: 0`、`permissions.not_evaluated: true`、`exit_reason: needs_semantic_judgment`、**exit 0**。权限写全与写漏，脚本输出完全一样。复现原因是三处硬编码限制：

1. `:727 extract_prd_permission_pages` 候选章节只有 `权限汇总 / 权限定义 / 权限规则`，不含模块级 `4.x.3 角色与权限`；
2. `:844 / :929` 用 `re.match(r'^#{1,2}\s+')` 判断进出权限章节 —— 而 `#### 4.1.3` 是四级标题，**永远进不去**；
3. `:811 _extract_perm_pairs_from_table` 要求表头首列含 `模块 / 操作对象 / 页面 / 对象`，且「单元格非空即视为该 pair 存在」——写入「否」会被当成有权限。

补充：`.workflow/reviews/` 中该项目从未跑过 PRD Review（只有 16 份 design-review、2 份 prototype-review）—— 说明 C、D 两类问题缺少任何人把关。

### 2.4 两个外部「去 AI 味」方案的当前迁移结论

**kill-ai-slop**：核心定义是「slop = 决定的缺席，而非用了某个词」，机器只捞候选、是否 slop 由人判，护栏明确写着「扫描通过 ≠ 页面变好」。**可迁移：形态层清单，以及「机器捞候选 + 人判是否 slop」这条边界。**

**human-writing**：其实测变更记录的精神是「1.0 用字符串禁令拦 AI 味，模型会换一套字面继续做同样的事；读者认的是姿势不是字」—— 这正是 A 根因的标准诊断书。**可迁移：动作级禁令方法论、三层检查、脚本不得自行增加未写明的硬禁词。不可迁移：节律/修辞层。**

节律层在 PRD 题材上的失效证据（双向跑过，本轮不主动引入；其他 AI 如有新证据，可在复核时指出）：

| 指标 | 真实 PRD 4.1.6 | 规范优秀样本 | 判据方向是否成立 |
|---|---|---|---|
| 句长变异系数 CV | 0.549 | 0.420 | 该技能认为 CV 小 = 机器味，这里**反向** |
| 「的」字密度 | 1.26% | 0.69% | 但 `prd-writing-rules.md` 自身也是 1.22% → 不能当阈值 |
| 段首 6 字重复 | 服务中心财务 ×9 / 服务区管理员 ×5 | 服务区管理员 ×5 | 同题材无法区分 |

原因：该技能治的是**文学性中文**的 AI 味（修辞动作贫乏）；PRD 的 AI 味是**信息架构贫乏**（事实无层级、没有未做决策、靠堆砌凑篇幅）。前者管「怎么写」，后者管「怎么组织」。

## 3. 本轮共同确认的治理方案

> 本节根据 PM 与本次讨论逐项确认的结果修订。它记录的是待其他 AI 复核的方案基线，不代表已经开始执行。

### 3.1 交付目标不变

4.x.6 仍是研发和测试的唯一自包含交付单元。读者只看该章节，就应能确定产品行为，不需要打开 Design、Prototype 或旧 PRD，也不需要向 PM 补问普通细节。可读性优化不能用“回去查 Design”来交换。

### 3.2 本轮治理解决什么问题

本轮同时处理三类问题：

1. **一次读懂**：研发和测试能够直接提取角色、条件、对象、动作、校验、结果、状态变化和失败恢复。
2. **表达稳定**：同一份 PRD 中，不同页面和不同动作的详细程度不再主要依赖模型临场发挥。
3. **自然可读**：保留业务事实密度，减少汇报腔、口号、抽象名词堆叠、长句堆步骤和没有新增信息的重复。

本轮不把“AI 味”缩减为词语问题。重点检查信息是否按动作和因果组织，读者是否需要自行补主语、拆步骤或猜状态。

### 3.3 4.x.6 的组织方式

4.x.6 采用以下稳定骨架：

- 业务阶段；
- 页面名称；
- 页面引入段；
- 独占一行的动作名称；
- 动作正文。

页面引入段和动作标题提供稳定落点，但动作正文不强制拆成固定小标题。正文按照业务复杂度承担适用的信息责任，避免所有页面都长成同一种模板。动作名称采用独占一行的无冒号粗体短语（现有 `**动作名称**` 形式）；它是标题，不是“字段名：内容”标签，lint 不得仅因动作名称使用粗体而报错。

### 3.4 页面引入段

页面引入段必须交代四项内容，但不规定固定句数、字数或列表格式：

1. 谁在什么前提下进入页面；
2. 进入页面要完成什么判断或任务；
3. 结果交给谁，或进入什么后续状态；
4. 页面与上游、下游页面如何衔接。

引入段不提前陈列页面全部字段和规则，也不加入“核心支撑、重要节点、形成闭环”等评价性句子。

### 3.5 动作正文的责任

三档复杂度用于生成和 Review 时判断需要覆盖的内容，不转写成固定的正文标签。

| 动作复杂度 | 适用动作 | 至少判断的内容 |
|---|---|---|
| 简单 | 查询、查看、返回、打开详情 | 操作角色、可用条件、页面或数据结果 |
| 普通 | 新增、编辑、保存、提交、修改 | 前置条件、输入与校验、系统处理、成功结果、失败保留或恢复 |
| 复杂 | 多角色、多状态、多分支、破坏性操作、外部协作 | 角色与状态、关键分支、状态变化、失败恢复、下一步衔接 |

槽位不是固定标题。某项不适用时可以不写，但生成和 Review 必须明确判断过，不能因为模型遗漏而静默缺失。简单动作不得为了填槽位扩写成复杂动作。

**责任到位不等于落点到位**（§2.5 N1）。审计样本的动作正文逐条核对责任清单几乎不缺，但被压成 544 字单段，研发仍需读第二遍。因此补充一条约束：

- 一个块（自然段或 `·` 列表项）只承载一层事实；出现「区域 → 字段清单 → 权限分支 → 版本节点 → 例外提示」这类多层堆叠时，必须拆成多个块或子列表，不得压成一个块；
- 拆分方式不限：多段、子列表、短矩阵均可，只要读者能一次定位到某一层；
- 这条约束的机械判据放在 §3.10（块长形态退化），语义判断仍由 Review 与 PM 负责。

### 3.6 自包含与重复

4.x.6 保持自包含。同一事实可以在状态规则、功能详细说明和字段定义中重复出现，但每次出现必须增加新的使用上下文，例如角色、状态、条件、对象、输入、校验、计算、结果、异常、恢复方式、展示方式或上下游关系。

第二处只换词重述第一处，未增加新的使用信息，属于原地重述。Review 只处理这类无效重复，不要求删除为了让研发独立阅读所需的有效重复。

本轮真实验收只在新写的 4.1.6 内部判断重复是否增加信息，不跨新 4.1.6 与保留的旧 4.1.5、4.1.7 做重复扣分。阶段 3 必须记录新旧文体交界处的处理说明，解释哪些旧章节保留、为什么不在本轮重写，以及研发如何只读 4.1.6 完成开发。

### 3.7 权限表达

每个业务模块的角色与权限章节提供“角色 × 业务能力”矩阵：

- 行是角色；
- 列是业务能力；
- 单元格写“可、否或条件”；
- 复杂条件在表下注释中展开；
- 能力按业务动作组织，不按按钮或图标组织。

矩阵用于表达模块级权限边界。4.x.6 仍然按动作写清具体状态、组织范围、数据范围、例外条件和退回后的处理。

对 PRD 的章节扫描只认模块内编号为 4.x.3 的角色与权限章节及其子级内容，不把 3.x.3 的角色权限表并入当前模块对照；章节定位优先使用编号，不用“权限”等泛关键词把不同层级的表合并。Design 侧沿现有 Design 权限元数据提取，不要求本轮强行把 Design 标题改成 4.x.3。

权限比较必须以双侧都成功提取为前提。只有 Design 侧和 PRD 侧都提取到可比权限事实时，才计算 missing、hallucinated 和 polarity/inversion；任一侧为空，都标记权限维度未评估，不得把 PRD 单侧提取结果与 Design 的空集合直接比较。

本轮优先只在 prd-consistency-check.py 修复双侧判定和 4.x.3 定位，不修改真实项目 Design 或 Design 侧解析脚本。若现有提取入口无法通过最小改动表达这两个边界，停止并回到 PM 讨论，不得用关闭检查或改写业务事实绕过。

**必须同时修复表头方向（`prd-consistency-check.py:811`）**：现有判定要求权限表表头首列含「模块 / 操作对象 / 页面 / 对象」，即「行=对象、列=角色」方向；而 §3.7 规定的矩阵是**行=角色、列=业务能力**。两侧方向相反，若只修章节定位和双侧判定、不动表头方向，按 §3.7 写出的合规矩阵在 PRD 侧照样提取为 0，于是双侧恒 0 → 权限维度永远 `not_evaluated`，§4.1 目标 7「权限矩阵可以被一致性检查提取」无法达成。

最小修复要求：在表头识别中同时接受「行=角色」方向（首列或首行标题含「角色 / 岗位 / 用户类型」等），并在同一函数内保留既有「行=对象」识别，不删除旧分支（存量 PRD 与 Design 侧仍在用）。角色名取首列或首行的非表头单元格，业务能力取另一维度；单元格语义仍按 §2.3 根因 D 第 4 点处理 —— 「否 / 不可 / —」必须判定为无权限，不能沿用「非空即存在」。

**存量 PRD 的处置口径**（§2.5 N5）：真实项目的 4.x.3 目前存在三种形态，无一符合角色 × 业务能力矩阵 —— 审计系统 4/4 模块是散文单段（204 / 266 / 388 / 478 字），租金清分 4.1.3 是 `·` 列表，3.3 是表格。因此：

1. 矩阵是**生成侧的新增要求**，不是对存量 PRD 的追溯要求；
2. 阶段 3 真实重写时，只对本轮重写的模块补 4.x.3 矩阵，并在交付说明中列出哪些模块的 4.x.3 未改、原因是什么；
3. 其他存量 PRD 的 4.x.3 不在本轮重写范围内，不得为了让 consistency 提取成功而批量改写业务文件；
4. 4.x.3 自身的巨块（>250 字单段）按 N3 一并纳入阶段 3 的块长治理范围。

### 3.8 短矩阵与流程图

4.x.6 可以使用短矩阵作为扫读锚点，适合表达角色差异、状态与动作、固定选项及其结果。短矩阵不能代替动作正文，也不要求每个页面都出现矩阵。

复杂流程是否配流程图按理解收益决定。三个以上角色、多分支、退回重试回环或复杂状态变化通常值得配图；简单顺序不必为了形式画图。正文必须自包含，不能只写“具体流程见图”。

### 3.9 自然中文规则

生成正文时遵循以下规则：

1. 先写角色和动作，再写条件、处理和结果；
2. 一个句子尽量只承载一个主要动作；
3. 一个自然段只推进一个主要业务判断；
4. 用具体动词替代抽象名词；
5. 用可验证的产品结果替代价值评价；
6. 不在产品正文评价方案是否先进、完整、务实或有效；
7. 不为了修辞制造“不是……而是……”等对比结构；用于排除歧义的否定定义可以保留；
8. 不用“通过……实现……”包住核心事实；
9. 不用“形成闭环、提升效率、强化管理”等总结句代替流程和状态；
10. 未确认事实直接标记待确认，不用概念化表达掩盖未知。

“赋能、抓手、底座、协同、支撑、闭环”等词不能单独作为禁词判断。是否需要修改，要看它是否替代了具体动作、条件或结果。

### 3.10 lint 与 Review 的边界

本轮针对自然描述结构新增或调整的 lint error 只保留能够写出明确判定式的形态；其他既有 error 规则先在阶段 0 登记，只有确认与本轮骨架冲突时才调整。

**error 清单（每条都必须写出判定式、适用边界，以及在旧标签体、审计样本、优秀样本上的命中数）：**

1. 加粗标签体：`**字段名：** 正文` 或 `- **字段名**：正文`；判定式为 §2.2 的两条正则；动作标题（独占一行的无冒号粗体短语）明确豁免。
2. 连续 3 行及以上的同形态加粗标签行；匹配形态、连续计数与动作标题豁免必须在规则中写明。
3. 连续 3 行及以上的行首键值对句式，即现有 STYLE012 的判定。
4. **块长形态退化**（§2.5 N1，本轮新增）：自然段合并后 >250 字，或单个 `·` 列表项 >100 字，判 error。**作用域为全文**（不局限于 4.x.6），并排除代码块（`` ``` `` 围栏内）、`>` 引用块、HTML 注释与表格行。

第 4 条不是长度偏好，而是形态判定：超过阈值的块在排版上已经失去「段落」「列表项」的扫读功能，等价于把多层事实压进一个视觉单元，与 §3.5「一个块只承载一层事实」是同一条规则的两侧。

**为什么必须全文生效**：§2.5 N3 实测审计样本 32 个超长段中只有 15 个在 4.x.6 内（53% 在外），租金清分全文 8 个中只有 4 个在 4.1.6 内，且最长的一段（1531 字）在 4.1.9。只作用于 4.x.6 会放过过半治理对象，也与 §7 阶段 3「本轮重写文件块长必须归零」自相矛盾。

**命中基线（全文口径，阶段 0 必须复跑，见 §2.2.1）**：优秀样本 0 + 0；模板 0 + 0；`test-fixture/` 三份 PRD 4 + 0（按 §9.2 登记为存量遗留）；审计样本 32 + 20；租金清分 8 + 0（其中 4.1.6 内 4 + 0）。旧标签体不适用（无长段）。阈值只能从 profile 的 `metrics` 读取，脚本不得硬编码。

5. **模块编号层级错配**（§2.5 N4，本轮新增）：在功能需求章节内，`###` 级模块标题若带编号，编号必须为两级（`4.<n>`），出现 `4.5.6` 这类三级编号判 error。
6. **编号标题跳级**（§2.5 N4，本轮新增）：在功能需求章节内，两个**都带编号**的标题之间出现层级跳跃（如 `### 4.5.6` 直接接 `##### 4.5.6.2`）判 error。

第 5、6 条的作用域与豁免已实测（见 §9.1）：作用域限定为「H2 标题文本含『功能需求』或编号以 `4.` 开头」的章节内部；**无编号标题不参与判定** —— 这一条不可省，优秀样本与 lint 测试样本的合规形态正是「无编号 H3 → H6 页面名」，不限定会在优秀样本上误伤 6 处、在 lint 测试样本上误伤全部。两条在优秀样本、模板、`test-fixture/` 三份 PRD 上均为 0 命中，在审计样本上各命中 1 处（同源：`### 4.5.6` 既是编号错配，也是跳级的起点）。

第 5、6 条沿用现有 STYLE 编号体系，不新建第二套编号，也不新建检查脚本。

**明确不作为 error 的候选：**

- 「用加粗短语模拟标题层级」—— 与 §3.3 独占一行动作名直接冲突，且审计样本 48 处、租金清分 30 处均为合规形态，整条删除；
- 「多层列表代替正文结构」—— 方向反了（§2.5 N2）。两份真实 PRD 的缩进嵌套列表均为 0 行，真实病状是层级不足。改为**明确允许**用子列表给长块分层，只禁止用缩进列表替代动作正文这个语义判断（由 Review 处理，脚本不判）；
- 「明确违反结构」等无法给出判定式的描述性条款。

动作名称可以独占一行，但必须使用已确定的标题语法，不能因为动作标题存在就被标签规则误报。

短矩阵是 §3.8 允许的结构。STYLE003 继续作为表格主导的 warning，不因短矩阵本身出现就宣判失败；阶段 0 记录基线后，凡是能够说明由允许矩阵直接触发的已知 warning，不得作为 §8 的异常停止条件。

逗号数量、页面列表密度、可能的抽象总结和可能的重复，只能作为 warning 或候选提示，不能单独宣判可读性失败。**例外：段落长度与列表项长度中的块长形态退化已按上面第 4 条升为 error**，因为它在两个真实样本上有区分度且在优秀样本上零误伤；其余长度类指标（如每页列表数量）仍为观察项。

脚本不得自行增加 profile 中没有写明的硬禁词或形态；词表不能承担“判断 AI 味”的责任。Review 和 PM 负责判断自然度、信息因果、重复是否有效以及研发能否第一遍提取事实。

### 3.11 Review 的判断方式

Review 不再只判断“有没有提到”。对每个重要动作，按复杂度检查适用的信息责任，并为结论保留具体证据：

- 谁可以执行，谁不能执行；
- 什么条件或状态下可以执行；
- 操作的对象是什么；
- 用户需要输入或确认什么；
- 什么情况允许或拒绝提交；
- 系统保存、计算、通知或生成什么；
- 成功后状态、页面、记录和下一步如何变化；
- 失败后内容、状态和恢复路径如何处理。

Review 问题必须定位到页面、动作或段落，说明缺失内容对研发、测试或权限判断的影响。不得用“流程不完整”“权限已覆盖”等无法复核的结论代替证据。

### 3.12 真实验收原则

真实验收使用租金清分 PRD，能源数据监测 PRD 不纳入当前 spm-prd 产物基线。

**审计系统 PRD 的地位（另设，不与租金清分混用）**：`D:/work/交投软件中心/审计系统/output/prd/审计整改与项目档案_迭代PRD.md` 是本计划的**第二复核样本**，用于三件事 —— ①验证判定式在租金清分之外的真实材料上是否仍有区分度；②提供 §2.5 的 N1–N5 基线；③作为阶段 0 四材料对撞中的「反例材料」。它**不是本轮重写对象**：不重写、不备份改写、不要求其 lint 归零，其命中按 §9.2 登记为存量遗留。因此 §3.12 的 Design 裁判、旧新对照与 PM 试读三条只对租金清分生效，审计样本不参与这三项。

- Design 是产品事实裁判；
- 旧 PRD 与新 PRD 逐页对照，用于发现改写中的信息损失；
- 文本差集只用于定位候选，不能作为唯一的无损证明；
- PM 进行研发视角的任务式试读，判断新 4.1.6 是否能一次提取关键事实；
- lint 和 consistency 的结果只能作为辅助证据，不能替代最终产物阅读。

## 4. 本轮目标

### 4.1 产品目标

改造后，4.x.6 应同时满足：

1. 研发和测试第一遍可以提取关键产品事实；
2. 页面和动作具有稳定的组织方式，但不会被迫套用完全相同的句式；
3. 复杂流程、状态变化和权限条件有明确落点；
4. 4.x.6 仍然可以独立评审和开发；
5. 产品正文以具体动作、条件、处理、结果和恢复方式为主，减少空泛总结和汇报式表达；
6. 机器能够稳定发现已确定的排版形态错误；
7. 权限矩阵可以被一致性检查提取（含 §3.7 规定的行=角色方向），无法提取时明确标记未评估；
8. 单个块只承载一层事实，长段与长列表项不再堆叠多层信息（§2.5 N1）；该判定全文生效，存量文件按 §9.2 豁免。

### 4.2 质量目标

最终质量以 PRD 的可读性和事实承接为准，不以以下结果单独替代：

- lint 退出码或 issue 数量；
- consistency exit 0；
- 重写前后字数变化；
- 列表数量或段落数量达到阈值；
- 示例文件检查通过。

### 4.3 建议记录的观察指标

真实重写时可以记录以下指标，用于前后对照和定位问题，但不单独作为通过条件：

- 形态 error 数量；
- 过长段落和过长列表项数量；
- 每页动作数量及复杂度覆盖情况；
- 权限矩阵提取到的角色和能力数量；
- Design 到新 PRD 的事实对照结果；
- PM 任务式试读中需要二次解释的动作数量。

三项指标按 §2.5 N1 分流，不再同等对待：

- **“段落 >250 字”与“`·` 列表项 >100 字”已升为形态 error**（§3.10 第 4 条），不再只是观察指标；
- **“每页至少一组列表”仍为观察指标**，不设硬门槛 —— 它会打到 `prd-writing-examples.md` 自己的「车位占用情况页」，属于规范参考系问题，不通过 lint 解决；
- 逗号数量、抽象总结、重复仍为候选提示，最终由 Review 判断是否影响理解。

阶段 3 记录块长时**必须按章节归属分别计数**（§2.5 N3）：审计样本全文件 32 个 >250 段落中只有 15 个在 4.x.6 内，若只统计 4.x.6 会低估一半以上的治理对象。

## 5. 明确不做

- 不改变 4.x.6 的自包含交付目标，不引入指向 Design 的替代方案；
- 不要求所有页面使用相同的正文小标题；
- 不把每页列表数量、动作数量或块数当作普遍可读性硬门槛；**例外**：段落 >250 字与 `·` 列表项 >100 字按 §3.10 第 4 条作为排版形态退化判 error，这不是字数门槛而是形态判定，且**全文生效**（不限 4.x.6）；
- 不因为存量文件命中本轮新增 error 而回头修改业务文件或放宽判定式；存量命中按 §9.2 登记为遗留，只清零本轮重写文件；
- 不用封闭词表判断 AI 味；
- 不把一句话的自然度交给脚本单独判定；
- 不删除为了自包含而必须保留的有效重复；

### 9.1 结构漂移（N4）的判定式、豁免与验收

N4 已由 PM 决定纳入本轮。它属于结构完整性而非文风，判定式、豁免与验收单列如下，避免与 §3.10 的表达形态规则混淆。

**现象（审计样本）**

5 个 `### 4.x` 模块只对应 4 个 `#### 4.x.6`；`### 4.5.6 审计报告-关闭检查` 用三级编号当模块名，且 H3 直接跳到 `##### 4.5.6.2`；模块号存在 4.7 → 4.9 跳号。现行 lint 0 告警。

**纳入的两条判定式**

| 编号 | 判定式 | 作用域 | 命中证据 |
|---|---|---|---|
| **N4-A 模块编号层级错配** | 功能需求章节内，`###` 级标题带编号时，编号必须为两级（`4.<n>`）；出现 `4.5.6` 这类三级编号判 error | 见下方作用域定义 | 审计 1 处（L373 `### 4.5.6`）；其余 6 份材料 0 |
| **N4-C 编号标题跳级** | 功能需求章节内，相邻两个**都带编号**的标题之间层级跳跃（跨级 >1）判 error | 同上 | 审计 1 处（L375 H3→H5）；其余 6 份材料 0 |

**作用域定义（三条限定缺一不可）**
