## 3. 根因证据

### RC-1｜PRD 生成顺序按章节填事实，不按业务对象生成连续流程

- **根因描述**：当前规则要求 PRD 包含业务流程、状态规则、功能详细说明和字段定义，但没有强制先按业务对象连续写完主路径、退回、失败和终态，再进入规则、页面和字段。结果是每类事实单独完整，读者需要自己拼成业务过程。
- **复现步骤**：
  1. 读取 `D:/work/交投软件中心/智慧服务区/租金清分/output/prd/prd.md:156`。
  2. 记录 `4.1.4 业务流程` 中租金账单处理只有一段摘要和一张图。
  3. 读取 `D:/work/交投软件中心/智慧服务区/租金清分/output/prd/prd.md:557`。
  4. 记录 `4.1.6.3` 先给字段，再在给字段之后才出现动作。
  5. 请研发或测试只读这两处，复述“账单从生成到结清”。
- **复现结果**：研发会追问审核退回、通知、登记到账、复核、多缴和结清之间的连续关系。
- **为什么不是表象级补丁**：把某个段落再写长，只会继续把流程、字段、状态和动作压在同一层；换一个模块仍会发生。
- **现有机制为什么没解决**：规则有“业务阶段、页面、动作”的骨架，但没有规定流程先独立成立；Review 只能事后指出“主链路连续可读”，生成阶段没有阻止。
- **证据边界**：
  - **已证明**：租金清分 PRD 的流程摘要无法支撑完整复述。
  - **仅推断**：按对象连续叙述能减少研发和测试的补问。
  - **待验证**：换到设备租赁或审计系统时，同一生成顺序是否仍然可读。

- **现有机制为什么没解决**：现有规则把复杂度作为抽象档位，没有把“落地判断”与“主流程”分层。

#### 4.1.2 目标章节骨架

```text
4.x.1 功能概述
4.x.2 业务对象与关系
4.x.3 角色与权限
4.x.4 业务流程
4.x.5 业务规则
4.x.6 功能说明
4.x.7 页面说明
4.x.8 异常处理
4.x.9 验收标准
4.x.10 待确认事项
```

各章只承担以下责任：

- `业务流程`：按具体业务对象连续写生成、提交、审核、确认、到账、退回、失败恢复和终态；流程图放在正文后。
- `业务规则`：状态、计算、口径、快照、重算、刷新范围和金额联动；复杂规则必须给最小数值例子。
- `功能说明`：按动作组织，并写清角色、允许状态、输入、校验、成功结果、失败保留、状态或金额变化和下一步。每个动作在生成前内部核对是否来自业务流程事件、是否有页面入口，不在正文复述对应关系。
- `页面说明`：页面区块、字段、展示条件、编辑条件、按钮状态、加载、空态、异常和无权限。
- `异常处理`：跨动作的系统异常、并发、重复提交、部分失败和外部失败。
- `验收标准`：主路径、退回、失败、边界、终态和复杂计算例子。

## 7. 每步完成判据

### 7.1 步骤判据

#### T-0｜基线冻结

- **输入**：当前工作树、`docs/iteration-plan-template.md`、目标规则和模板。
- **动作**：记录当前 git 状态、HEAD、目标文件哈希；读取当前规则。
- **必须留下的证据**：状态记录、哈希记录、读取记录。
- **完成判据**：
  - 能区分本轮新增改动和用户已有改动。
  - 能识别既有测试基线。
- **不能据此宣布的结论**：不能宣布规则已改对。

#### T-1｜叙述顺序规范

- **输入**：T-0 基线、D-1、D-2 决策。
- **动作**：修订 PRD 章节顺序、标题和写作责任。
- **必须留下的证据**：规则差异。
- **完成判据**：
  - `业务流程`、`业务规则`、`功能说明`、`页面说明`职责互不替代。
  - 不引入“业务生命线”“动作与页面承接”等标题。
- **不能据此宣布的结论**：不能宣布真实 PRD 已经可读。

#### T-2｜生成规则落地

- **输入**：T-1 完成的规范。
- **动作**：更新 `spm-prd`、`spm-prd-review`、Review checklist 和 USAGE。
- **必须留下的证据**：规则差异和检查项差异。
- **完成判据**：
  - 生成阶段先流程、再规则、再功能、再页面。
  - Review 检查第一次读可复述、动作无高影响歧义、例子是否足够。
- **不能据此宣布的结论**：不能宣布产物层有效。

#### T-3｜示例更新

- **输入**：T-2 完成的规则。
- **动作**：更新示例，展示连续流程、动作闭环、页面说明和最小例子。
- **必须留下的证据**：示例差异。
- **完成判据**：
  - 示例不新增业务事实，只展示写法。
  - 示例能说明“难理解规则必须配例子”。
- **不能据此宣布的结论**：不能宣布复杂项目适用。

#### T-4｜实现验证

- **输入**：T-3 完成的规范与示例。
- **动作**：必要时更新 manifest；运行既有测试。
- **必须留下的证据**：测试结果。
- **完成判据**：
  - 既有测试无新增失败。
  - 新章节能被生成和 Review 触达。
- **不能据此宣布的结论**：不能宣布 PRD 产物有效。

#### T-5｜隔离副本产物验证

- **输入**：T-4 完成的实现。
- **动作**：在隔离副本重写一段租金清分 `账单生成和处理`，按研发/测试视角试读。
- **必须留下的证据**：样本路径、试读问题、未验证项。
- **完成判据**：
  - 第一遍能复述流程。
  - 第二遍能查到动作边界和页面承接。
  - 例子能解释计算段和多缴。
- **不能据此宣布的结论**：不能宣布所有项目都适用。

#### T-6｜最终验收

- **输入**：T-1 到 T-5 的证据。
- **动作**：按规范、实现、产物三层写验收结论。
- **必须留下的证据**：验收报告。
- **完成判据**：
  - 任一层未通过，总状态不得写已完成。
  - 负面结论逐项列出。
- **不能据此宣布的结论**：不能替代真实项目全量重写。

### 7.2 每项改动卡

#### F-1｜固化 PRD 叙述顺序

- **表象**：PRD 事实完整但主线弱。
- **根因**：生成顺序按章节填事实，不按业务对象连续成文。
- **根因证据**：`D:/work/交投软件中心/智慧服务区/租金清分/output/prd/prd.md:156`、`D:/work/交投软件中心/智慧服务区/租金清分/output/prd/prd.md:557`。
- **修复层**：规范层。
- **修改内容**：`业务流程 → 业务规则 → 功能说明 → 页面说明`。
- **不修改哪一层**：不修改真实项目产物层。
- **最终产物证据**：隔离副本试读样本。
- **仅有哪种证据时仍不能宣布完成**：只有规则差异时不能宣布。

#### F-2｜动作说明闭环

- **表象**：实施时仍问输入、保留、失败和联动。
- **根因**：动作没有稳定闭环。
- **根因证据**：2026-10-26 试读问题清单。
- **修复层**：规范层。
- **修改内容**：功能说明按动作组织。每个动作在生成前内部核对是否对应业务流程事件、是否有页面入口，但不在正文复述对应关系。每个复杂动作必须回答角色、允许状态、输入、校验、成功结果、失败保留、状态/金额联动和下一步。
- **不修改哪一层**：不新增脚本或检查器。
- **最终产物证据**：试读样本中的动作段落。
- **仅有哪种证据时仍不能宣布完成**：只有 Review 文本更新时不能宣布。
- **反膨胀判据**：正文不新增流程步骤对照、动作追溯表或重复的“对应第几步”说明；动作段落只比原稿增加缺失的实施事实。

#### F-3｜难理解规则必须配最小数值例子

- **表象**：公式正确但研发/测试理解不一致。
- **根因**：缺少共同的最小结果样例。
- **根因证据**：计算段、多缴、收入确认、年度清算的试读问题。
- **修复层**：规范层。
- **修改内容**：复杂计算和状态联动必须配最小数值例子。
- **不修改哪一层**：不修改验证包规则，不生成测试用例包。
- **最终产物证据**：样本中的计算段和多缴示例。
- **仅有哪种证据时仍不能宣布完成**：只有公式重写时不能宣布。

#### F-4｜页面说明独立成章

- **表象**：页面字段抢占主线，动作和页面职责混在一起。
- **根因**：功能说明同时承担动作闭环和页面字段。
- **根因证据**：`D:/work/交投软件中心/智慧服务区/租金清分/output/prd/prd.md:561` 到 `D:/work/交投软件中心/智慧服务区/租金清分/output/prd/prd.md:700`。
- **修复层**：规范层。
- **修改内容**：功能说明写动作闭环，页面说明写区块、字段、按钮、反馈和状态驱动展示。
- **不修改哪一层**：不修改原型和视觉规范。
- **最终产物证据**：试读样本中两个章节各自成立。
- **仅有哪种证据时仍不能宣布完成**：只有标题改名时不能宣布。
