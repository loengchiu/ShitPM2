## 三、发现的问题

### P2-1：执行报告对 `output/design` 的描述与磁盘事实不符

报告 §八.4 称“`output/design` 空壳子目录（context-pack 验证遗留）无法通过安全删除器移除”。

实际核查：

- `test-fixture/output/fusion-acceptance/output/design/design.md` 存在，大小 129,066 字节；
- 与 `test-fixture/output/fusion-acceptance/design.md` 的 SHA-256 完全一致（`3AB3F9FA...`），是同一 design.md 的重复副本，不是空壳。

建议：修改报告该段描述，说明这是验证过程中产生的完整 design.md 副本；若保留作证据，说明用途；若不保留，直接删除即可，不存在“无法移除空壳”的障碍。

### P3-1：`.tmp-fusion/` 目录未在报告中说明

工作区存在 `.tmp-fusion/`（含 main 的 6 个提取文件副本），未在报告 §九 修改清单中列出，也未说明用途。

建议：要么说明它是 main 提取材料的执行证据并纳入清单，要么清理后不进入最终工作区。当前状态属于报告遗漏。

### P3-2：三种表达形式在 §2.1 与 §6.2 轻微重复

`prd-writing-rules.md` L178（§2.1 写作建议）与 §6.2 都写了“自然段/数字编号/`·` 并列列表”的用法。一处是写作建议概览、一处是使用条件明细，语义一致，不构成冲突，但按“唯一规则源”原则可让 §2.1 只引用 §6.2。非阻塞。

### 待验证：真实 V2 结构复杂项目样本缺失

报告已承认：融合样本的 Design 是 main 风格（1941 行、无操作表十列），无法直接验证 context-pack `--module` 在 V2 结构（十列表格）大项目上的模块级装载与生成。test-context-loading 覆盖了装载机制正确性，但不等于真实产物验证。

建议：下一个真实 V2 结构项目（或构造符合十列表格契约的较大 Design 副本）生成 PRD 时，按同一“资深规格五问”验收一次，再关闭该遗留项。
