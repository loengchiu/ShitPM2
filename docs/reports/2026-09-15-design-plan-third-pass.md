## 2. 必须再补（P1）

### N1｜关键空集判据与旧格式降级路径重叠，会把旧格式项目打成硬失败

计划的判据是"正文存在页面标题信号但 pages=0"。用旧格式 Design（无 `页面：/区块：/字段：/操作：` 固定标题结构）实测：

```
summary {"blocks":0,"fields":0,"operations":0,"pages":0,"errors":1}
codes   ['unsupported_format']
load_verified_index → err = None（即当前降级可用）
正文标题  ['## 页面说明']     ← 含「页面」字样，会被"信号"命中
```

即旧格式项目**同时满足**「pages=0」和「标题含页面」，但它在今天是被 `_is_unsupported_format` 正常降级为 legacy 的（`prd-consistency-check.py:2174`）。`load_verified_index` 里的判定顺序是：

```python
if compiled.get("errors"):
    if _is_unsupported_format(compiled):        # ← 旧格式在这里 exit
        return compiled, None, False
    if any(... code == "invalid_type" ...):     # ← invalid_type 的既有写法
        return None, "…索引不可用…", False
```

**若把新 fatal 判断放在 `_is_unsupported_format` 之前，或按"标题含页面 + pages=0"在消费者侧独立判断，旧格式项目就从降级可用变成硬失败。** T-1 的 5 条动作没有规定顺序与精确信号，完成判据也只写"标准格式无回归"，没有旧格式保持降级的判据。

建议改法（最小）：

- 判据从文本信号改为结构判据：**`blocks + fields + operations > 0 且 pages == 0`** → `page_extraction_empty`。理由：零实体文件已由 `unsupported_format` 覆盖，两者互斥。设备租赁实测 `blocks=14/fields=89/operations=7/pages=0` 命中；上面的旧格式夹具 `0/0/0/0` 不命中。
- 写入顺序约束：fatal 判定必须位于 `_is_unsupported_format` 分支**之后**，沿用既有 `invalid_type` 的写法（`return None, "<原因>", False`）。
- T-1 完成判据加一条：**旧格式（unsupported_format）项目仍走 legacy 降级，不得变成硬失败**；§8 加对应停止条件。

（附带：`design-index.py` 已有 `_extraction_diagnostics` 计算同类的 `no_entities_extracted`，但只出现在 CLI 输出、刻意不写索引。新 fatal 与它是两个不同层面，不要合并。）

### N2｜T-7 的 F2 分支会被读成"删场景"，而可确定夹具存在

T-7 第 2 条写"检查输入格式是否存在明确的终态/非终态事实……若不存在，删除 F2 的确定性检出声明"。事实是格式里没有"是否终态"列，执行者很可能据此判定"不存在明确事实"→ 删除场景。

但规范的终态定义是**结构性**的：`references/design-state-format.md:23` 规定「终态（无下一步）也占一行，触发动作和下一状态写"—"」。因此 F2 现有夹具里"待审核"的两个 `—` 按格式定义**就是终态**，A 夹具不构成缺陷——这不是"缺断言"，是**前提错误**（第二遍已指出）。

而"非终态无出路"在格式里是可确定的：**状态只作为目标态出现、表中没有它自己的行**。实测两种夹具：

```
A 待审核有自有占位行 → 待审核 is_terminal=True  transitions=0  → 非终态无出路 = []
B 待审核仅作目标态、无自有行 → 待审核 is_terminal=False transitions=0 → 非终态无出路 = ['待审核']
```

建议 T-7 第 2 条直接写明：**用 B 形态夹具，形成真实断言**，并把 `design-state-format.md:23` 作为"A 不是缺陷"的规范依据；只有在 B 形态也无法判断时才走删除分支。这样既修掉假断言，又不删掉一个真实的检查缺口。

### N3｜T-3 的关系实例定义缺 R13 实证的两个维度

T-3 定义的关系实例维度是：角色、对象、状态/前提、动作、数据范围、规则/来源、结果/去向、异常/恢复。

R13 的自我归因是这 8 个维度之外的**维度缺失**：

- `design-review-13.md` 0.2：本轮新增三条轴——⑱「单据类型」统称 ↔ 类型区分、⑲ 页面属性集差集、⑳ 字段表含糊展示条件 ↔ 权限矩阵归属行；"扩完闸门判定从「通过」翻转为「未通过，硬命中 6 项」"。
- 同节明写：⑤/⑭/⑮ 三轴"都只按「状态名」或「角色 × 状态」做差集，**没有「单据类型」维度**"，而"定向基础结算单"是统称，下辖两种可见性截然不同的单据。

也就是说，最后两轮的命中不是"已知维度下的新实例"，而是**核对面维度本身缺失**。计划 T-5 的完成判据写"新关系类型算方法缺口"，但没有给出发现新维度的动作，"维度缺口"仍只能靠人读撞上。

建议 T-3 的关系实例定义补两个维度：

- **对象细分类型**：存在统称/分类表述时，必须按细分类型分别判断权限、可见性、状态与数据范围；
- **属性集差集**：同类对象的属性/字段集合必须成组比对（页面属性是否齐备、字段在矩阵/字典/实体三处是否成组）。

并在 T-5 加一条动作：**每个审查单元先做维度差集（本单元用到的核对面 vs 关系实例维度清单），维度缺口与实例缺口分别记录**。这正是把 R13 的"补轴"动作从人工偶然变成固定步骤。

## 3. 建议补强（P2）

### N4｜T-2 缺 R13 的串归一化口径

R13 0.3 记录了第三种工具缺陷：**解析噪声冒充信号（假阳性）**。⑯ 轴把括注当字段名（矩阵行「冲正标记（原单被冲正标识）」拆出「原单被冲正标识」），修正口径（剥离括注、剥离「全部字段」「与…入口」后缀）后 **7 条降到 3 条**；④ 轴同病，拆开后 **3 条降到 0 条**。R13 明确写"这条经验要固化"。

T-2 的准入门槛只有"覆盖率 ≥ 60% / 错误候选 < 命中×2"，没有约束候选提取本身的归一化，也没引用这两个已有误报基线。建议 T-2 动作加一条：**候选串先做归一化（剥离括注、剥离「全部字段」「与…入口」类后缀、拆分并列分隔）后再判定**，并把 ⑯ 的 7→3、④ 的 3→0 作为误报对照基线。

### N5｜T-6 的"同族"必须写成三维

R13 的第 12 轮回读给出的根因（R13 自评"本轮最重要的结论"）：

> 第 12 轮自我回扫抓到的 6 类 14 条**全部是被点名的字符串的其他出现处**……**"同族"是按字面字符串定义的，不是按「约束 × 承载面 × 页面」三维定义的**。

于是三类同族全漏：写法**变体**（「按权限显隐」漏「按权限可见」5 处）、**整页/整属性漏**（D12-01 只落 P-SET-01/02，03/04 两页漏，且这两页无「状态可见性限缩」属性）、**统称未按类型拆**（D13-01）。

T-6 第 4 条现为"搜索字面变体、同类型对象和兄弟页面"。建议补成三维枚举：**约束 × 承载面 × 对象（含细分类型）**，并加"缺失属性整列/整页"这一形态。这条同时把 N3 的维度缺口落到 Fix 侧。
