# AI 时代的业务正确性审查：哪些环节可以被「AI + 脚本」替代

调研日期 2026-09-16。承接同日的前一篇调研（`2026-09-16-engineering-business-review-practices-survey.md`），
那篇收集的是**前 AI 时代**的自动化审查手段，其隐含前提是「人已经把规格写成机器可判定的形式」。
本文回答：LLM 出现后，这个前提发生了什么变化，哪些环节从"只能靠人"变成"AI + 脚本可以做"。

> 引用纪律：本文所有数字均来自**原始摘要或原文表格**。调研中发现二手博客转述的数字系统性偏乐观
> （详见 §8），凡未能回到原始出处核对的一律不采用。

## 0. 结论

**分界线的位置变了。**

前 AI 时代自动化审查的前提是「规格已经从业务语言翻译成机器可判定的形式」（状态机、权限矩阵、不变量、契约）。
脚本能做的是**在已形式化的对象上穷尽检查**。瓶颈不在检查，在**形式化那一步**——那需要人，且成本高，
所以只有安全关键、金额相关、权限相关的核心路径才值得投入人力去形式化。跨文档一致性、异常恢复、
结果去向、字段来源这些"中间地带"长期留在人审里，不是因为无法检查，而是因为**不值得为它们付形式化成本**。

LLM 改变的是**形式化这一步的单位成本**。一旦这步便宜了：

- 原来"不值得形式化"的中间地带可以被形式化，于是可被脚本穷尽；
- 原来"需要专家才能写"的形式规格（TLA+、SMT、系统断言）可以先有草案，但**必须由求解器验证**；
- 出现了一类**前 AI 时代不可能有**的新手段（§4），它们用"多次采样的不一致"本身当作缺陷信号。

所以正确的形态不是「AI 替代脚本」也不是「脚本替代 AI」，而是三段式：

```
LLM 起草形式化候选  →  确定性检查器给出硬结论（反例/证据）  →  人处理无机械判据的部分
       ↑                                                              │
       └──────────────── 反例回喂，粒度决定修复效果 ──────────────────┘
```

三条硬约束（§6 展开）：**LLM 产物只能当候选**；**验证器必须与生成器异源，优先可执行/求解器型**；
**反馈要给具体反例，不能只说"这里有错"**。

## 1. 七个维度在 AI 时代的可替代性

| 维度 | 前 AI 时代手段 | AI 时代新增的可行路径 | 可替代程度 |
|---|---|---|---|
| **状态/流程** | 人画状态机 → 脚本跑路径覆盖 | LLM 从非结构化需求起草状态机；**矩阵化查空格** | 结构可替代，**条件不可**（§5） |
| **权限** | 人写角色×动作×范围矩阵 → 脚本逐格双向断言 | LLM 从自然语言抽矩阵候选；SMT/TLA+ 建模后模型检查找反例 | 抽取可替代，判定仍靠人 |
| **规则/不变量** | 人写不变量清单 → 属性测试穷举 | LLM 推断不变量 → 随机搜索反例（Agentic PBT） | **高度可替代** |
| **字段来源/数据** | 列级血缘 + data contract + 内置数据测试 | 语义对齐（严格字符串匹配失效处） | 中 |
| **异常恢复** | 故障注入（先写假设再注入） | LLM 起草"若[故障]则[补偿]维持[业务结果]"假设 | 起草可替代，注入需运行时 |
| **结果去向** | 消费方驱动契约测试 + 部署门禁 | LLM 比对声明与承接面的一致性 | 中 |
| **跨文档一致性** | 人工比对（最耗时、最易漏） | **LLM 双向一致性检查（已有 SANER 2025 实证）** | **最显著的一处替代** |
| **歧义** | 人读（无工具） | **多次独立形式化，不一致即歧义信号** | **前 AI 做不到（§4）** |

## 2. 已有工业实证的四种「AI + 脚本」范式

### ① 变异引导测试生成 —— LLM 生成候选，确定性过滤器把关

Meta ACH（`arXiv:2501.12862`，FSE 2025 Industry）：让 LLM 生成"针对某类关注点的、当前未被任何测试捕获的故障变异体"，
再让 LLM 生成能杀死这些变异体的测试。规模：10,795 个 Android Kotlin 类、7 个平台 → 9,095 个变异体、571 个测试用例；
等价变异检测 agent precision 0.79 / recall 0.47，**加简单的静态预处理（如去注释）后升到 0.95 / 0.96**；
工程师接受 73% 的测试，其中 36% 被判为与隐私直接相关。

同组更早的 TestGen-LLM（`arXiv:2402.09171`，FSE 2024）把过滤器链写得更直白，摘要原话是
"verifies that its generated test classes successfully clear a set of filters that assure measurable improvement
over the original test suite, **thereby eliminating problems due to LLM hallucination**"：

```
生成 100%  →  能编译 75%  →  稳定通过 57%  →  真的提高覆盖率 25%  →  留下
```

这组漏斗数字本身就是「LLM 产物只能当候选」的量化证据：**四分之三的产出在确定性过滤器下被淘汰，
而正是这个淘汰动作让剩下的四分之一可以被信任**。

**可迁移的判据**：为 LLM 的每一类产出配一条能机械判定的"改进证明"。不是"看起来对"，
而是"编译通过 / 执行通过 / 重复运行不抖动 / 覆盖率有净增"。

### ② LLM 起草形式规格 → 求解器验证

**VeriMed**（`arXiv:2605.13817`，Stevens Institute of Technology，2026-05）：把自然语言需求翻译成 SMT 逻辑
（autoformalization），再用求解器做四类审计：

- **全局一致性**（unsat core 定位冲突子集）
- **空泛性**（触发条件不可达）
- **可违反性**（取反可满足 → 该需求可被打破）
- **冗余性**（被邻条包含）

实验：64 条血液透析机安全需求，解析成功率 100%，往返等价余弦相似度 96.2%，**变异检测 97.3%**，
并定位出 2 条冗余需求。

关键提醒来自论文自己的表述：**"syntactic validity is not enough"** ——语法合法的形式规格可以全局矛盾、
可以触发条件不可达、可以同时容纳多种解读。**没有 ground truth 形式化时，不存在正确性 oracle**，
这是 LLM 自动形式化的固有困难。所以这里的脚本侧不是"再让模型读一遍"，而是**求解器**。

同类：PropertyGPT（智能合约，`arXiv:2405.02580`）用编译/静态分析反馈做外部 oracle 迭代修正属性，
覆盖人类专家判定等价的属性 80%、precision 0.64；神经符号环不变式合成（`arXiv:2606.16886`）
用 ESBMC 作 oracle，**符号反馈对弱模型带来最多 +35 个解出的基准**。

### ③ LLM 推断不变量 → 随机搜索反例

**Agentic PBT**（`arXiv:2510.09907`，Anthropic + Northeastern，NeurIPS 2025 workshop）：agent 读 Python 模块，
从代码与文档**推断函数级与跨函数不变量**，翻译成 Hypothesis 属性测试并执行，反思失败结果确认真 bug，
输出可执行的缺陷报告。100 个流行包，**56% 的缺陷报告经人工复核是有效 bug，32% 值得上报维护者**；
而得分最高的 21 个里 **86% 有效、81% 值得上报**。向 NumPy 等库上报 5 个 bug，3 个补丁被合并。

这里的分工是教科书式的：**"什么该永远成立"由 LLM 想（语义、需要领域理解），
"是否真的永远成立"由随机搜索试（穷尽、机械）**。属性测试长期不流行的原因恰恰是
"识别有意义的属性需要大量领域专业知识与时间"——LLM 补的正是这一块。

（此前调研已记录：faker-check 类工具的教训是测试要写"不该发生的形态"，这与属性测试的思路一致。）

### ④ LLM 生成变形关系 → 关系断言替代预期值

变形测试（metamorphic testing）的 30 年老问题同样是"关系由人写"。新工作把这一步交给 LLM：
`Information and Software Technology` 2026 的论文在数据中心、自动驾驶、有限自动机三个领域做
**变形关系推断 + 后续测试用例生成**，**后续用例正确率 >99.6%**。

可迁移的四类关系（对任何"输出无法预先写出"的判断都适用）：

- **改写不变**：换个说法，判定必须一致
- **否定反转**：否定决定性事实，结论必须翻转（这条 embedding 相似度看不见）
- **无关内容不变**：塞进无关句子，结论不得改变（可暴露提示注入敏感）
- **顺序不变**：打乱独立项顺序，结论不得改变

## 3. 只能由 LLM 起草、不能由 LLM 定论的四类产出

把上面四类范式横过来看，共同结构是「**LLM 输出一个可被机械检验的中间物**」。这个中间物是新的资产类型：

| 中间物 | LLM 负责 | 脚本/求解器负责 |
|---|---|---|
| 变异体 | 生成"这个业务关注点下现实会犯的错" | 是否有测试能杀死它 |
| 形式规格（SMT/TLA+） | 起草逻辑式与不变量 | 一致性/空泛/可违反/冗余查询 |
| 不变量 | 推断"什么该永远成立" | 随机输入搜索反例 |
| 变形关系 | 推断输入变换与输出关系 | 关系是否被违反 |

**这四类中间物的共同点：一旦写出来，它的检验就是可判定的。** 这正是 LLM 补上的那一环。

## 4. 前 AI 时代不可能有的新手段

### 4.1 用"多次独立形式化的不一致"检测歧义

VeriMed 的做法：对同一条需求，**独立采样 N=5 次形式化**，然后两两做**双向 SMT 等价检查**。
若形式化之间不等价，说明原文容许多种解读——**歧义**。求解器给出的 witness 直接指出分歧在哪
（例如数值边界的两种解释）。

结果：64 条需求中标出 12 条（18.8%）产生多种编码；配合澄清流程后**歧义敏感需求的不确定性从 18.8% 降到 0**。

这是纯 LLM 时代产物：前 AI 时代没有"同一个输入给出不同形式化"这件事；
而它最漂亮的地方在于**把概率性的不一致，转换成了可判定的等价检查**——
LLM 的不确定性在这里从缺陷变成了**探针**。

### 4.2 反例回喂，且**粒度决定效果**

VeriMed 的第二个发现比第一个更可操作：在反例引导修复（CEGR）中，反馈的粒度直接决定修复质量。

| 反馈内容 | 验证准确率 |
|---|---|
| 无反馈 | 55.4% |
| 只给"违反的是哪条需求" | 80.0% |
| **给出具体 SMT 反例** | **98.5%** |

**"你错了" 与 "错在这个具体输入上" 之间有 18.5 个百分点的差距。**
LLM 当 reviewer 时最常见的失效正是只给前者。

### 4.3 跨文档双向一致性检查

`arXiv:2509.09975`（SANER 2025，Fujitsu）系统化了设计文档审查：先整理出 **11 个审查视角**，
再判定哪些视角当前通用 LLM 能替代人。结论是**一致性检查可替代**，并做实验确认 LLM 能识别
软件设计文档中的不一致（真实业务用的基于 Excel 的设计文档，银行账户系统，SDEM 标准）。

论文给出的失效边界很具体：**一致性检查比歧义检查更难，因为它要求正确理解多章节之间表头与取值的关系**，
而歧义检查可以逐句做、不依赖表格结构。当 LLM 误读这些结构化关系时，跨文档一致性评估就会失效。

配套的 schema 约束路线（`AICCC 2025`）把检查拆成：LLM 抽取 → 统一 schema（标识/度量/关系/值/单位/追溯链）
→ 追溯覆盖检查 + 数值验证 + 逻辑矛盾检测。

### 4.4 多轮迭代审计的收敛，而非单次通过

`arXiv:2605.12280`（MDPI Software 2026）是对 7,152 行规范面做 9 轮 agent 审计的案例：
**51 个一致性缺陷，逐轮计数 15 / 8 / 12 / 2 / 8 / 1 / 4 / 1 / 0**。

三个可直接借用的观察：

- **非单调收敛**：轮次间缺陷数不单调下降，与"级联编辑"和"审计范围扩张"一致 → 不能把"上一轮全绿"当收敛判据
- **跨厂商面板**：四家（OpenAI/Anthropic/Google/xAI）12 条轨迹的**并集检出全部 5 个种子缺陷** → 异源组合提升覆盖
- **评分者间一致性：类别 κ=0.80，严重度 κ=0.46** → **分类可靠，定级只有中等一致性**

最后一条对本项目尤其相关：审查结论的**严重度定级**本质上不如"是不是缺陷"可靠。

## 5. 明确的边界：这些地方 LLM 替代不了（有数字）

| 能力 | 实测 | 出处 |
|---|---|---|
| 状态机**结构** | states F1 0.90 / transitions F1 0.75（Claude 3.5 Sonnet） | `arXiv:2604.00275` |
| 状态机**守卫条件** | guards F1 **0.23** | 同上 |
| 状态机**动作** | actions F1 **0.00**（GPT-4o） | 同上 |
| TLA+ 语义正确 | **8.6%**（语法正确 26.6%） | `arXiv:2606.05792` |
| 代码审查精确率 | **3.19% – 5.10%**（GPT-5.2/GPT-5-mini） | CR-Bench `arXiv:2603.11078` |
| 代码审查召回率 | 18.39% – 32.76%，且**多轮反思以噪声换召回**（SNR 5.11→1.95） | 同上 |
| 覆盖人类审出的问题 | 四个工具**并集 41.5%**（97/234） | c-CRAB `arXiv:2603.23448` |
| 业务逻辑缺陷 | OWASP ASVS 4.0.1 明示：**只能靠人类协助** | OWASP |
| 缺失授权（CWE-862） | ICST 2025 对比中**没有一个 LLM 能处理** | 见 §8 说明 |

**两条最该记住的：**

1. **LLM 抓得住"状态和迁移"，抓不住"守卫条件和动作"**（0.90/0.75 vs 0.23/0.00）。
   而后者恰好就是 Design 里最要紧的东西——"这个动作在什么条件下可用"。**把条件判断交给 LLM 单独完成是没有依据的。**

2. **"零发现"是危险信号，不是通过信号。** CR-Bench 的原始表述是
   "code review agents can exhibit a low signal-to-noise ratio when designed to identify all hidden issues"，
   配套调研中也有实测：某工具在默认配置下对四个预置缺陷返回**零条评论**，而"一次完成且零评论的 AI 审查
   会让团队把通过当成安全证据"。**审查结论必须区分"查过且没问题"与"没查出来"，这与此前项目里
   `page_extraction_empty` 要解决的问题同源。**

### 一条反直觉的负面证据

`arXiv:2608.21298`（2026-08，34 人交叉对照实验）的标题直译是
**《人机协作需求工程：LLM 对需求审查产生负面效应的证据》**。结论：

> LLM 支持**降低了缺陷（smell）识别的准确率**；对缺陷分类与任务耗时无显著影响；
> 学习效应存在，但**先借助 LLM 进行审查会削弱学习效应**——作者据此提出"从一开始就依赖 LLM
> 学习需求审查，可能延缓技能习得"。

同时它综述的 26 项研究（2019–2025，Wolf et al.）给出了更细的图景：
GPT-4 在**识别"不完整"上好于识别"不一致"和"歧义"**；10-shot 相比 0-shot 在歧义分类上提升 20.2%。
（Bashir et al., ICSME 2025，三个工业数据集，八位行业专家对解释质量评分 3.84/5。）

**这条对 ShitPM 的直接含义：把 LLM 当"审查协作者"塞进人的判断回路里，可能反而降低人的检出率——
尤其是对新人。** 这支持把 LLM 用在"机械可验证的产出"上，而不是"帮人看得更清楚"。

## 6. 三条硬约束（可执行）

### 约束一：LLM 产物只能当候选

Meta 的做法是标准形态：**每一类 LLM 产出都配一条机械的"改进证明"**。
TestGen-LLM 的漏斗（75% → 57% → 25%）说明这不是形式主义——
**留下的四分之一之所以可信，正是因为被淘汰的四分之三被机械地验伪了**。

反例形态：LLM 给出结论 → 人说"看起来对" → 通过。这既不是候选制也不是验证制。

### 约束二：验证器必须与生成器异源；优先可执行/求解器型

`arXiv:2606.20093`（2026-06，四模型家族、85 组对照）给出了一个**反向**证据：
在"**有效与否由确定性验证器裁定**"的设置下（IFEval 官方 checker 判定草稿违反了约束、候选编辑修复了它），
**自我偏好偏差检测不到**：作者拒绝已验证为好的修正的比例与新手（fresh）模型几乎相同
（gap −5.1pp，95% CI [−12.9, +2.7]）。唯一稳健的观察是质性的：作者拒绝时 **97% 的理由是在挑缺陷，而非偏好**。

对照另一侧：在**无 ground truth 的质量判断**场景下，自我偏好是明确存在的
（模型能以高准确率识别自己的输出，自我识别能力与自我偏好线性相关；
不同 prompt 的同一模型几乎买不到独立性，不同模型家族能买到一些，**规则/执行型检查器最多**）。

**合并结论：一旦引入确定性验证器，"同源偏差"基本消失；在没有验证器的地方，"换个模型再审一遍"几乎无效。**
所以顺序应当是：**先找有没有可执行检查器（测试、断言、求解器、schema 校验），
没有的话才退回到跨厂商模型面板**——而后者只能提高覆盖，不能提供置信度。

### 约束三：反馈粒度决定修复效果

VeriMed 的 55.4% → 80.0% → 98.5% 三级台阶（§4.2）。
写审查报告时，"违反了什么"是最低要求，**给出具体反例（哪个输入、哪条路径、哪个取值组合）才是有效反馈**。

这与此前项目里反复验证的一条同构：**"再跑前先确认上轮 P1 已修"、"声明与实物不符是高频缺陷"**——
只报结论不报证据，修复方只能猜。

## 7. 落到 ShitPM：哪些可以动，哪些不该动

`AGENTS.md` §1 的准入四问不变（删除它最终产物会错在哪？现有自检为何解决不了？有无真实项目证据？）。
按本文证据，符合四问的是**引入"LLM 起草中间物 + 脚本穷尽检验"这条链路**，而不是新增检查器。

### 可以替代（有外部实证支撑）

| 现在 | 可变成 | 依据 |
|---|---|---|
| Design ↔ PRD 结构对账（`design-index.py` 已有确定性比对） | 保持脚本侧不变，**LLM 只用于起草"实体↔实体"的映射候选**，映射经脚本核对后才生效 | c-CRAB：检查器型 > 模型型 |
| 状态机只做图视角（孤岛/可达/终态） | 增加**状态×事件矩阵**：LLM 起草矩阵，脚本标注空格（某事件在某状态下无定义） | 前篇调研 HN 讨论 + guards F1 0.23 说明条件侧必须可见化 |
| 权限靠自然语言 | LLM 抽"角色×动作×范围"矩阵候选 → 脚本逐格双向断言 | OWASP：唯一通用做法是不变量清单 + 指出由谁保证 |
| 无歧义检测 | **多次独立形式化 + 不一致信号**（§4.1） | VeriMed 18.8% 检出 |
| 跨文档一致性靠人 | LLM 双向比对，按 schema 约束输出 | SANER 2025 已验证可替代 |
| Fix 的"影响面枚举"（`spm-fix` 步骤 5） | 保持枚举，但**反馈必须带具体反例**，否则修复方只能猜 | VeriMed 粒度效应 |

### 不该替代（无机械判据）

业务合理性、范围边界、金额口径、高影响未决事实——`AGENTS.md` §11 已规定必须问用户。
本文证据支持这条不变：CR-Bench/c-CRAB 的精度数字、OWASP 的"业务逻辑只能靠人"、
以及 2608.21298 的负面结果，都指向同一结论。

### 一处需要重新审视的现状

当前 Review 走的是 instruction-only 路线，而**本文证据显示价值最高的是"LLM 起草可检验的中间物"**。
但这条不等于"给 Review 加脚本"——按四问，前提是能指出**某个中间物在真实项目里反复缺失、
且写出来之后检验是可判定的**。目前能明确满足的是**状态×事件矩阵**（矩阵自身是可数的）与
**权限矩阵**（格子是可枚举的）。其余（跨文档一致性、歧义）缺少可判定的中间物，
只能停留在"LLM 给候选 + 人判"。

## 8. 一条方法论警告：二手转述系统性美化 AI

本轮调研中，多篇聚合站点与博客给出的"AI 能力数字"**在原始论文中查不到，且偏差方向一致地偏乐观**：

| 博客转述 | 回到原文 | 差异 |
|---|---|---|
| CR-Bench 精度 0.38 / 0.62 / 0.71，人类基线 0.85/0.78/0.69 | 原文 Table 4：精度 **3.56% / 5.10%**；**原文没有任何 human baseline** | 精度差约 10 倍；人类基线一行是**编造的** |
| c-CRAB：Claude Code 43.2% / Copilot Workspace 35.9% / CodeGemma 7B 24.1% | 原文 Table 5：Claude-Code **32.1%** / Codex 20.1% / Devin 24.8% / PR-Agent 23.1% | 数字整体上调约 10 个百分点 |
| 框定效应使漏洞检测下降 **16.2–93.5 个百分点** | 原文摘要只给"6 个模型 × 5 种框定条件"与"精炼攻击 32/33 成功（97%）"，**无此区间** | 数字无原文来源 |
| 引用 aggregate 站（emergentmind / ar5iv / pith.science）作为论文出处 | 原始源为 arxiv/ACM/ScienceDirect | 应直引原始源 |

`arXiv:2603.18740` 原文的真实结论仍然重要且可利用：
框定效应是 LLM 漏洞检测中"系统且普遍"的现象，**精炼攻击成功率 32/33（97%）**，
论文自己点出根因是一个不对称性——**攻击者可以对审查流水线的本地克隆反复迭代，而防御方只有一次机会**。

**纪律**：AI 能力数字必须回到原始摘要或原文表格；聚合站与博客只能当线索，不能当证据。
这条与前一篇调研里"凭印象拼 OWASP WSTG 深链会 404"是同一类错误的两次复现。
