## 1. 概念与触发边界

### 1.1 什么是“数据口径闭包”

数据口径闭包（Data Definition Closure）指系统内**影响用户判断、业务处理、经营决策、财务对账、数据下钻、报表导出或跨系统流转的重要数据结果**，必须具备完整的业务定义：
- 研发人员依据文档能推导出唯一确定实现；
- 测试人员能依据文档设计出完备的输入输出测试用例；
- 严禁出现“根据文档可合理推导出两种及以上不同计算结果”的歧义。

### 1.2 触发边界

- **必须触发数据口径闭包的场景**：
   - 经营报表、看板指标、概览卡片、趋势图表、排行榜；
   - 财务清分、计费结算、分成租金、滞纳金、公摊金额、税费折算；
   - 跨表/跨状态/跨维度的数量统计、比例分析、平均耗时、达成率、在线率；
  - 列表汇总行、表头筛选计数、下钻明细联动统计、导出统计文件；
  - 依赖多业务状态过滤或特殊时间窗口（如近 7 日、本月至今、自然季度）的派生数值。

- **免除触发数据口径闭包的场景（不适用项）**：
  - 普通表单直接录入的单源字段（如“用户姓名”“联系电话”“车牌号”）；
  - 系统自增主键、流水号、固定枚举字典标签（如“男/女”“正常/停用”）；
  - 纯前端交互状态与元数据（如当前页码、每页条数、排序图标、静态占位符）；
  - 无业务逻辑直接回显的单表原生属性（如用户注册时间、创建人）。

## 2. 四档数据责任

重要数据结果根据其计算与逻辑复杂度，分为四档，承担递增的信息闭包责任。不得把简单直接数据强套周期结算模板，也绝不能用“系统统计/系统计算”一笔带过复杂统计或结算。

```text
第四档：周期结算 (Periodic Calculation) ─── 包含第三档全部责任 + 账期锚点 + 过程精度 + 尾差平衡 + 历史快照锁定
       ▲
第三档：汇总统计 (Aggregate Data) ─────── 包含第二档全部责任 + 统计对象 + 组织时间范围 + 纳入排除 + 分子分母 + 去重兜底
       ▲
第二档：派生数据 (Derived Data) ───────── 包含第一档全部责任 + 依赖字段 + 转换换算逻辑 + 边界空值
       ▲
第一档：直接数据 (Direct Data) ────────── 权威数据源实体 + 属性字段 + 空值回显
```

### 第一档：直接数据（Direct Data）

- **定义**：直接源自单个底层业务实体、字典或关联实体的单一原生字段回显。
- **责任要求**：
  1. 权威数据源：指明来自哪个业务对象/实体的哪个具体属性；
  2. 空值处理：指明字段为空、未绑定或无值时的前端展示（如展示为“`-`”或“无”）。
- **边界**：不要求编写公式、统计范围或时间边界。

### 第二档：派生数据（Derived Data）

- **定义**：由单个或少数已知源字段通过确定性格式化、单位转换、简单条件判定或文本拼接生成的数据（如分转元、年龄计算、多字段拼接姓名工号、基于状态的判定标签）。
- **责任要求**：
  1. 依赖源字段：明确引用的所有源字段名称与实体；
  2. 转换规则：明确转换计算公式（如 `金额（元） = 金额（分） / 100`）或条件映射字典；
  3. 异常与空值：任一依赖源字段缺失或异常时的回显与兜底逻辑。

### 第三档：汇总统计（Aggregate Data）

- **定义**：基于单表或多表多条记录聚合汇总而成的数据结果（如卡片总数、完成率、平均值、比率、趋势图序列、列表汇总行等）。
- **九项写作要素（统一写作口径）**：
  1. **统计对象与业务实体**：统计基本单元是什么（如车辆出入记录、工单、租户、订单）；
  2. **组织与权限范围**：按哪个组织层级或租户汇总，是否严格继承当前登录人或筛选器的数据查看权限；
  3. **时间范围起止边界**：明确起止时点（年月日时分秒）、区间开闭（如闭区间 `[起, 止]` 还是左闭右开 `[起, 止)`）、快捷筛选词（今日、近7日、本月）的标准锚点与时区；
  4. **分子与分母定义**：比例、完成率、均值类指标必须分别明确分子集合与分母集合的独立定义，严禁只写“总数”；
  5. **纳入状态与排除项**：明确纳入统计的业务状态白名单（如仅限“已结算”状态），显式写出排除的异常、作废、测试、冲销或内部记录；
  6. **去重规则**：明确按什么业务唯一键去重（如按车牌号、身份证号、设备 ID），还是不作去重按流水累计；
  7. **空值、零值与兜底**：无数据时显示为 `0` 还是“`-`”；分母为 0 时的展示与容错逻辑（如显示 `0.00%` 或“`-`”）；
  8. **刷新与时效**：明确是实时查询计算、定时按批次聚合（如每日凌晨 2 点），还是事件驱动触发；
  9. **联动、下钻与导出一致性**：同名汇总指标在看板卡片、列表汇总行、下钻明细及导出 Excel 中默认必须使用完全相同的口径与范围。

### 第四档：周期结算（Periodic Calculation）

- **定义**：涉及会计周期、计费账期、跨期分摊、多阶段重算、历史快照锁定与财务级尾差平衡的高复杂度数据（如租金清分、滞纳金、水电公摊、分成结算金额）。
- **责任要求（在第三档基础上追加）**：
  1. **账期周期定义与时间锚点**：明确自然月还是业务账期（如上月26日至本月25日）；结算启动日基准；首期不满周期与末期退出的锚定处理；
  2. **取数时点与版本策略**：以发起结算时的业务数据快照为准，还是结算期间实时取数；版本追溯机制；
  3. **完整分步公式**：列出清晰的数学运算公式与步骤，明确每个参数、系数与分摊因子的定义；
  4. **过程精度与最终精度**：明确计算中间过程保留的小数位数、最终展示与落库保留位数，明确舍入规则（四舍五入、向下截断、向上进位）；
  5. **尾差处理机制**：因按天折算、多方分摊或精度取整导致的角分尾差，明确其归属规则（如全部计入首期、末期吸收、或归属主出租方）；
  6. **重算与锁定规则**：已生成账单、已对账确认或已归档的数据是否允许重算；撤销、退款、历史补录或争议调整时的跨期冲正机制与权限控制；
  7. **正常例与边界例**：在 Design 规则已确认的前提下，给出标准业务场景的数值代入正常例，以及极端/边界场景（如跨闰年、首期仅1天、金额极小分摊为0）的计算验证示例。

## 3. 同名同口径原则

- **原则**：同一系统或同一业务模块内，同名指标（如“待处理工单数”“今日营业额”“平均在场时长”）在页面顶部指标卡、主列表汇总行、趋势图折线、弹窗明细、下钻列表以及导出文件中，**默认必须具有完全相同的统计对象、时间边界、纳入排除、去重和计算口径**。
- **差异处理**：若因业务需要确实存在不同口径（例如顶部卡片为“全服务区今日车流”，列表仅为“本车道车流”）：
  - 必须通过字段命名区分（如“服务区今日车流量”与“车道今日车流量”）；
  - 严禁使用完全相同的指标名称承载不同统计逻辑；
  - 必须在 PRD 正文中显式设立“指标差异说明”对比差异。

## 4. 决策簇原则（上游事实缺口治理）

- **原则**：当在 Align、Design 或 PRD 阶段发现重要数据结果的关键事实（如账期锚点、分母定义、状态排除项、精度舍入、尾差归属）缺失时：
  - **严禁静默补全**：PRD、AI 或研发人员严禁凭借“通用惯例”或“猜想”私自拍板确认；
  - **严禁碎片化提问**：禁止把一个数据指标的关联未知拆散成 5~6 次零碎单字段反复追问；
  - **聚合为决策簇（Decision Cluster）**：必须以该数据结果为中心，将依赖的所有缺失维度（来源、范围、公式、精度、尾差）聚合成一个完整的决策问题簇，一次性向用户或业务负责人暴露为 pending decision，确认后再推进下游。

## 5. 低影响推断与高影响未知边界

为防止过度打扰用户，同时严守产品事实底线，划定明确边界：

| 类别 | 定义与典型场景 | 处理方式 |
|---|---|---|
| **低影响推断** | 纯表现层、无业务分歧的通用展示约定：<br>- 货币金额默认保留 2 位小数、千分位逗号展示；<br>- 百分比默认保留 2 位小数并加 `%`；<br>- 标准日期格式为 `YYYY-MM-DD`，时间为 `HH:mm:ss`；<br>- 空值或无数据时统一显示“`-`”或“`0`”且无业务歧义。 | 允许 AI / PM 按常规设计约定直接承接，不阻断流程。 |
| **高影响未知** | 改变数值大小、核算结果、对账逻辑或责任归属的核心事实：<br>- 纳入哪些业务状态、排除哪些异常/内部单据；<br>- 比率计算的分母包含哪些集合；<br>- 时间区间是闭区间还是开区间；<br>- 周期折算是按自然月实际天数还是按 30 天；<br>- 角分尾差由哪一方承担；<br>- 已结算数据是否允许重算与解锁权限。 | **严禁推断**。必须标记为待确认决策簇，停止该部分下游生成，交由上游或用户确认。 |

---

## 6. 正常例与边界例适用条件

- **适用条件**：仅在第四档“周期结算”及包含复杂分步运算的第三档数据中编写；
- **前置条件**：Design 必须已经明确了公式、精度、周期和分摊规则；
- **禁止越权**：PRD 严禁为了满足“有示例”而自编一套未经确认的假想数值规则作为事实。

## 7. 章节分工与落点原则

在 PRD 中，以单业务模块为自包含单位，各章节明确分工，杜绝口径规则压缩在字段表或跨模块不可查：

| 章节 | 职责分工 | 严禁行为 |
|---|---|---|
| **4.x.5 状态与业务规则** | 放置属于该模块的公共数据口径闭包、通用统计规则、周期定义、计算公式、尾差平衡机制及跨页面共享口径。 | 严禁只写状态机而漏写数据口径。 |
| **4.x.6 功能详细说明（页面）** | 承接各具体页面对上述规则的应用，写清各卡片、图表、列表对 `4.x.5` 规则的引用、页面特有筛选联动与交互。 | 严禁只罗列“展示统计指标”而不指明规则出处。 |
| **4.x.7 字段与交互定义** | 字段表格仅定义该页面特有控件类型、展示格式、排序/跳转交互；“来源或约束”列仅保留权威来源和对 `4.x.5` 的定位索引。 | **严禁将复杂公式、统计范围和时间起止压缩写在字段表格内**。 |
| **4.x.9 业务验收与用例** | 提供重要数据结果的可验证输入输出用例（包括正常例与边界例）。 | 严禁空缺复杂计算的验收用例。 |

### “系统统计/系统计算”表述规范

- **禁止**：严禁在正文或字段表中将“系统统计”或“系统计算”作为唯一的描述和完成标志；
- **允许**：仅当正文 `4.x.5` 或本节前文已经提供了完整的数据口径闭包时，字段表来源列才允许简记为“`系统计算（口径见 4.x.5 规则 1）`”。

## 8. 八类任务式试读问题（Review 与验收口径）

八类试读问题是 Review 独立审查与研发试读的通用验收口径。它全面覆盖了写作九项要素，用于逐项检验关键数据结果是否达到开发和测试标准：

1. **业务含义**：这一项数据具体代表什么业务概念？面向什么业务目标？
2. **权威来源**：数据最终从哪个业务对象、底层表或外部接口获取？
3. **统计范围**：包含了哪些组织、对象和业务状态的记录？排除了什么？是否去重？去重键是什么？
4. **时间边界**：统计周期的时间起止点是什么？开闭区间如何界定？快捷时间筛选的锚点是什么？
5. **聚合/公式**：具体的聚合方式或计算公式是什么？分子、分母、系数与分摊权重是什么？
6. **精度与尾差**：保留几位小数？采用何种舍入规则？过程精度如何保持？尾差如何吸收？
7. **刷新与时效**：数据何时计算或更新？是实时、定时还是人工触发？历史数据是否生成不可变快照？
8. **异常与兜底**：无数据、零分母、上游接口异常或数据跨期调整时，前端展示什么、系统如何兜底？

**试读判定准则**：
对抽检的重要数据结果，若研发人员在试读上述问题时发现存在 2 种以上不同解释，或存在无法唯一落代码的关键空白，即判定为**数据口径未闭包（严重缺陷 P1）**。
