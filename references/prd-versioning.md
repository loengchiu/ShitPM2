# PRD 版本记录维护规则

> 版本表的初始行、日期、格式和追加由确定性流程处理；LLM 只在用户主动触发时归纳修订说明并判断大修/小修。module pass 不装载本规则。

<!-- context:prd-writing-versioning:start -->
## 维护模式

批量提交式：首次生成只有 v1.0 一行；后续修订不自动追加；用户说“总结本次修订”“更新版本记录”等指令时才生成新条目。

## 总结逻辑

读取版本表最后一行版本号作为基线，通过 git diff 或对话上下文获取修订内容，按维度归纳：模块增减、页面增减、字段调整、状态机变更、权限调整、流程变更、文案修订。

## 版本号递增

- 小修订（字段调整、文案修订、错误修正）：v1.0 → v1.1；
- 大修订（模块增减、流程变更、状态机重排、权限模型调整）：v1.0 → v2.0；
- 大小修订同时存在时按大修订处理。

## 字段填写

版本按递增规则；日期为总结当天 YYYY-MM-DD；修订人为触发用户姓名，不填“系统/AI”；修订说明按维度归纳，超过 3 条用“主要：…；其他：…”；状态与文档头部一致。
