# PRD 版本记录维护规则

> 本文件规定 PRD 版本记录表的维护模式、触发指令、总结逻辑和字段填写规则。
> 本文件是 PRD 生成和修订时必须读取的详细维护规则；Skill 只保留调用顺序和职责边界。

<!-- context:prd-writing-versioning:start -->
## 维护模式

版本记录采用"批量提交式"维护，不每次修订都追加：

1. 首次生成 PRD 时，版本记录表只有 v1.0 一行，记录生成日期、生成人、首次生成说明
2. 后续修订（人工改或 AI 改）不自动追加版本记录
3. 当用户主动触发"总结修订"指令时，AI 才生成新版本记录条目追加到表格

## 触发指令

用户说以下任一指令时触发版本记录总结：
- "总结本次修订"
- "更新版本记录"
- "总结修订并更新版本"
- 其他语义等价的指令

## 总结逻辑

触发后 AI 执行：

1. 读取 `output/prd/prd.md` 头部的版本记录表，找到最后一行的版本号作为基线
2. 通过 git diff 或对话上下文获取自基线以来的 PRD 修订内容
3. 按维度归纳修订说明：模块增减、页面增减、字段调整、状态机变更、权限调整、流程变更、文案修订
4. 判断版本号递增规则（见下）
5. 生成新版本记录条目，追加到表格末尾

## 版本号递增规则

- 小修订（字段调整、文案修订、错误修正）：递增小数位，v1.0 → v1.1
- 大修订（模块增减、流程变更、状态机重排、权限模型调整）：递增大数位，v1.0 → v2.0
- 同时存在大小修订时，按大修订处理

## 字段填写规则

| 字段 | 填写规则 |
|------|----------|
| 版本 | 按递增规则生成的新版本号 |
| 日期 | 总结当天的日期，YYYY-MM-DD 格式 |
| 修订人 | 触发总结指令的用户姓名，不填"系统"或"AI" |
| 修订说明 | 按维度归纳，每条以顿号分隔；超过 3 条时用"主要：...；其他：..."句式 |
| 状态 | 评审稿 / 已发布 / 已废弃，与文档头部状态字段一致 |

## 边界

- 版本记录不承担内容事实，只记录修订留痕
- 不在版本记录里写技术细节（字段名、状态名），只写维度归纳
- 修订说明不展开成多行，单格内一句话
