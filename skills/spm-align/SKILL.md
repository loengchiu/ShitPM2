## 路径与资源

从系统 prompt 的 `<!-- SHITPM GLOBAL RULES START -->` 段读取 `ShitPM bundle root:`，记为 `$BUNDLE`。

- `scripts/python/`、`references/`、`templates/`、`contracts/`、`schemas/` → `$BUNDLE/`
- `.workflow/`、`output/` → 当前项目根目录

流程开始时给出一次模型建议：目标和边界明确、材料简单时可用轻量模型；存在材料冲突、范围不清或复杂背景时使用深度推理模型；无法判断时使用深度推理模型。

完成条件：用户已获得一次与当前输入复杂度相符的模型建议。

材料准备由项目级运行时编排能力维护。Align 消费当前输入和编排器提供的材料索引、分来源事实；不把材料事实提取、Design 状态或下游规划写成新的细粒度用户流程。

## 核心定位

Align 是 Design 前的需求事实形成阶段，不是摘要器，也不是最终 Design。

- **Align 必经**：每次首次生成 Design，或用户请求、材料、回答发生实质变化时，必须重新承担 Align 分析责任。
- **材料可选**：没有原始材料时，使用用户当前描述和回答形成事实，`source_count=0` 是合法状态，不要求伪造材料文件。
- **不替用户拍板**：不新增用户没有提供、也不能从事实直接推出的高影响流程、状态、权限、数据范围、系统边界或方案权衡；应提问或列为待确认。
- **完整保留**：材料已经明确写出的细节必须逐项保留，不能压缩成“相关信息”“基本字段”“支持查询等”。
- **可复用**：当前请求、材料版本和已记录回答未变化时复用有效 Align；变化时先使 Align 及受影响下游失效。

Align 完成后，Design 自动沿用户选择的 simple 或 full 模式继续；用户不需要退出当前任务后再次手工调用 `/spm-align`。

## 输入事实源

按以下顺序读取；以材料资产的可定位事实为主输入，`align.md` 作索引与汇总，不只是短摘要：

1. `.workflow/status.json`（如存在）；
2. `.workflow/runtime/inputs/request.md` 和用户当前原话；
3. `$BUNDLE/references/align-writing.md`；
4. `$BUNDLE/templates/align.md`；
5. `$BUNDLE/schemas/align-notes.schema.json`（内部 JSON 的唯一结构来源）；
6. `.workflow/runtime/materials/manifest.json`、`source-index.json` 和分来源 `facts/<source_id>.json`（如存在）；
7. `.workflow/runtime/materials/facts.json`（如存在）；
8. 历史 Design 按目标事实闭包读取（设计地图 + 设计集清单 → 目标模块及必要基线与契约）、历史 PRD 或用户明确提供的其他材料（如属于当前需求）。

材料资产有效时优先使用可定位的事实和来源行范围；只有索引或事实不足、需要核验冲突时，才定点读取原文。没有材料时继续基于用户原话和回答形成事实，不因缺少材料而停止。

完成判据：所有存在且属于当前需求的输入均已按顺序读取；可定位事实与来源行范围已收集；缺失、失效或不可读输入已明确标注，未被伪造成事实。

## 执行流程

1. 记录当前用户原话、输入路径、材料清单和版本；区分当前需求与无关历史产物。
   完成条件：每个采用的输入都有路径或用户原话标识及当前版本；无关历史产物已排除。
2. 按 `$BUNDLE/references/align-writing.md` 的事实类型和完整保留清单整理已确认事实，不把“提炼”理解成“缩写”。
   完成条件：参考文件中的每个适用事实类型均已逐项落入对齐稿或注明不适用，没有用概括词替代页面、字段、操作、规则、状态、异常或验收事实。
3. 识别会改变 Design 的高影响未知；没有材料时先从用户描述写出已知事实，再识别问题、目标和成功判断、范围内外、角色责任、核心场景、系统/人工/外部边界和已知约束中的缺口。
   完成条件：每个高影响未知都写明会改变的下游判断；低影响未知已单独记录且不阻塞继续。
4. 每次只问一个最影响当前方案的问题；能从材料查到的内容直接采用，不再追问用户。
   完成条件：当前轮只有一个阻断问题，或没有需要提问的高影响未知；问题未重复材料已有答案。
5. 用户回答必须写回 `output/align/align.md` 和 `.workflow/runtime/align/align-notes.json`，并注明回答影响哪些事实或下游判断；回答不留存在对话上下文中。
   完成条件：两份产物均包含最新回答，`align-notes.json` 符合 schema，受影响事实和下游判断可定位。
6. 按 `$BUNDLE/templates/align.md` 写入完整对齐稿，分开记录已确认事实、用户回答、材料冲突、废弃旧事实、可直接推导结论、模型推测、高影响待确认、低影响待确认和来源索引。低影响展示层推测进入 Design 后按推断值处理；高影响推测转为 Design 未决事项。
   完成条件：模板中的适用部分均有内容或明确不适用；事实、推导、推测、冲突和未知没有混写。
7. 在 Align 完成前做一次事实回读，按 `$BUNDLE/references/align-writing.md` 核对详细材料是否逐项有落点；缺口直接补回对齐稿，无法判断的事项列为待确认。
   完成条件：每个来源的适用事实均有正文落点、明确排除理由或待确认项；来源索引能回查对应事实。
8. 停在需求事实边界：不写最终方案，不把分析层级写成产品章节，不启动 PRD、Prototype、Review 或确认。
   完成条件：Align 产物只包含需求事实及其判断状态；下一动作仅为等待高影响回答或交给当前 Design 任务继续。

## 产物与完成语义

- `output/align/align.md`：完整的需求事实对齐稿，不是短摘要。
- `.workflow/runtime/align/align-notes.json`：按 schema 记录真实阻塞问题、问答状态和判断说明。
- `.workflow/status.json`：导航状态和产物路径（由宿主按项目状态约定维护）。

没有材料时，`output/align/align.md` 仍必须存在，并明确记录“无原始材料，事实来自用户原话和回答”，不伪造来源行号。

只有以下条件同时满足，才可把 Align 交给下游：当前输入和材料版本已记录；事实、冲突、推测和未知已分开；需要回答的高影响问题已回答，或已向用户明确展示并获得继续采用保守表达的决定；对齐稿可读取。

## 输出与停止

- 需要高影响回答时暂停当前 Design，等待用户回答；回答写回后从受影响动作继续。
- 用户说“跳过”“先这样”或“进入 Design”时，不把未确认内容伪装成事实；记录当前结果、未决问题和保守边界后继续。
- 目标、范围和边界已足以进入分析时完成当前 Align；不追求固定轮次、问题数量或字数。
- 完成后告知用户 Align 已形成，Design 将自动继续；Align 是 Design 的前置，不存在可跳过路径。
- Align 完成判据：Align 产物可读取；无高影响未知悬空未记录；已告知用户 Align 形成且 Design 将自动继续。

## 失败处理与禁止事项

- 模板或必要 schema 缺失：报告具体路径并停止；不得凭记忆生成完整产物。
- 材料路径不可访问：列出路径并向用户询问替代材料；不要把缺失材料当成已确认事实。
- 输入矛盾：分别列出来源、冲突内容、影响和待确认事项；不得擅自定案。
- `align-notes.json` 损坏：保留旧文件后按 schema 重建；重建失败则停止并请求处理。
- 不把模型推测写入已确认事实，不把对话记录、运行状态、动作 ID、回执或内部任务图写入产品正文。
