## 路径解析

从系统 prompt 的 `<!-- SHITPM GLOBAL RULES START -->` 段读取 `ShitPM bundle root:` 的值，记为 `$BUNDLE`。

- `scripts/python/`、`references/`、`templates/`、`contracts/`、`lib/` 开头 → `$BUNDLE/` 下
- `.workflow/`、`output/` 开头 → 当前项目根目录下

```
# 脚本调用
python $BUNDLE/scripts/python/stage-context.py --stage design --project-root .

# 读取 bundle 资源
Read $BUNDLE/templates/prd.md
Read $BUNDLE/references/prd-writing.md

# 读取项目文件
Read output/design/design.md
Read .workflow/status.json
```

## 前置检查

运行 `python $BUNDLE/scripts/python/stage-context.py --stage design --project-root .`

准入条件：
1. `output/design/design.md` 存在
2. `metadata/design` 完整

不通过则输出阻塞项，不写任何产物。

## 最小读取集合

一次工具调用批量读取，不逐个读：

1. `.workflow/status.json`
2. `output/design/design.md`
3. `$BUNDLE/templates/prd.md`
4. `$BUNDLE/references/prd-writing.md`
5. `$BUNDLE/references/prd-writing.profile.json`

字段定义、页面落点、权限矩阵、状态机从 design.md 原文读取，不依赖 metadata JSON。metadata 仅用于生成后校验幻觉。

## 执行顺序

1. 运行前置检查
2. 读取最小读取集合
3. 生成 PRD：按模块规划详细需求 → 模块内按页面、动作展开 → 权限汇总 → 数据字典 → 状态机 → 辅助章节（如需要）
4. 运行 `$BUNDLE/scripts/python/prd-style-lint.py` 自检
5. 写入 `output/prd/prd.md`
6. 运行 `$BUNDLE/scripts/python/verify-against-metadata.py --stage prd --project-root . --stdin-artifact` 校验幻觉
   - `hallucinated_items` 非空 → 立即修正 prd.md 中的幻觉字段/页面
   - `constraint_mismatches` 非空 → 逐条核对 design.md 原文，修正 prd.md 中的错误约束
   - 修正后重新运行 verify 直到 `hallucinated_items` 为空
7. 更新 `.workflow/status.json`

## 写作规则

### 标题与编号

1. Markdown 标题层级最多 3 级：`##` 章、`###` 节、`####` 小节
2. 中文编号前缀增强阅读结构感，不替代 Markdown 层级，不得跳级
3. 章 `一、`，节 `（一）`，小节 `1．`
4. `（1）` 作为正文内第四级顺序表达，不新增标题层级
5. 导出 docx 时按 Markdown 标题层级映射样式，不靠后处理猜层级

### 页面组织

1. 按模块 → 页面 → 动作组织；模块顺序与 design 模块定义一致，模块内页面顺序与 design 页面清单一致
2. 每个模块开头用 1-2 句说明模块职责和涉及页面，不展开成模板腔总述
3. 页面内部按用户动作组织，动作使用 `（1）/（2）/（3）` 分块展开，动词短语直接作为动作名（如 `（1）查询入库记录` `（2）发起入库申请`）
4. 不按 UI 区域盘点（如"筛选区""列表区"）
5. 页面开头可用一段交代页面区域组成和职责，后文仍按用户动作展开
6. 不允许出现 design 页面清单中不存在的模块、页面、区域或功能点
7. 不允许整页使用连续自然段覆盖多个动作；不同动作必须拆开写，形成清晰的阅读节奏
8. 列表、表单、详情中的字段描述只写当前动作真正需要读者理解的字段集合、展示方式和关键规则；不把数据字典 9 列或完整字段定义原样搬进页面正文
9. 动作下如需交代页面区块或信息分组，且区块较多或存在子分组时，用 `·` 列一级并列区块；区块内用 `-` 列子分组；区块很少且内容很短时直接用自然句写，不强行拆列表

### 写作风格

1. 按操作顺序写成产品规格说明，语言自然但克制，信息密度高
2. 每个动作覆盖：触发条件、操作过程、操作结果、异常处理，但不套用固定四段格式
3. 流程写法像资深产品经理的规格说明：主链路写清步骤、关键分支单列、状态变化落到结果
4. 少讲原因多写规则：写展示字段、可点条件、状态变化、失败提示、边界限制
5. 短句优先：一句一层规则，不写成背景说明
6. 少用加粗，层级通过标题、编号、段落和列表表达
7. 一个动作内部按"业务判断与关键结果 → 关键字段/状态 → 默认展示规则 → 异常/边界"组织；排序、分页、默认加载、常规空状态不放在首句

### 写作要求

1. 具体数值写死：所有数值直接写具体数字（"每页 20 条""倒计时 60 秒""保留前 3 后 4"），禁止占位
2. 静态内容加引号，动态内容写来源：静态标签/按钮/提示/空状态文案用双引号标明；动态展示需说明数据来自系统计算、接口返回、关联带出或用户输入
3. 超长文本必须交代处理方式：长名称/备注/说明/渠道信息等场景，写清截断、换行、滚动、悬停查看全文中的一种或多种
4. 标题下内容连续完整：不补空栏目，不写只有标题没有实质内容的占位段
5. 不用伪排版：正文用完整段落，不用伪缩进字符，不手敲空格模拟首行缩进，不通过空行制造视觉层级
6. 表格只用于映射关系：数据字典、权限汇总、状态映射、枚举定义用表格；区域说明、操作说明用自然语言或列表
7. UI 文案直接写：提示文案、按钮文案、空状态文案直接写在描述中，不单独列文案表
8. 混用三种表达，按场景选择：自然段（承接说明）、`1. 2. 3.`（有先后顺序的流程）、`·`（并列项）
9. 页面或模块开头的自然段只承担语境交代；进入动作后，不用大段自然段替代规格本身
10. 有明确前后顺序、状态推进、处理链路时，用 `1. 2. 3.`
11. 同层并列的展示项、校验项、限制项、异常项，用 `·`
12. 动作下需要拆页面区块时，可写成 `· 区块名：规则`；区块内子分组用 `- 子分组：规则`；仅在区块较多、信息密度高时使用
13. `## 三、业务流程` 仅承担整体业务流转和全局视图，优先用自然语言写整体流程，必要时配一张整体流程图；不展开页面级详细流转、按钮操作和模块内部状态细节
14. `## 五、详细需求说明` 的模块级内容，仅在存在真实跨页面流转、多角色协同或状态变更时，才在模块开头补充"详细流程图"和"状态变化图"；纯展示、纯配置管理或无业务状态变更的模块不补图，改为 1-2 句自然语言说明，细的流转与状态说明收敛在详细需求说明内
15. 页面正文写列表和表单时，只简要罗列当前动作涉及的关键字段、展示位置和规则，不把数据字典完整字段清单原样抄入正文，也不把表单字段原样平移成列表展示列
16. 列表类动作优先写"用户先看什么、靠什么判断、能做什么"；排序、分页、默认加载、常规空状态放在后半句或并列项中补充
17. 通用 B 端规则（默认分页、常规空状态）无特殊要求不展开
18. 禁用模板腔（"用于承载""用于支撑""需支持""按规范处理""同常规"）和模糊表述（"详见原型""待定""按业务规则"）

### 边界

1. `design` 是字段完整定义、权限完整定义、状态完整定义的唯一事实源
2. `PRD` 的职责是把 `design` 中已确认的事实展开成研发可评审的人读规格说明
3. `PRD` 不得独立新增 `design` 中不存在的字段、权限、状态定义
4. `PRD` 不得独立改写 `design` 已确认事实的语义
5. 数据字典是字段主定义的交付镜像区，不是新的字段事实源
6. 权限汇总是研发评审所需权限口径的集中展示区，不承担完整权限主定义
7. 状态机只保留研发评审所需的状态集合、迁移、触发动作和限制条件

## 数据字典

默认格式：`| 字段 | 类型 | 必填 | 说明 |`

按实体分组。长度、默认值、枚举值、格式、业务来源仅在确实影响研发实现或联调判断时写入"说明"，不强制固定展开成 9 列。

## 场景覆盖自检

每个动作写完后，检查以下场景（不存在的跳过）：

- 数据展示：静态内容用双引号标明；动态内容说明数据来源；超长文本处理方式（截断/换行/滚动/悬停）；空状态文案
- 按钮与操作：可点击/不可点击条件；点击反馈（加载动画、防抖、置灰）；操作成功后的变化；操作失败提示
- 表单与输入：输入限制（字符类型/长度/格式）；校验时机（实时/失焦/提交时）；错误提示文案
- 列表与加载：加载方式（分页/无限滚动）；加载中提示；无数据/加载失败/加载完毕状态
- 弹窗：触发/关闭方式；点击遮罩层是否关闭；多弹窗优先级和父子关系
- 异常与降级：网络异常处理；权限不足提示；关键功能降级
- 边界：数值边界值、列表数据量上限、状态临界值、并发冲突

未覆盖的必须补充。

## 输出要求

### 人读产物

写入 `output/prd/prd.md`，按 `$BUNDLE/templates/prd.md` 骨架组织。

核心章节必须全部存在：详细需求说明、权限汇总、数据字典、状态机。

权限口径：权限汇总默认只写页面级、按钮级权限；字段权限例外写入详细需求说明对应动作，不强制单列字段级权限矩阵。

辅助章节可选：文档概述、范围、业务流程；验收标准汇总（仅形成真实验收约束时出现）；风险与待确认（仅存在真实风险或待确认项时出现）。

### 状态更新

更新 `.workflow/status.json`：

- `current_stage`：`"prd"`
- `artifacts.prd`：`"output/prd/prd.md"`
- `metadata_paths.prd`：`".workflow/metadata/prd/"`
- `next_recommended`：`"prototype"` 或 `"prd-review"`

## 停止条件

1. prd.md 核心章节全部存在
2. `prd-style-lint.py` 无 P0 问题
3. PRD 内容不超出 design 范围

满足以上 3 条后停止，建议 `/spm-prd-review`。

## 不要做什么

1. 不重新定义范围
2. 不脑补 design 没确认的页面和字段
3. 不写成表格稿、动作流水账或标签式正文
4. 不把自己变成字段、权限、状态的第二事实源
5. 不执行 review（建议 `/spm-prd-review`）
6. 不自动推进到下一阶段

## 失败模式

| 场景 | 触发条件 | 一线修复 | 仍失败兜底 |
|------|---------|---------|-----------|
| 前置检查失败 | stage-context.py 返回阻塞项 | 输出阻塞项清单，停下等用户补充 | 不跳过前置检查 |
| stage-context.py 执行失败 | 脚本报错或超时 | 检查脚本路径和 Python 环境 | 停下告知用户具体错误 |
| design.md 不存在 | output/design/design.md 不存在 | 停下，需要先完成设计阶段 | —— |
| prd-style-lint.py 报 P0 | lint 检查发现严重格式问题 | 按 lint 输出逐条修正 | 修正后重新运行 lint 直到通过 |
| verify 脚本发现幻觉 | hallucinated_items 非空 | 删除幻觉字段/页面，从 design.md 重新提取 | 重新运行 verify 直到为空 |
| verify 脚本发现约束不一致 | constraint_mismatches 非空 | 逐条核对 design.md 原文，修正 prd.md | 重新运行 verify 直到为空 |
| 模板文件不存在 | templates/prd.md 不存在 | 使用内置最小模板 | 停下告知用户安装模板 |
| 参考文件不存在 | references/prd-writing.md 不存在 | 跳过参考，按硬规则生成 | —— |
