# 审计管理系统详细设计

> 说明：本文件是历史回归/校准产物，不是当前 Design 规则的唯一正例；其中部分操作可见性写法保留旧版表达，仅用于差异分析。

> 版本：v1.0
> 状态：设计稿
> 基线：需求对齐稿 v1.1（PM 已确认）

## 一、设计概述

本设计基于已通过审查的需求对齐稿（align-20260505.md v1.1），覆盖 6 项需求目标：审计全流程线上化、审计单位与被审单位在线协同、产品化架构、统一首页总览、审批流程灵活配置、问题整改闭环追踪。

建设类型为新建系统（基于集团审计系统功能蓝本）。一期覆盖 10 个模块，54 个核心页面，纯 PC 端，不对接 OA 和移动端。

## 二、功能清单

### 审计计划模块

| 功能 | 使用角色 | 说明 |
|------|----------|------|
| 年度计划编制 | 审计用户（项目组员） | 填报年度审计计划，包括项目名称、审计类型、审计范围、计划时间等 |
| 年度计划审批 | 公司管理员/集团管理员、集团领导/公司领导 | 按配置的审批流程依次审核/审批 |
| 年度计划调整 | 审计用户（项目组员） | 在已审批通过的计划内增加或停止审计项目 |
| 计划同步 | 系统自动 | 审批通过的审计项目自动同步到项目启动列表 |

### 项目启动模块

| 功能 | 使用角色 | 说明 |
|------|----------|------|
| 项目立项 | 项目组长/主审 | 确定项目基本信息，从计划同步的项目创建审计项目 |
| 成员管理 | 项目组长/主审 | 添加/移除项目组成员，指定角色 |
| 对接人指定 | 项目组长/主审 | 指定被审单位用户（对接人） |
| 项目终止 | 项目组长/主审 | 终止审计项目，记录终止原因 |

### 审计准备模块

| 功能 | 使用角色 | 说明 |
|------|----------|------|
| 准备项目列表 | 审计用户（项目组员）、项目组长/主审 | 查看所有当前用户参与的项目，5项准备材料（实施方案、通知书、进点会、承诺书、资料清单）的完成状态一目了然，点击对应的材料直接进入该材料的编辑页 |
| 实施方案编制 | 审计用户（项目组员） | 编辑实施方案，未完成时可填写提交，已完成时可查看详情并修改后重新提交 |
| 审计通知书 | 审计用户（项目组员） | 制作审计通知书，保存后即可发送给被审计单位，支持修改后重新发送 |
| 进点会记录 | 审计用户（项目组员） | 记录审计进点会的时间、参会人员、会议内容，保存即完成，支持在详情页修改后重新保存 |
| 承诺书管理 | 审计用户（项目组员） | 管理承诺书基本信息、对接人和附件；发出后跟踪各被审单位签署情况，支持修改后重新发送 |

### 审计实施模块

| 功能 | 使用角色 | 说明 |
|------|----------|------|
| 实施项目列表 | 审计用户（项目组员）、项目组长/主审 | 查看所有"进行中"的项目，选择项目进入底稿作业 |
| 底稿录入 | 审计用户（项目组员） | 录入审计底稿，支持单条录入和批量导入，一个底稿记录一个问题 |
| 组内审核 | 项目组长/主审 | 审核组员提交的底稿 |
| 被审单位反馈 | 被审单位用户（对接人） | 将底稿发送给被审单位反馈意见 |
| 底稿复核 | 项目组长/主审 | 结合被审单位反馈意见复核底稿 |
| 问题列表/问题详情 | 审计用户（项目组员） | 汇总审计问题列表（由底稿复核通过后自动生成），支持批量设定上报告标记；在问题详情页完成问题定性、涉及金额、上报告决策和整改意见 |
| 上报告问题列表/上报告问题详情 | 审计用户（项目组员） | 新建上报告问题（选类型、填名称、多选已上报告问题、填归纳和整改要求），提交组内审核；审核通过后上报告问题完成 |
| 问题沟通会 | 审计用户（项目组员） | 记录与被审单位的问题沟通会 |

### 审计报告模块

| 功能 | 使用角色 | 说明 |
|------|----------|------|
| 报告项目列表 | 审计用户（项目组员）、项目组长/主审 | 查看所有"进行中"的项目，列表中直接展示各报告环节（征求意见稿、正式报告、关闭检查）的完成状态，点击状态标签直接进入对应环节操作 |
| 征求意见稿 | 审计用户（项目组员） | 在报告列表中新建征求意见稿，填写报告标题、送达信息、报告内容后发送给被审单位收集反馈意见；支持撤回修改后重新发送 |
| 意见收集 | 被审单位用户（对接人） | 被审单位查看征求意见稿并反馈意见；审计单位可查看反馈并回复 |
| 正式报告 | 审计用户（项目组员） | 征求意见稿流程完成后创建正式审计报告，填写报告基本信息、报告内容、送达信息后提交；可关联上报告问题，将问题信息引用至报告正文 |
| 关闭检查 | 项目组长/主审 | 按环节（实施方案、审计通知书、审计承诺书、审计资料清单、审计底稿、上报告问题、审计报告）逐项检查内容/附件是否齐全，标记已确认并上传可能遗漏的附件，完成后可提交项目结束 |
| 统一登录 | 全部用户 | 所有角色通过统一登录页认证后进入系统，系统根据角色跳转对应首页 |

## 四、数据字典

### 年度计划
| 字段 | 类型 | 必填 | 枚举值 / 规则 | 说明 |
|------|------|------|---------------|------|
| 计划 ID | 整数 | 是 | 系统自动生成 | 主键 |
| 计划名称 | 字符串 | 是 | 最大 100 字符 | 如"2026 年度审计计划" |
| 计划年度 | 字符串 | 是 | 格式：YYYY | 如 2026 |

## 五、系统流程

### 流程一：审计项目全流程

1. 审计用户（项目组员）在审计计划模块填报年度计划，填写审计项目列表
2. 提交审批，按配置的审批流程流转（公司管理员/集团管理员审核→集团领导/公司领导审批）
3. 审批通过后，计划状态变为"已通过"，审计项目自动同步到项目启动列表
4. 审计用户（项目组长/主审）在项目启动模块查看待启动项目，填写项目详细信息、添加成员和对接人
5. 确认启动，项目状态变为"进行中"
6. 审计用户在准备项目列表页查看5项准备材料的完成状态，点击对应材料直接进入编辑页。每项材料支持多次修改重提：未完成时填写提交，完成后仍可进入修改并重新提交/流转/发送
7. 准备工作完成后，准备工作完成，进入实施阶段
8. 审计用户（项目组员）录入审计底稿（一条底稿对应一个问题），提交组内初审
9. 初审通过后，底稿发送给被审单位征求意见
10. 收到被审单位反馈后，审计用户（项目组长/主审）进行组内复核，决定是否采纳反馈意见
11. 底稿组内复核通过后自动创建审计问题，审计用户（项目组员）进入问题一览列表查看所有问题，设定问题定性、涉及金额、是否上报告及整改意见
12. 审计用户（项目组员）在上报告问题列表新建上报告问题，选择已标记为上报告的问题进行关联，填写问题归纳和整改要求，提交组内审核
13. 审计用户（项目组员）在报告项目列表页查看各报告环节状态，点击征求意见稿状态进入报告列表，新建征求意见稿并发送给被审单位收集意见
14. 收集并回复被审单位反馈后，在报告列表中新建正式报告，填写报告内容并关联上报告问题，发布正式审计报告
15. 审计用户（项目组长/主审）在报告项目列表页点击关闭检查状态进入关闭检查页，按环节逐项检查确认后提交项目结束，项目状态变为"已结束"

### 流程二：被审单位协同反馈

1. 被审单位用户（对接人）通过独立登录页进入系统
2. 在反馈首页查看待办列表和整改台账统计
3. 接收任务（承诺书签署、资料提交、底稿意见、报告意见、整改反馈）
4. 被审单位用户（对接人）可将任务转办给被审单位用户（经办人）
5. 被审单位用户（经办人）处理完成后，被审单位用户（对接人）审核并统一提交给审计单位

### 流程三：审批流程

1. 用户提交审批申请（如年度计划、底稿、报告）
2. 系统根据业务类型匹配审批流程模板
3. 创建审批流程实例，进入第一个审批节点
4. 审批人收到待办通知，执行审批操作（通过/驳回/转办）
5. 通过时，按流程定义判断下一节点（含条件分支判断）
6. 支持会签（多人同时审批，全部通过才进入下一节点）
7. 支持加签（审批人临时增加其他审批人）
8. 驳回时，流程终止或退回至指定节点
9. 所有节点通过后，流程结束，业务对象状态更新

### 流程四：底稿作业流程

1. 审计用户（项目组员）录入审计底稿（单条录入或批量导入），状态为"草稿"
2. 审计用户（项目组员）提交组内初审，状态变为"正在初审"
3. 审计用户（项目组长/主审）进行初审：
   - 初审通过，状态变为"初审完毕"，底稿进入征求意见准备状态
   - 初审退回，状态回退为"草稿"，经办人修改后可重新提交
4. 初审完毕后，审计用户（项目组员）将底稿发送给被审单位征求意见，状态变为"正在征求"
5. 被审单位通过审计反馈模块的底稿反馈功能反馈意见：
   - 被审单位用户（对接人）（或转办后的经办人）登录反馈首页，进入底稿意见页
   - 提交反馈意见（无异议/有异议），并附具体说明和佐证附件
   - 审计组在底稿详情中查看反馈意见
6. 征求意见期间，审计用户（项目组员）可撤回底稿：
   - 撤回后状态回到"初审完毕"，填写撤回原因
   - 审计用户（项目组员）修改后可重新发送征求意见
7. 被审单位反馈意见后，状态变为"征求完毕"；审计用户（项目组员）也可手动标记征求完毕
8. 审计用户（项目组长/主审）进行组内复核，查看被审单位反馈意见，决定是否采纳：
   - 记录复核意见和是否采纳反馈
   - 状态变为"组内复核"，底稿作业完成
9. 复核后如需进一步沟通，可退回征求意见（状态回到"正在征求"），待重新反馈后再次复核

## 七、角色权限

### 7.1 三层权限模型

本系统采用三层权限模型：**系统管理角色 + 业务角色 → 用户类型 → 项目身份**，分别控制系统级、模块级和操作级权限。

#### 第一层：系统管理角色（系统级，登录后固定，负责人员和系统配置管理）

| 角色 | 职责 | 管理范围 |
|------|------|----------|
| 系统管理员 | 全系统配置、用户管理、角色分配 | 全部数据 |
| 集团管理员 | 管理集团本部全部部门人员（含审计部和其他部门）、审批流程配置 | 集团本部所有部门 |
| 公司管理员 | 管理本公司全部部门人员、审批流程配置 | 本公司所有部门 |
| 普通用户 | 使用业务功能 | 根据业务角色和所属机构决定 |

#### 第一层补充：业务角色（系统级，决定可访问的业务模块和数据范围）

| 角色 | 说明 | 数据范围 |
|------|------|----------|
| 集团领导 | 查看全集团审计业务数据 | 全集团审计项目+被审计数据 |
| 公司领导 | 查看本公司审计业务数据 | 本公司审计项目+被审计数据 |
| 审计用户 | 审计部门正式员工，可参与审计业务 | 按所属机构决定（见7.2） |
| 外包审计用户 | 外部审计公司人员，仅能参与被分配的项目 | 仅被分配项目 |
| 被审单位用户 | 被审单位人员，仅在审计反馈模块操作 | 本单位相关项目 |

> 一个用户可同时拥有多个角色（如子公司高层可同时是"公司管理员"+"公司领导"；子公司审计人员被集团审计时，既是"审计用户"又是"被审单位用户"）。多身份用户登录后可在首页顶部切换视角。

#### 第二层：用户类型（系统级，可多选）

| 用户类型 | 说明 |
|----------|------|
| 审计用户 | 审计部门正式员工，可参与全部审计业务 |
| 外包审计用户 | 外部审计公司人员，仅能参与被分配的项目 |
| 被审单位用户 | 被审单位人员，仅在审计反馈模块操作 |

#### 第三层：项目身份（项目级，在每个项目中指定）

| 用户类型 | 可分配的项目身份 |
|----------|------------------|
| 审计用户 | 项目组长、项目主审、项目组员 |
| 外包审计用户 | 项目组长、项目主审、项目组员 |
| 被审单位用户 | 对接人（项目启动/审计准备阶段指定）、经办人（通过转办任务产生） |

### 7.5 身份切换逻辑

```
用户登录
  ↓
判断系统管理角色
  ├─ 系统管理员 → 显示系统管理模块（全量数据）
  ├─ 集团管理员 → 显示系统管理模块（集团本部全部部门）
  ├─ 公司管理员 → 显示系统管理模块（本公司全部部门）
  └─ 普通用户 → 继续判断
  ↓
判断业务角色（可多选）
  ├─ 集团领导 → 显示审计模块（全集团只读）
  ├─ 公司领导 → 显示审计模块（本公司只读）
  ├─ 审计用户 → 显示审计模块（按数据范围过滤）
  ├─ 外包审计用户 → 显示审计模块（仅被分配项目）
  ├─ 被审单位用户 → 显示审计反馈模块（本单位相关）
  └─ 多身份用户 → 显示身份切换入口
  ↓
进入具体项目
  ↓
判断项目身份
  ├─ 项目组长/主审 → 完整操作权限
  ├─ 项目组员 → 录入/查看权限
  ├─ 对接人 → 签署/提交/反馈/转办权限
  └─ 经办人 → 仅处理转办任务
```

| 被审单位独立登录页的认证机制 | 审计反馈模块 | 待研发确认 | 需确定账号密码 or 手机验证码 or 其他方式 |

| 外包审计用户的计费/合同关联 | 一期不涉及 | 暂不处理 | 后续可扩展外包用户的合同和计费管理 |

## 附录：MVP 优先级建议

鉴于工期紧迫（一期功能约 50+ 项），以下按优先级分层，供研发排期参考：

**P0（核心主链路，必须完成）：** 审计计划（编制、审批、年度计划调整）、项目启动（立项、成员管理）、审计实施（底稿录入、组内审核、被审反馈、复核、问题列表/问题详情）、审计报告（征求意见、正式报告发布）、实施结束（项目关闭）、系统管理（用户、角色、组织机构、审批流程配置）

**P1（重要支撑，尽早完成）：** 审计准备（实施方案、通知书、承诺书、资料清单）、审计反馈（独立登录、承诺书签署、资料提交、底稿意见、报告意见、整改反馈）、审计总览（审计单位首页、被审单位首页）、项目档案

**P2（基础配置，按需完成）：** 审计知识库（审计检查项库）、系统管理（数据字典、菜单管理、操作日志、登录日志）、年度规划设置、数据请求配置
